Use the actual generated collection API and reified/backing serializers. Bigint List/Map elements use numeric Long; direct DTO/Patch bigint fields keep their decimal-string serializer. Bytes use signed numeric arrays inside JSON collections, while standalone ByteArray HTTP keeps its independent raw policy. Value classes retain their actual wrapper/raw API, checks and codec. Caller-native classes and serializers belong to the provider. Native-date uses Instant/ISO. Ordinary empty models use JsonElement, including JsonNull; open dictionaries use JsonObject and the original alias/backing. Nearest accepted nullable intent and intrinsic views remain. A nullable JSON view can decode null to Kotlin null.

Ordinary tuple fields, component roots and eligible independent collection aliases can own outer defaults. Validate Long numbers, signed byte arrays, actual wrapper raw scalars/checks, supported timestamps and JSON kinds through original source roles. JsonObject defaults must be objects or explicitly nullable null, and retain opt-in property counts. Required/Patch annotations validate before suppression; required arguments and Patch.Absent remain. No target/chain/child annotation is inherited or newly granted. Factories/helpers decode fresh outer collections.

Use existing supported scalar literal validators for caller-native defaults. An opaque provider's empty collection or nullable null element is accepted; an unproved non-null literal remains rejected. Applications may construct actual provider values normally. A matching builtin/native spelling does not authorize different source roles or an inferred physical layout.

Original node/path/catalog, canonical profile, unique actual export/name, marker, wrapper/checks, consuming/backing address and cached source height remain authoritative. Same-byte copies and duplicate exports cannot supply authority. Discarded prefixes retain dependencies and source work. Boolean additionalProperties is a dictionary keyword; it does not add a schema-value depth edge.
