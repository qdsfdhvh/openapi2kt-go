# Kotlin compilation smoke

This minimal consumer compiles actual CLI-generated models with the kotlinx.serialization compiler plugin. There are no handwritten substitute DTOs and no Gradle generator plugin.

From the repository root:

```bash
# Kotlin plugins/dependencies must already be cached; the harness is offline.
bash scripts/test.sh models
```

To select an already-built native Go command:

```bash
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go build -trimpath -o .pi/openapi-kt-go ./cmd/openapi-kt
OPENAPI_KT_BINARY="$PWD/.pi/openapi-kt-go" bash scripts/test.sh models
```

Both paths use Go, Python 3, Gradle and a JDK, never Cargo. It creates a fresh repository-local project, generates all 38 positive corpus cases and 15 semantic fixtures in baseline/suffix configurations through the actual Go binary, and runs 17 runtime suites, including dictionary contracts and three native-port supplemental suites. The exporter compares CLI reports/warnings, actual bytes, manifest hashes and check/no-op mtimes with the pure Go API. Go and Gradle both run offline; dependencies must already be cached. See [Go verification and platform boundaries](../../docs/go-port.md).

Requirements for the current source checkout: Go 1.27.2 or newer, Python 3, Gradle, and a JDK. `GO` and `GRADLE` may select executable paths. The previously tested Kotlin combination used Go 1.26.5, Gradle 9.3.1, JDK 21, Kotlin 2.4.10, and kotlinx.serialization 1.11.0; bytecode targets JVM 17. The harness never downloads dependencies; install/cache toolchains separately.

The script exports all 38 positive cases in the [JSON corpus](../../tests/fixtures/p1/README.md) plus semantic/resource inputs into a new ignored `.pi/go-migration/` project through the actual Go CLI. [`generate-fixture-smoke.py`](../../scripts/fixtures/generate-smoke.py) is also available as a standalone native Go fixture tool. Each case has a separate owned output root and a distinct Kotlin package. One `compileKotlin` invocation compiles the actual generated outputs together; expected snapshots are never used as compilation inputs. The script also generates the focused enum/ref/suffix input, [enum naming vocabulary](../../tests/fixtures/model-semantics/enum-naming.json) and a 240-member enum boundary. `runPrimitiveContracts` also executes [primitive-reference assertions](src/main/kotlin/org/example/contracts/PrimitiveContracts.kt) against generated aliases/ref/suffix models and 120-wide/240-boxed JVM constructor boundaries. `runEnumContracts` executes [runtime assertions](src/main/kotlin/org/example/contracts/EnumContracts.kt) against these generated types, including uppercase/digit/operator/UTF-16 constant spellings, reserved/collision suffixes, `Serializer.fromSerialName` call sites, unknown-value round-trips, strict JSON string handling and `encodeDefaults`/`explicitNulls` combinations.

`runNullableCompositionContracts` executes [nullable-composition assertions](src/main/kotlin/org/example/contracts/NullableCompositionContracts.kt) against actual generated oneOf/anyOf fields, object/enum references, nested scopes, list-item nullability, missing/null/value behavior and all `encodeDefaults`/`explicitNulls` combinations.

`runConstContracts` executes [const-field assertions](src/main/kotlin/org/example/contracts/ConstContracts.kt) against generated body defaults, plain const-only classes, nested/list/ref/suffix models and the 120-Long serialization-constructor boundary. It tests all JSON configuration combinations and verifies that DTO decoding is not const-membership validation.

`runObjectCompositionContracts` executes [object-composition assertions](src/main/kotlin/org/example/contracts/ObjectCompositionContracts.kt) against generated multi-level allOf merges, declaration/override order, required fields, const tags, reference wrappers, nullable inline objects, list items and suffixes across all JSON configurations. The generated 120-Long merged model tests the serialization-constructor boundary.

`runEnumContextContracts` executes [enum-context assertions](src/main/kotlin/org/example/contracts/EnumContextContracts.kt) for typeless string component/ref/inline/array/suffix scopes and native numeric/boolean inline enums. It verifies numeric/boolean wire types, decoding outside declared membership, native range/shape/missing failures and every JSON configuration, plus typeless 240-member enums and a 120-Long native-enum model. Native enum roots have the scalar-projection contract; null enum members remain deferred.

`runScalarProjectionContracts` executes [scalar projection assertions](src/main/kotlin/org/example/contracts/ScalarProjectionContracts.kt) on actual baseline/suffix output: native enum aliases/refs (not quoted enum tokens), const root/item membership approximation versus const-ref/wrapper body defaults, const-ref union tags, unknown native values, scalar extrema/negative zero, required native slots, and 120-Long enum-ref constructor/const-ref body limits. Every JSON configuration runs; no substitute DTOs are used. [Migration and remaining boundaries](../../docs/model-semantics.md#scalar-value-projections) are explicit.

`runDictionaryContracts` executes [dictionary assertions](src/main/kotlin/org/example/contracts/DictionaryContracts.kt): typed/open/root/nullable aliases, inline/list/nested value models, enum unknowns, primitive union values, suffixes, recursive value DTOs, object-only and invalid-value decoding, fixed extras under strict/tolerant JSON, and all default/null configurations. A generated 240-map-field DTO verifies the one-slot collection budget. Transparent alias cycles and dictionary composition/common-union projections remain rejected; see [dictionary semantics](../../docs/model-semantics.md#dictionaries).

`runHierarchyContracts` executes [typed hierarchy assertions](src/main/kotlin/org/example/contracts/HierarchyContracts.kt) on actual CLI-generated baseline/suffix graphs: explicit mappings and ignored aliases, original-key lowercase fallback, enum constructor versus typed enum body, const singletons, inferred const-first selection, default-polymorphic intermediate class-discriminator wire asymmetry, four-level ancestor Unknown stand-ins/raw passthrough, base allOf, named refs/lists and the generated 119-Long + bool + typed-enum-body 240-slot boundary. All JSON configurations run; general fixed/missing-field/mixed/alias graphs remain deferred.

`runUnionNormalizationContracts` executes [normalization assertions](src/main/kotlin/org/example/contracts/UnionNormalizationContracts.kt) on actual baseline/suffix CLI output: merged known/open vocabularies and lookups, unknown string/value equality, nullable items/nested types, uniform range/format native widths, outside-pin native payloads/extrema/wrong kinds/no envelopes, every JSON configuration, and actual merged240-member enums/120-Long folded models. [Constraint and membership approximations/migration](../../docs/model-semantics.md#primitive-union-normalization) are explicit; no handwritten substitute DTOs.

`runRootKindContracts` executes [root-kind/null assertions](src/main/kotlin/org/example/contracts/RootKindContracts.kt) on actual baseline/suffix CLI outputs: native sibling payloads, extrema/wrong kinds, root null singletons and strict consuming serializers, independent nullable refs/lists, content Unknown versus closed nullable polymorphism, all JSON configurations/custom discriminator/array polymorphism, and generated 120-Long object variants plus 119-Long+root+boolean 240-slot models. [Migration and boundaries](../../docs/model-semantics.md#root-json-kind-and-nullable-unions) distinguish named roots from nested scalar folds.

`runRootUnionContracts` executes [standalone-root assertions](src/main/kotlin/org/example/contracts/RootUnionContracts.kt) on actual generated components: enum constructors versus inline enum body defaults, content/tag/presence and ordinary sealed polymorphism, unknown raw passthrough versus class-discriminator failures, referenced variant/implicit/suffix wire names, named refs/lists/recursive DTOs and const-only root singletons under every JSON configuration. [Typed mapping/hierarchy](../../docs/model-semantics.md#typed-discriminator-hierarchies) is separately verified; general fixed/mixed/nullable graphs remain deferred; primitive/nullable roots have their independent root-kind task.

`runObjectUnionContracts` executes [inline object-union assertions](src/main/kotlin/org/example/contracts/ObjectUnionContracts.kt) against actual field/item variants: tag and exclusive-required-key dispatch, duplicate first-claim, reachable/no-key behavior, common constructor/default and Unknown stand-ins, fixed const singleton encoding/decoding, complete raw JSON passthrough, refs/allOf/nested/items/suffix scopes and native constructor limits. Every JSON configuration runs; [standalone component roots](../../docs/model-semantics.md#standalone-root-object-unions) have separately verified policy; [typed hierarchies](../../docs/model-semantics.md#typed-discriminator-hierarchies) have another policy; general fixed/mixed/alias hierarchy behavior remains deferred.

`runPrimitiveUnionContracts` executes [inline primitive-union assertions](src/main/kotlin/org/example/contracts/PrimitiveUnionContracts.kt) against sibling wrappers and JSON-kind serializers. It verifies all 11 multi-kind primitive combinations, branch-order-independent boolean/Long/Double dispatch, quoted strings, no envelope on encoding, unmatched-kind failures, one object/ref with const defaults, nullable array items, nested/suffix scopes and all JSON configurations. This does not establish component-root or tagged-object union dispatch.

Fresh harness directories prevent old outputs from satisfying compilation. The standalone fixture tool uses `build/fixture-source-roots.txt` to select only current positive cases. Coverage includes recursive graphs, nested scopes, nullable arrays/items, primitive formats, keyword/digit-leading names, runtime-type name shadowing, escaped wire keys and `JsonElement` aliases.

The standalone sample build can optionally include already-generated local models with `-PextraModelSources=/absolute/path/to/generated-models`. This option belongs to `samples/kotlin-smoke/build.gradle.kts`, not the default fresh exporter project, and is not a Gradle generator plugin. Keep local paths out of tracked build files.

Go tests handle routine generation regression checks. Ordinary DTO round-trip testing is outside this smoke's scope; enum custom serializers, primitive component references and single-branch nullable compositions, scalar const body fields and object allOf merges have runtime tests; named primitive/nullable-root unions have runtime tests; general fixed/mixed/nullable discriminator graphs and Patch types still need their own contracts. This project does not establish Android or KMP compatibility.
