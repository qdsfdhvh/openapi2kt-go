# Enum defaults on DTO fields

[Bounded lexical enums in object defaults](bounded-enum-object-defaults.md) extend D03/D05/M01/M03/M04/M07/M08/M12 to existing ordinary factory/field/DTO-collection walks. Exact direct enum sources retain String checks and strict original vocabularies; original plain DTO component/alias factories and consuming annotations remain independent. Required/Patch, actual serializers/optimization, original Pointer/owner and budgets remain. Generic graphs, other root/child/composition roles, platforms and final acceptance stay separate.

[Direct lexical String enum field bounds](string-enum-field-bounds.md) extend D03/D05/M03/M04/M07/M08/M12/V05 to ordinary scalar fields and supported metadata on existing direct collection leaves. Actual serialName checks retain open runtime words, strict own defaults, nullable/required/Patch, original source/check/type and optimization identities, and existing budgets. Enum-root/reference/composition/platform and final acceptance remain separate.

[Model String enum metadata](metadata-string-enums.md) extends nullable roots/aliases, actual internal lexical references, existing independent scalar/collection/object default roles and serialName uniqueness. Original ownership, source/null-vocabulary boundaries, presence and budgets remain. Equivalent enum merges now retain each component-owned factory; generic graphs, platforms and final acceptance remain open.


[Referenced String enum scalar field defaults](referenced-string-enum-scalar-defaults.md) separately admit ordinary direct local `$ref` fields' own annotations on already accepted plain String/typeless enum paths, preserving actual classifiers, strict annotation vocabulary and open runtime Strings.

[Referenced native enum scalar field defaults](referenced-native-enum-scalar-defaults.md) separately admit the consuming ordinary direct local `$ref` field's own annotation on already accepted numeric/Boolean enum paths. Component-root and intermediate alias annotations retain their exclusions.

Direct plain String/typeless and native numeric/Boolean enum fields in generated DTOs accept a representable schema default. Non-null defaults must belong to the original declared vocabulary. Nullable schemas may declare a null default. [Null native enum members](native-enum-null-members.md) separately admit one null in an explicit nullable numeric/Boolean vocabulary under validation; non-null defaults match the original scalar members regardless of null position.

String fields keep their actual lexical enum classifier, companion mapping and open `Unrecognized` behavior. Optional fields initialize from the declared member and JSON decoding uses it for missing keys. Supplied values, explicit null and unknown String values keep their existing decoding behavior. Generated private helpers refer to the actual enclosing enum classifier after model relocation, so field names cannot shadow the constructor expression.

Numeric/Boolean fields retain their native Kotlin scalar. Default-off generation retains `W_ENUM_NATIVE_APPROXIMATION`; [direct DTO native enum membership](native-enum-validation.md) additionally enforces mapped values under `--validation`, while the default itself remains checked against original vocabulary. Numeric default membership uses bounded exact source values, so distinct values that round to the same Float/Double are not treated as equal.

Required fields, including required nullable fields, retain required constructor arguments. Optional explicitly nullable ordinary request fields retain `Patch.Absent`; default annotations never turn missing keys into updates. JSON settings and Patch Null/Value retain the [scalar default presence contract](model-defaults.md).

Supported DTO contexts include shared components, nested objects, referenced DTOs used through List/Map, supported allOf shapes, inline request/response DTOs and SSE payloads. Inline String enum defaults in object-union variants keep distinct lexical types rather than introducing an abstract common classifier. Numeric/Boolean common fields retain their existing scalar projection. All original vocabulary and default nodes, including discarded allOf fields, are validated before output commits.

This is a DTO field extension. Component-root and alias annotations follow their independent factory contracts; metadata String enums use the model metadata profile linked above. Reference wrappers outside admitted roles, element/value annotations, const/value-class extensions and new default graphs retain their own restrictions. Direct numeric/Boolean and plain String enum List/Map field defaults have separate [native](native-enum-collection-defaults.md) and [String](string-enum-collection-defaults.md) collection-default contracts. [Finite direct nested String enum collection field defaults](nested-string-enum-collection-defaults.md) grant only the outer ordinary inline field's own annotation on already admitted List/typed Map trees, keeping actual lexical owners, open runtime vocabulary, strict original membership, per-layer nullability and validate-before-suppression; nested enum String bounds/patterns and referenced/named/root/child defaults remain excluded. Numeric enum bounds and defaults follow their [combined contract](native-enum-bounds.md). [Explicit nullable String null members](string-enum-null-members.md) have their own open-vocabulary contract. [Null-only field defaults](null-only-defaults.md) have a separate JsonNull/presence contract; discriminator-default semantics and general defaults remain separate features. The source depth 48 and vocabulary/constructor limits 240 are unchanged.

The [options fixture](../tests/fixtures/http/enum-default-options.json) also compiles and runs combined hoist/deduplicate/merge/name-lock output. Defaults participate in model reuse and hoisted-name lock identity. Identical vocabularies with different emitted defaults remain distinct; replaying a changed default fails the existing shape-change contract. Existing accepted inputs without enum defaults preserve their output and wire behavior. One previously rejected direct enum-default guard is retained as an explicit positive regression.

The [synthetic envelope](../tests/fixtures/http/enum-defaults.json), Go source/resource/optimization/native tests and `bash scripts/test.sh feature enum-defaults` cover the feature. These JVM checks do not establish Android/KMP or broader platform support.
