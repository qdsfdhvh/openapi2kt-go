# Next bounded JSON alpha: scope and migration

The next preview keeps the [frozen bounded JSON scope](../json-release-checklist.md): current documented model/reference/nullable/composition/validation profiles, local configuration and output ownership, and the existing Ktor HTTP/SSE subset. Candidate verification targets macOS ARM64 for the CLI and Kotlin/JVM 17 bytecode running on JDK 21. General reference graphs, Android/KMP and other host/engine combinations remain on the roadmap.

The source CLI now declares **`0.2.0-alpha.1`** under the [version policy](../versioning.md). This identifies the local candidate; no new tag or release is implied. The new input/reference profiles, removal of previously supported downloader interfaces and increased minimum Go toolchain require a MINOR change before 1.0. Freezing the candidate does not satisfy beta/rc admission by itself.

## Migrate from the historical `v0.1.0-alpha.1`

| Surface | Required action |
|---|---|
| Go source builds and `core` consumers | Use Go **1.27.2 or newer** with its matching `GOROOT`. Go 1.27 macOS builds require macOS 13 or newer. Running a packaged native CLI does not require an installed Go toolchain |
| Former `openapi-kt download` / `help download` | Acquire the specification with an external tool, confirm acquisition succeeded, then call `validate` or `generate --input FILE`. Removed commands return usage exit 2 / `E_USAGE` without fetching or consuming stdin |
| Former `[specs.download]`, URL/header metadata | Remove downloader tables and metadata from TOML. Keep local `input` paths; unknown downloader fields fail with `E_CONFIG_UNKNOWN_FIELD` rather than being ignored |
| One direct streamed document | Explicitly use `--input -` for `generate`, `validate` or `generate --check`. The input must reach EOF and fit the existing 8 MiB limit. Configured specs remain local-file-only; use `input = './-'` for a literal file named `-` |
| Producer failures | Observe the producer's exit status. A valid complete JSON stream followed by producer failure cannot undo successful generation. When success must precede generation, first acquire a local file successfully |
| New DTO reference profiles | Eligible existing ordinary DTO owners and named/internal alias bridges preserve their canonical physical constructor/serializer identity. Access nested classifiers through their canonical owner, as documented in the [DTO reference contract](../internal-dto-references.md), rather than assuming Kotlin typealias provides nested classifier access |
| Persisted configuration/output/name locks | Preserve the existing configuration and manifest/name-lock versions and state. This release classification does not authorize deleting locks, resetting ownership, renaming owners or moving roots to bypass a diagnostic |
| Generated Kotlin and wire behavior | Downloader removal and the Go minimum upgrade preserve existing generated APIs and serialization/HTTP/SSE behavior. Opt-in optimization migrations continue to follow their individual contracts; unsupported inputs retain diagnostics |
| Default annotations that previously errored | Inputs documented below now generate instead of failing. Schemas without a `default` emit the same bytes as before, so existing generated sources and call sites are unaffected; only a schema that previously carried a rejected annotation changes |

The [local-input contract](../local-input.md) defines EOF, bounded reads, failure preservation and exact migration behavior. Existing `v0.1.0-alpha.1` packages retain their original Go toolchain and may still contain the downloader; they are not updated by changes in the working source.

### Default-value admission

Every profile in this section is **additive**: a schema whose annotation used to be rejected now generates. An invalid annotation value is still rejected with `E_SCHEMA_INVALID` at the same Pointer, so a wrong default is not silently accepted; only the shape admission widened. No field type or serializer changes, and a schema without a `default` keeps its exact previous output. One consequence is stated where it applies rather than here: a non-null bytes default is always written even with `encodeDefaults = false`, because `ByteArray` equality is referential. The action required is to re-read the diagnostics that no longer appear if a build previously depended on them.

**Object-default member roles.** An object default whose property references a collection now accepts plain ordinary DTO elements, finite collection aliases and internal bridges, finite nested List/typed Map trees, scalar/temporal/enum element leaves, and a direct `$ref` to a primitive union component; a property may also resolve a finite transparent chain to a plain object terminal. Each role keeps its own original-node authority, nearest nullable intent, budgets and exclusions, documented in [ordinary allOf object field defaults](../allof-object-defaults.md) and [direct inline object defaults](../nested-object-defaults.md).

**Component default factories.** A component schema's own root `default` now emits an opt-in factory instead of failing. There is no call site for a component, so the annotation never becomes a constructor initializer: the class keeps its signature, `required`/Patch classification and serializer, and adopting the default is an explicit caller decision.

| Component root | Factory |
|---|---|
| plain ordinary object, disjoint `allOf` constructor | companion member `default()` |
| plain scalar, String enum, numeric/Boolean native enum, standard temporal (`date`/`date-time`) | top-level factory function named `default` |
| finite inline List / typed Map tree with supported nullable or non-nullable layers | top-level factory function named `default` |
| bytes root (`format: byte`/`binary`) with a signed integer array | top-level factory function named `default` |
| `$ref`-only wrapper over an admitted target | top-level factory function named `default` on the alias |
| nullable ordinary object or explicitly nullable disjoint ordinary `allOf` constructor with `default: null` | companion member `default()` returning the nullable type, with no decode helper |
| explicitly nullable root with a non-null annotation | the shape's own form above, on the nullable public type ([contract](../nullable-component-defaults.md)) |
| raw JSON carrier (`additionalProperties: true` or an admitted empty-object root), including explicitly nullable `default: null` and eligible pure `$ref` wrappers | top-level `default()` on the actual `JsonObject`/`JsonElement` alias ([contract](../raw-json-component-defaults.md)) |

Collection factories now accept [finite nested inline List/typed Map trees](../nested-component-defaults.md) and independently nullable containers/leaves, including through an eligible `$ref`-only wrapper. Previously accepted inputs keep their generated API and wire behavior; the new input forms require no migration.

Raw carrier wrappers now validate through the target's own raw grammar and actual alias serializer; target files and referencing fields retain their behavior. Null annotations require effective nullability from the target or nearest explicit alias. See the [raw wrapper contract](../reference-wrapper-component-defaults.md#raw-json-carrier-targets).

[Finite pure component alias chains](../reference-wrapper-component-defaults.md#finite-pure-component-alias-chains) now let the outer wrapper own a default through eligible component aliases. The terminal role, actual alias serializer, original value Pointers, consumer depth and default budgets remain in force. Targets, intermediate aliases and fields do not inherit the annotation; previously accepted inputs require no migration.

[Explicitly nullable outer wrappers](../reference-wrapper-component-defaults.md#explicitly-nullable-outer-wrappers) now accept null and non-null own defaults through the existing pure chains. Target/intermediate types and referencing fields retain their behavior; the factory decodes through the actual nullable alias serializer. Plain scalars and nullable numeric/Boolean enum wrappers require validation. This additive profile requires no migration for previously accepted input.

[Nullable intent across aliases](../reference-wrapper-component-defaults.md#nullable-intent-across-component-aliases) now also accepts outer false and intermediate true/false on the same finite component chains. The nearest explicit setting wins, including narrowing OpenAPI 3.1 nullable roots without narrowing their children. Factory annotations and runtime serializers follow that actual alias; original declarations, fields, source budgets and warnings are preserved. Previously valid inputs require no migration. Explicit nullable plain-scalar wrapper annotations now enforce retained primitive bounds; invalid values formerly accepted because only the source was checked now fail with `E_SCHEMA_INVALID` at the wrapper's `/default`. Correct those annotations; valid default output and existing Kotlin API/wire behavior stay unchanged.

[Independent component defaults](../reference-wrapper-component-defaults.md#independent-defaults-on-target-and-intermediate-components) now allow admitted target and intermediate defaults on the same named-component chain. Each default validates at its original owner, retains its own nullable view and emits only its own factory. Unannotated aliases/fields never inherit a value; existing types, factories, warnings and output-state formats remain unchanged. Invalid source/annotations and individual resource limits still fail before output. Previously accepted input requires no migration.

Still rejected: unsupported default roles, `x-native-type`, value classes, `const`, `oneOf`/`anyOf`, reference/composition elements, inner defaults, union elements, and an unformatted numeric enum root. See the [component default factory contract](../component-default-factories.md) for the exact grammar, the retained native-enum approximation warning and the diagnostics that keep their original Pointers.

[Constrained plain-scalar component factories](../component-default-factories.md#constrained-plain-scalar-roots) now admit validation-on root defaults with existing String length/portable pattern, integer bounds/multipleOf and floating bounds. They preserve alias types, original JSON tokens, per-owner factories and non-inheritance. Bounded aliases without explicit nullable intent now validate their annotations against retained constraints; values formerly accepted by the legacy kind-only path fail at the original alias `/default`. Malformed constrained nullable root schemas report the actual constraint keyword (for example `/minLength`) instead of an unsupported-default location. Correct invalid annotations/schema metadata; valid prior output and API/wire behavior require no migration.

## Acceptance and packaging boundaries

Local source acceptance runs the entire `scripts/test.sh all` profile set and bounded fuzz targets against one frozen source tree. Generated Kotlin is compiled and run from fresh output, with existing compiler options and resource limits; no claims extend to the full option Cartesian product or wide-by-deep maximum combinations.

Local package preflight verifies the macOS ARM64 archive, SHA-256, the exact ten members (`openapi-kt`, `README.md`, `RELEASE.json`, `LICENSE`, `GO-LICENSE`, `APACHE-2.0.txt`, `THIRD-PARTY-NOTICES`, `THIRD-PARTY-NOTICES.md`, `YAML-LICENSE`, `YAML-NOTICE`) and installation/help/file/stdin/validate/generate/check without fixture or Go/Gradle dependencies from another checkout. Build archives with `--tag v0.2.0-alpha.1` and verify them with the [isolated package check](../releases.md#local-packaging). An archive is a local candidate until the complete acceptance and publication gates pass. Do not replace or distribute it as the historical release.

A new release still needs exact Git tree/history and package review, dependency-security review, version identity consistency and explicit Git/tag/upload/publication authorization. Packages are unsigned. Candidate scans and checksums do not constitute a complete vulnerability audit. Keep local logs, hashes, machine paths and task records outside public documentation.
