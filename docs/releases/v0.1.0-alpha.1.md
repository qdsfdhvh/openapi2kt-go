# v0.1.0-alpha.1

First **alpha preview** of the Go OpenAPI-to-Kotlin generator, licensed under [MIT](../../LICENSE). This is not the complete first version or a promise of stable generated APIs.

## Supported scope

- Local OpenAPI 3.0/3.1 **JSON** input, Kotlin serialization models and the documented bounded schema/reference profiles.
- The [initial Ktor HTTP client](../http-client.md) and [SSE subset](../sse.md), not a general-purpose implementation of every operation or parameter style.
- Explicit CLI generation, validation, read-only `--check`, local configuration and manifest-owned safe output handling. Downloads are separate from offline generation.
- Six CLI archive targets: macOS, Linux and Windows, each for AMD64 and ARM64. Every archive contains only the binary, `README.md`, project `LICENSE`, Go runtime `GO-LICENSE` and `RELEASE.json`; `SHA256SUMS` accompanies the archives.

See the [README](../../README.md) and [compatibility matrix](../compatibility-matrix.md) for the actual supported profiles. Unsupported semantics are diagnosed, not silently promised by the roadmap.

## Compatibility and migration

There is no previous published product version to migrate from. Alpha APIs may change; future version changes follow the [compatibility policy](../versioning.md), including Kotlin call sites, wire behavior, CLI/core and persisted state. Do not infer a persisted-format migration from the product version.

The Go module remains `openapi-kt`. Use local source installation or verified binary archives; a remote versioned `go install github.com/...@version` coordinate is not provided.

## Verification boundaries

The source CLI has hosted Go format/vet/test/race and native installation/generation/check evidence on Linux, macOS and Windows. Generated Kotlin has separate local macOS ARM64/JVM compilation/runtime evidence using Kotlin 2.4.10, serialization 1.11.0, Ktor 3.5.2, Gradle 9.3.1 and JDK 21.

Release packaging uses Go 1.26.0, standard-library dependencies only, CGO disabled and trimmed source paths. A release workflow must pass its entire Go-to-generation/check graph before packaging. Cross-built archives do **not** establish runtime behavior for all six architectures; Go generation/check does **not** execute the generated Kotlin.

## Known limitations

- YAML/Swagger 2.0, external/remote references and complete OpenAPI/JSON Schema support are not available.
- General reference/composition graphs, remaining HTTP parameter/response contexts and some model/validation/optimization combinations remain open.
- Android/KMP, minimum Kotlin versions and every binary architecture have not been fully verified.
- Very wide models combined with deeply nested generic collections can exceed Kotlin compiler/class-file resources despite independent width/depth limits passing.
- Packages are unsigned. Checksums and candidate scans are not a complete vulnerability audit or proof that every possible secret format has been detected.

## Installation

Use the matching archive and `SHA256SUMS` from the reviewed release. Verify its SHA-256 before extraction and placing `openapi-kt` (`openapi-kt.exe` on Windows) on `PATH`:

```bash
openapi-kt --version
openapi-kt generate --input tests/fixtures/catalog.json --output generated --package-name org.example.catalog
openapi-kt generate --input tests/fixtures/catalog.json --output generated --package-name org.example.catalog --check
```

The fixture commands assume a source checkout; fixture files are not bundled in the binary archive. With a binary alone, substitute your own supported local JSON input. Go and Gradle are not required to run the CLI. A draft release must be reviewed before publication; it is not an already-published stable release.
