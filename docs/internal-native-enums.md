# Native enum leaves through internal schema Pointers

With `--validation`, an existing local schema Pointer may borrow a direct numeric/Boolean enum leaf. For example, `#/components/schemas/Source/properties/code` referring to `{"type":"integer","enum":[1,2,3,4],"minimum":2}` retains mapped membership and numeric constraints in typed consumers. It adds no component entry or nominal classifier for the leaf. Only actual schema edges (`properties`, `items`, `additionalProperties`, and supported composition indices) are traversed; defaults/examples and arbitrary payloads never acquire schema roles.

This extends [typed native enum consumers](native-enum-consumers.md) and [numeric enum bounds](native-enum-bounds.md). Direct fields, finite internal reference chains, typed List/Map leaves, borrowed root collections and root scalar bridges retain the same source checks. HTTP inputs/results and SSE data reuse the typed check plan. Public wire types remain scalars/typealiases. A root `Bridge` may export `typealias BridgeDto = Int`; independently assigning or serializing a bridge value does not enforce checks. Actual generated DTO constructors/decoders and operation/event consumers do.

## Source and nullable behavior

The resolver borrows the original node, lexical owner and Pointer. Root bridges retain the actual original vocabulary array/member nodes and schema member views; final validation checks source identity and the actual generated root declaration. Equivalent text, a matching Kotlin name or a copied validation object does not establish the original binding. Forward root-container references share the existing catalog dependency traversal for this admitted source role; cached heights retain every incoming alias/reference hop.

The nearest explicit nullable override follows the existing borrowed scalar path. A direct nullable source can produce a nullable bridge; `nullable:false` at an admitted reference narrows the consumer while preserving membership, bounds and source work. Request Patch behavior remains governed by the existing request presence policy. [Null native enum members](native-enum-null-members.md) separately admit one null in explicit nullable numeric/Boolean vocabularies under validation. Numeric enum schemas with an empty admitted non-null bounds intersection are rejected even when nullable.

The existing 48 schema/source depth, 16 checked collection edges, 16,384 expansion work, 240 enum members and 240 serialized/operation slots remain. Long required fields retain their two-slot JVM layout. Diagnostics for malformed admitted enum vocabularies, defaults and bounds point to the original leaf. Pointer syntax/role errors retain use-site diagnostics. Root/borrowed leaf references do not gain default support; direct DTO defaults follow their separate contract.

## Limits and compatibility

Admission is opt-in and limited to direct `integer`, `number`, and `boolean` enum leaves accepted by the current native enum grammar. Bounds use the numeric enum profile, including the explicit exclusion of floating enum `multipleOf`. Native overrides, value-class/const annotations, general scalar enum composition/intersections and String/null-only vocabularies remain separate. The existing String enum nominal owner behavior is unchanged. [Named native enum borrowing](named-native-enums.md) additionally admits plain non-null named numeric/Boolean sources with their actual catalog/vocabulary/scalar export authority. [Nullable native enum roots](nullable-native-enums.md) separately admit checked nullable named scalar roots/aliases; general composition remains separate.

Without validation, these previously rejected native enum internal Pointer inputs remain rejected. Already supported default-off and checked profiles retain output and wire behavior. Historical numeric enum Pointer rejection cases preserve their original inputs and now explicitly assert validation-only scalar bridge/result support, alongside the default-off rejection.

Raw/stringification projections, ignored additionalProperties and discarded allOf fields continue to reject any checks they cannot retain. Membership and bounds participate in merge/dedup/name-lock identity. Persisted format versions remain unchanged.
