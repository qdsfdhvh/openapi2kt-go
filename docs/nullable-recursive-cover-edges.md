# Nullable reference edges in complete recursive JSON covers

OpenAPI 3.1 complete named recursive JSON-kind covers accept Boolean `nullable` siblings on their original array-item/object-value `$ref` edges and on transparent named reference nodes inside that graph. Each original value is validated; malformed nullable values still reject at their original Pointer. Defaults, bounds, native/value-class extensions, partial covers, reference-only cycles and other unsupported semantic siblings remain excluded.

A complete cover already contains JSON null. Its recursive fields live inside a `JsonElement` tree, whose null leaf is `JsonNull`. An edge's true/false carrier intent changes neither that tree representation nor the existing cover alias, wire codec, warnings or JSON value set. A narrowed non-null `JsonElement` still contains the `JsonNull` value. Separately exported nullable aliases and ordinary typed consumers retain the existing nearest-override `JsonElement?` policy, where JSON null may decode as Kotlin null. This extension grants no nullable root-cover syntax or default inheritance.

Original graph validation retains the SCC algorithm and source work: two edges per cover, one per transparent alias, longest outgoing group height, source depth48 and work16384. Nullable siblings do not erase or add an unfolded graph. Source snapshots retain original schema/branch/reference/nullable nodes, member/item identities and lookup consistency, so same-byte replacements cannot substitute a different source through a cached lookup. Borrowed cover aliases, JSON-value uniqueness and typed consumers reuse the same authority and existing budgets. Opt-in uniqueness still compares mapped JSON values and preserves its typed constructor boundaries.

The [core acceptance/grammar controls](../core/nullable_recursive_cover_edges_test.go), [SCC/original-intent identity tests](../internal/schema/nullable_recursive_cover_edges_test.go), [native parser/parity/old-output checks](../internal/cli/nullable_recursive_cover_edges_process_test.go) and [bounded deterministic fuzz](../core/nullable_recursive_cover_edges_fuzz_test.go) define this role. Historical nullable-edge negative inputs remain in their original test tables as positive or validation-mode controls; their other source refusals remain failures.

PREPARE_ONLY does not execute Kotlin. The complete `http` route includes the consumer without enabling the independent optional uniqueness profile.

**Migration:** eligible graph-edge inputs previously rejected and now generate. Accepted output bytes, API/wire/codec/warning and ownership/name-lock formats retain their contracts. General nullable recursive types, constrained or inline covers, Boolean false, full JSON Schema validation and broader platform/final candidate acceptance remain separate.
