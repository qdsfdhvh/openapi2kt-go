# Collection reference graphs in object defaults

A property inside an accepted ordinary object-default walk may follow a finite local `$ref` graph through named or internal List and typed Map schemas. Container elements may themselves reference another accepted container. For example, `member → Rows → items → Values → additionalProperties → Text` can consume `{"member":[{"a":"text"}]}` when Rows is a List, Values is a typed Map and Text is an accepted String schema. Finite transparent aliases and internal reference bridges compose with these edges.

This extends the existing [object-default member](nested-object-defaults.md) role. Accepted built-in, temporal and enum leaves retain their existing mapping and annotation checks; ordinary DTO and eligible disjoint allOf leaves retain their [constructor and source requirements](allof-object-defaults.md). It introduces no replacement declaration or serializer. The actual enclosing DTO serializer constructs the typed initializer and keeps its binding after deduplication, hoisting, merging and name locking.

Each container retains its own nullable view and checks. The nearest explicit true/false override controls only that reference's root; null container elements and null dictionary values require their respective schemas to allow null. Optional Kotlin presence grants no annotation permission. Every original hop and leaf validates even when the enclosing annotation is null, omits the property, or is suppressed for required/Patch/discarded output. Invalid values report the consuming default's original JSON Pointer, including escaped dictionary keys.

Only the consuming property's existing own-default role applies. Defaults on intermediate aliases, target collection roots and container elements are rejected; referenced component factories are never inherited. General consuming-field and component-root defaults, raw/native/value-class/hierarchy/composition terminals and arbitrary recursive default graphs keep their separate admission contracts. Cyclic container sources remain rejected. Plain enum defaults strictly match their original vocabulary, while supplied runtime String enum values retain open `Unrecognized` behavior.

Planning walks original document nodes rather than expanded copies. Every reference and container consumes the shared source-depth/work budget; final validation pairs original sources with the actual linked TypeRef. Existing source depth 48, source work 16,384, whole-default 16,384 JSON value nodes and 32 KiB original/canonical bytes, checked collection depth 16 and 240 constructor slots remain unchanged. Failed generation emits no artifacts and the CLI preserves existing output.

The [core tests](../core/object_default_graphs_test.go), [source/binding tests](../internal/schema/object_default_graphs_test.go) and [native parity/preservation tests](../internal/cli/object_default_graphs_process_test.go) define this D03 increment. `bash scripts/test.sh feature object-default-graphs` freshly generates Data/Plain × validation off/on projects, optimized locked output and independent width240/depth15 probes. The [consumer](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/ObjectDefaultGraphsContracts.kt) checks four Json settings, independent default instances and factories, null overrides, Patch, enum unknowns, controlled HTTP and fragmented still-open SSE cancellation/error closure/reuse. It is also registered in `http`. Independent width/depth probes do not establish a combined maximum-width × maximum-depth guarantee. `OPENAPI_KT_PREPARE_ONLY=1` prepares generation/check output without Kotlin runtime evidence.

**Migration:** previously rejected finite collection graphs in this member role now generate. Existing accepted Kotlin call sites, wire behavior and persisted lock formats require no migration. General D03, broader platforms and final release acceptance remain separate.
