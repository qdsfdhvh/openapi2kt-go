# 实现状态与剩余工作

本页汇总[开发计划](development-plan.md)中尚未关闭的工作。范围仍是离线 OpenAPI JSON／有界 YAML 3.0/3.1 → Kotlin 模型和有界 Ktor HTTP/SSE 客户端；完整路线图与[当前 JSON alpha 候选](json-release-checklist.md)分别验收。

## 状态口径

- **已有实现**：存在当前功能合同、源码和测试入口；只覆盖合同接受的输入和上下文。
- **功能缺口**：当前仍拒绝、近似处理或没有提供的能力，需要先明确增量合同再实现。一个有界子集完成，不等于对应兼容矩阵整项完成。
- **待验收**：实现已有，但同一候选、工具链、选项或目标平台的运行证据尚未统一关闭。不能把“测试存在”写成“本候选已通过”。
- **后续／范围外**：完整 YAML 超出已实现的 JSON-compatible adapter profile；外部规格获取、正式 Gradle 插件等不属于当前产品交付。已声明的近似映射也不自动成为必须改写的功能。

本页不记录本地运行日志，不给没有统一分母的完成百分比，也不改变既有支持或发布范围。精确输入边界以链接的功能合同为准；实际候选结果按 R01–R08 单独核验。

## 3. 已有实现的验收与剩余发布门槛

## 4. 后续阶段与当前不承诺项

- **P8 YAML**：已实现[有界 document loader adapter](yaml-input.md)，关闭同一 ordered JSON-compatible tree、core auto/json/yaml、native file/stdin/config、同义产物/warnings/语义 Pointer 与明确安全 profile 子项。完整 YAML、merge/tag directives、非 JSON tags/keys、一般 source spans 与新候选跨平台运行证据仍开放；现有 JSON 候选和 R01–R08 不自动关闭。见[Loader 设计](development-plan.md#33-json--yaml-的真正扩展点)。
- **输出中断策略**：已有[遗留事务检测并拒绝](recovery-rejection.md)。自动 recover 和跨文件/跨文件系统 crash atomicity 未提供，不是当前候选需补齐的隐含门槛。
- **规格获取**：下载、鉴权、代理、重试和输入原子获取由外部工具负责；不添加内置 downloader 或远端 `$ref` 获取。
- **当前范围外**：正式 Gradle 插件、GUI、其他生成语言、完整 OpenAPI/JSON Schema validator、应用鉴权流程；multipart/cookie/callbacks/webhooks/links 等未纳入现有合同。
- **指标解释**：已有 core options/parse/analyze/transform/emit timing、配置聚合及可用宿主的 process-lifetime peak RSS；独立 resolve/name 分摊和 per-phase memory 未提供。性能或编译收益需要独立测量，不由 metrics 或测试通过推导。

## 5. 推进顺序与维护规则

1. 交付当前 alpha 时，先按冻结范围补齐第 3 节的统一验收；只修复这个范围内的缺陷，保留其余路线图。
2. 扩展功能时，从 D01–D10 选一个真实输入缺口，先写清接受/拒绝边界与迁移影响，再实现最小 fixture、Go/native 和相应 Kotlin wire 合同。
3. 需要更广平台时，为目标平台建立独立消费工程及运行证据；YAML 按 P8 单独推进。
4. 完成增量后，同步功能合同、本页与兼容矩阵；删掉已经失效的缺口描述，保留仍未覆盖的范围。只有对应候选证据齐全时，才更新发布门槛。
