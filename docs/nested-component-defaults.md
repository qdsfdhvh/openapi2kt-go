# Finite nested collection component defaults

A component's own `default` may describe a finite inline tree of Lists and typed `Map<String, T>` values. The component receives an opt-in top-level factory using its actual alias serializer; consuming fields retain their constructor, presence and wire behavior.

```json
{
  "Rows": {
    "type": ["object", "null"],
    "additionalProperties": {
      "type": "array",
      "nullable": true,
      "items": {"type": ["integer", "null"]}
    },
    "default": {"rows": [1, null], "empty": [], "nil": null}
  }
}
```

```kotlin
public typealias RowsDto = Map<String, List<Int?>?>?
public fun `RowsDto default`(): RowsDto = /* typed JSON decode helper */
```

List → List, List → Map, Map → List and Map → Map are accepted, including longer finite paths. Each container and leaf retains its own nullability. Only an explicitly nullable root admits `default: null`; a nullable leaf alone does not authorize null for any enclosing container. Empty and null annotations still validate every original source node.

## Grammar and validation

Admission and value validation reuse the existing nested field-default walker. Leaves retain its supported builtin scalars, standard `date` / `date-time`, signed `byte` / `binary`, plain String enums (including typeless vocabularies), and numeric/Boolean native-enum collection roles. Enum annotations must belong to the original vocabulary; runtime String enums remain open to `Unrecognized`. Bytes retain signed integer-array wire values and generation-time range checks.

The component root owns its annotation. Eligible physical scalar references, named scalar-leaf collection references and their independent child annotations follow the [scalar-reference collection contract](scalar-reference-collection-child-defaults.md). Other inner container or leaf defaults, reference/composition elements, fixed-property DTO leaves, raw/open dictionaries, const, caller-native/value-class leaves and tuple schemas remain excluded. An `allOf`-wrapped collection retains its separate rejection. Existing nullable typed-Map root count restrictions remain separate; this role does not widen them.

Validation-enabled inputs retain supported counts, scalar bounds and innermost scalar-list uniqueness at every admitted layer. Invalid annotations fail during generation. Typed DTO consumers retain the same constructor/copy/decode checks as without the factory. Bare alias assignment and standalone builtin serializers do not enforce schema bounds. Validation-off inputs cannot silently drop constraints.

Factories decode a fresh tree on each call, including fresh ByteArrays. Public List/Map interfaces remain read-only; deep runtime immutability is not promised. A required referencing property retains its required constructor argument. Optional referencing properties keep neutral presence and never call the component factory automatically.

Eligible `$ref`-only wrappers may own a factory over these nested collection targets under the [wrapper contract](reference-wrapper-component-defaults.md). The target's source and generated bytes remain unchanged. Finite pure component alias chains follow the [chain rules](reference-wrapper-component-defaults.md#finite-pure-component-alias-chains); explicit nullable wrappers/intermediate aliases and intermediate/target defaults retain their restrictions.

## Sources, budgets and compatibility

Invalid values retain the original `/components/schemas/<Name>/default/...` Pointer, including escaped dictionary keys and a wrapper's own annotation location. Maps are validated in source order and sorted recursively only after successful validation; array order remains significant. Keys such as `$ref`, `/` and `~` remain opaque JSON data. Original schema/value nodes are never rewritten.

Existing source depth 48, checked collection depth 16, whole-default 16,384 value nodes and 32 KiB original/canonical compact JSON budgets remain unchanged. Overflow returns no partial report or artifacts. Independent boundary tests do not establish combined maximum-width/depth Kotlin compilation or additional platform support.

This adds factories for previously rejected component annotations (D03/M03/M04/M07). Unannotated declarations, previously admitted single-layer factories, Kotlin constructors, serializers, warnings and persisted lock formats retain their behavior. No migration is needed for previously accepted input. General defaults and other reference/composition roles remain separate.
