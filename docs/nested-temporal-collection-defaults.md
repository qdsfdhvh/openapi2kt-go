# Directly nested temporal collection field defaults

Component root annotations use the separate [finite nested component factory contract](nested-component-defaults.md); these factories do not become field initializers.

[Directly nested native enum field defaults](nested-native-enum-collection-defaults.md) separately cover an ordinary outer field's own default with existing Int/Long/Float/Double/Boolean enum terminals, preserving native scalar wire, the original vocabulary, and checked membership/bounds. They do not change this page's temporal grammar, lexeme identity, or bounds/uniqueness exclusions.

[Referenced temporal collection field defaults](referenced-temporal-collection-field-defaults.md) separately cover an ordinary direct `$ref` field's own annotation, binding actual LocalDate/Instant through already accepted named/internal finite List/typed Map paths. This page's direct-inline grammar and leaf-reference exclusion remain unchanged.

An ordinary DTO field may declare its own outer `default` on a finite direct inline List/typed `Map<String, T>` tree. Direct String `format: date` and `date-time` leaves use `kotlinx.datetime.LocalDate` and `kotlin.time.Instant`, respectively. The six existing builtin leaves continue to follow the [nested builtin default contract](nested-builtin-collection-defaults.md). Outer field defaults for plain unformatted String enum leaves separately follow the [nested String enum contract](nested-string-enum-collection-defaults.md), preserving the actual lexical enum and open runtime vocabulary without admitting nested enum String bounds/patterns. List/List, List/Map, Map/List, Map/Map, and longer finite mixed paths follow the same rule.

```json
{
  "type": "array",
  "items": {"additionalProperties": {"type": "string", "format": "date"}},
  "default": [{"a": "2024-02-29"}]
}
```

An optional ordinary field generates `List<Map<String, LocalDate>>?` and a typed initializer. Missing JSON uses the default, explicit null remains null, and an explicitly supplied collection replaces the entire default collection. Each constructor/default evaluation decodes an independent collection tree through the existing typed JSON helper and standard temporal serializers; empty collections retain their full generic types. The public List/Map interfaces do not promise deep immutability.

Original nullability is independent at each container and leaf layer. An annotation null requires explicit nullability on the corresponding schema; field optionality alone does not authorize it. Required fields still have no initializer, but their complete annotations must first be validated. `explicitNulls=false` retains existing missing-required-null inference. An optional explicitly nullable inline request field remains `Patch.Absent`; its default does not turn a missing key into an update. Null/Value retain bare wire behavior, and inner nullability does not create Patch. See [request presence](request-presence.md).

## Original annotations, ISO, and identity

Every original schema node is validated even when the default is empty or null. This contract admits only an ordinary DTO field's own outer default. Date/date-time child-node annotations on direct List/Map fields of ordinary named DTOs are validated under the separate [child-node contract](inline-builtin-collection-child-defaults.md). Deeper containers/leaves, target/chain/root defaults, named/reference collection defaults, `$ref` temporal leaves, native-date/provider/value-class, formatted enum/const/union/hierarchy leaves, and composition wrappers retain their respective admission limits (inline DTO object leaves use the separate [object collection contract](nested-object-collection-defaults.md)). Plain unformatted String enum leaves receive outer field defaults only under the separate contract above, without changing temporal grammar or checks. This contract does not extend general schema roles, intersections, or default inheritance.

LocalDate uses existing valid four-digit-year ISO date rules, including real leap-day checks. In addition to existing RFC3339 date checks, Instant shares the [single-layer collection limits](primitive-array-defaults.md#date-and-timestamp-elements): a four-digit year, uppercase T/Z, two-digit time fields, at most nine fractional digits after a dot, and Z or a valid offset within ±18:00. Comma fractions, single-digit hours, excess precision, invalid leap days, and out-of-range offsets are rejected at generation time so an initializer does not fail on first execution. No timezone-equivalent default identity or date ordering rule is added.

Original default members must have the correct JSON kind. Errors use the original `/default/<index>/<escaped-key>/...` Pointer; each Map is validated in source order and its key order is canonicalized only after success. Keys such as `$ref`, `type`, `/`, and `~` are always opaque data. Array order and original temporal strings participate in default identity. Instant runtime wire retains ISO UTC normalization; source strings are not guaranteed to round-trip verbatim, and different source offsets or fractional spellings of the same instant do not share default identity. Existing exact integer and mapped Float/Double identities retain their meaning.

Helpers use LocalDate/Instant keys in valid JVM method names, and serializer generics bind the final actual TypeRef. Dedup/merge/hoist/name-lock use existing typed tree/check/default domains. Reordering canonical keys preserves output and locks; changing the effective default, nullable layer, or retained checks changes the shape. Required/Patch annotations without initializers create no runtime default identity. Lock format, occurrences, and canonical replay rules remain unchanged.

Ordinary shared/nested DTOs and ordinary inline request/response/SSE payload DTOs can consume this profile. Existing ordinary object allOf retains later-field override; original discarded annotations must still be validated, and override or output suppression cannot remove invalid annotations or checks. Union/hierarchy fields and collection-check aggregation across contributions remain rejected.

## Validation and resources

With `--validation`, List min/maxItems and typed Map min/maxProperties at every layer constrain both the original default and supplied typed values. Null skips only its own non-null checks; empty collections must still satisfy minimum counts and validate the entire leaf grammar. Constructors, Data copy, automatic serialization, Patch.Value, typed HTTP, and SSE use existing recursive checks.

Temporal `uniqueItems:true` follows the [mapped-value uniqueness contract](temporal-unique.md), including duplicate detection for equivalent Instant offsets/fractions in defaults. Temporal String/numeric bounds remain rejected, including for empty/null defaults; a String source type does not introduce String length/pattern. `uniqueItems:false` retains the existing validation metadata/no-op contract. Existing builtin leaf checks and all NoDrop guards remain. Bare collection assignment, standalone builtin codecs, subsequent caller mutation, and requestBuilder replacement are not schema validation barriers.

All original budgets remain unchanged: 8 MiB input, source depth 48, checked collection depth 16, 240 serialized slots, 16,384 units of analysis work, and existing schema/alias/name-lock caps. Before canonical allocation, each original default independently preflights its full tree of 16,384 values (including containers/null) and 32 KiB compact JSON; canonical JSON has a separate 32 KiB limit. Keys and scalar contents count in bytes, and required/Patch/discarded annotations also count against the budget. Failure returns no partial files, locks, or warnings; native generation preserves old owned output and handwritten files. Compiler heap has not been increased, and maximum width × maximum depth or Android/KMP is not guaranteed.

## Compatibility and verification entry points

These directly nested temporal defaults previously returned `E_SCHEMA_UNSUPPORTED`; existing single-layer temporal and default-free collection APIs, wire behavior, and lock identity are preserved. This increment closes only the direct nested temporal part of D03, extends M02/M03/M04/M07, and retains typed consumer contracts M12/V05 and A03/A05/A08. General default references, nominals, roots, and other roles remain open.
