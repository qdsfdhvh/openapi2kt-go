# Model semantics

[Ordinary allOf object field defaults](allof-object-defaults.md) accept direct inline ordinary constructor DTO fields and direct local `$ref` fields whose terminal is an existing named or unique internal allOf constructor Model with disjoint property contributions. Eligible references may traverse accepted named aliases/internal hops; final retained declaration authority, actual lexical owner, nearest nullable intent and original source fields remain. Internal scopes include property/collection-owned Models, root peers and unique composition-owned concrete Models. [Referenced finite collection fields](allof-object-defaults.md#referenced-collection-field-defaults) also accept outer defaults whose element references an eligible named/internal allOf Model, retaining actual collection/element serializers, independent nullable layers and the same source/type authority. [Direct inline List/typed Map fields with bare allOf constructor elements](allof-object-defaults.md#direct-inline-collection-field-defaults) also accept outer own defaults, scoped to the consuming field's original element node and the shared planner's actual nonempty Model. [Bare allOf elements inside referenced collection trees](allof-object-defaults.md#bare-allof-elements-in-referenced-collections) also accept outer own defaults through actual retained constructor/node/Pointer/owner authority, including package-relative root peers and existing collection aliases. [Direct inline allOf object-default properties](allof-object-defaults.md#inline-allof-properties-inside-object-defaults) now reuse the disjoint merged-field walk with a nonempty ordinary constructor, original required/nullable/source/budget checks and final enclosing serializer; referenced allOf property targets use the [named/internal chain member contract](allof-object-defaults.md#referenced-allof-properties-inside-object-defaults). [Inline List/typed Map properties with bare allOf leaves](allof-object-defaults.md#inline-collection-properties-inside-object-defaults) use per-property original-leaf permission, the same ordinary constructor gate and shared budgets, retaining independent nullable layers and the final enclosing serializer. [Referenced allOf elements in inline collection properties](allof-object-defaults.md#referenced-elements-in-collection-properties) also retain the original element reference and complete named/internal chain, nearest nullable intent, existing terminal constructor authority and shared budgets; [named collection properties with named allOf reference elements](allof-object-defaults.md#named-collection-properties-inside-object-defaults) also preserve original named container/alias paths, including [internal reference bridges between named roots](allof-object-defaults.md#internal-bridges-in-named-collection-aliases), actual root nullable semantics and shared budgets. [Direct internal reference prefixes to named collections](allof-object-defaults.md#direct-internal-references-to-named-collections) also preserve original hop identity, full budgets and nearest nullable intent over the first named type view. [Internal collection entities](allof-object-defaults.md#internal-collection-entities-inside-object-defaults) also retain original internal List/Map sources, named allOf reference elements, current lexical authority, actual nullable views, full budgets and shared retained-declaration checks. [Referenced collections with bare allOf element leaves](allof-object-defaults.md#bare-allof-element-leaves-in-referenced-collection-members) borrow the same retained constructors, and [internal allOf element terminals](allof-object-defaults.md#internal-allof-element-terminals-in-referenced-collection-members) bind their original node through the shared resolver seam while keeping the physical lexical owner; [plain DTO elements in referenced collection members](allof-object-defaults.md#plain-dto-elements-in-referenced-collection-members) follow the original terminal plain object and its per-member Pointers, including finite named collection aliases, internal bridges and finite nested List/typed Map trees that keep every hop's original node/Pointer/SourceCatalog and nearest nullable intent; inter-container references retain a separate member role. [Direct inline collection fields with allOf element references](allof-object-defaults.md#direct-inline-collections-with-referenced-elements) defer their own annotation until final nominal/source linking, preserving actual collection/element types, original node/Pointer/owner and pre-presence nullable intent. The shared shape retains original fields/required/nullable intent; existing default checks, budgets, final type binding and required/Patch suppression remain. A finite transparent chain to a plain object terminal follows the member [plain-object chain rule](allof-object-defaults.md#plain-object-chains-inside-object-defaults). A property `$ref` to a primitive union component reuses the [primitive-union member role](union-field-defaults.md), enforcing accepted-branch membership and enum/const pins against its own Pointer; object union components and union alias chains keep their separate roles. Reference wrappers, repeated-field aggregation, hierarchy sources/owners and target/root/component defaults retain separate roles.

## Primitive components

Non-nullable string, boolean, integer and number components generate Kotlin typealiases using the same scalar/format resolver as inline properties. Local references to these components inline the resolved Kotlin scalar in consuming model fields, including array items and nullable references. Object and string-enum references continue to use their generated named types.

Component suffixes apply to exported aliases; consuming primitive fields remain scalar types. These aliases are transparent, not value classes: they do not create new runtime identities or independent overloads. Standard kotlinx.serialization primitive serializers retain the numeric wire representation and range behavior.

Required non-null Long/Double references count as two JVM constructor slots; nullable/optional references count as one boxed slot. [Go model contract tests](../core/model_contracts_test.go) cover exact limits and unsupported semantic component keywords even without consumers. [Generated Kotlin runtime tests](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/PrimitiveContracts.kt) cover numeric extremes, alias/ref/suffix behavior, nullable array items and 120-wide/240-boxed constructor boundaries.

Intrinsic nullable builtin roots have the separate [transparent nullable primitive contract](#intrinsic-nullable-builtin-primitives) below; nullable enum/const and broader roots are not implied. Direct array components have their own [collection alias profile](#array-components), including a separate [nullable-root profile](#nullable-array-components). Simple scalar reference-alias chains and bounds have a separate opt-in [validation contract](#primitive-alias-validation). Simple primitive components can opt into the independently verified [value-class subset](#simple-primitive-value-classes). Direct special formats have a separate [special scalar contract](special-scalars.md). Unsupported component semantics are not dropped during reference inlining. Existing accepted P1 inputs keep their output; primitive roots that were previously rejected now generate aliases.

## Intrinsic nullable builtin primitives

Plain String/Boolean/Int/Long/Float/Double components may use `nullable: true` or a supported single primitive plus `null` type array. Existing type/format grammar determines the builtin mapping. The exported root is a transparent `typealias Root = kotlin.Long?` (for example), not a wrapper, generated companion or new runtime identity. Use reified `serializer<Root>()` or the builtin serializer's `.nullable` adapter. Native null, Boolean and numeric encoding/range behavior remain unchanged.

Direct and supported single-ref wrappers inherit intrinsic root intent. Pure component aliases **to these intrinsic targets** retain the nearest explicit true/false override; a false root exposes the real non-null builtin backing. List items and map values keep their own intent. Shared nullable fields retain default-null; inline request required-nullable fields have no default, optional-nullable fields use Patch, and optional false-narrowed fields retain ordinary defaults. Nullable/non-null method identities still use builtin erasure and existing numeric suffix allocation.

Unbounded roots work with either validation setting. Bounds retain the existing opt-in contract: without `--validation`, unsupported bound keywords fail; with it, typed DTO constructor/copy/automatic serde, Patch/list/map, HTTP pre/postflight and SSE payloads keep original source checks. **Bare alias assignment and standalone reified builtin serialization are not constraint barriers**, even for a bounded nullable root. Enable a primitive value class when an intrinsic constructor/serializer barrier is required. Null skips primitive checks; narrowed required values reject null.

Root String HTTP values keep Ktor's raw-text projection: a null request writes ASCII `null` and a matching response returns the String `"null"`, not Kotlin null. This differs from nullable String JSON fields/reified codecs and SSE data. Boolean/numeric HTTP roots retain JSON null/value decoding. Nullable Int JSON responses use the generated client's configured Json codec on response text: Ktor's default erased-Int transformer otherwise attempts to parse `null` as a non-null integer before ContentNegotiation. This also fixes formerly accepted inline nullable Int response schemas. Non-null Int and raw String/ByteArray reception stay unchanged. Affected non-SSE clients/groups gain a defaulted Json constructor argument; existing two-argument source calls still work, but compiled consumers must be rebuilt (not a binary ABI guarantee). Query null omission/stringification is unchanged.

**Migration and limits:** these direct intrinsic roots were previously rejected. Existing non-null primitive outputs and validation-opt-in non-null scalar-ref aliases are unchanged. Own-nullable component aliases to **non-null** primitive targets have the separate [binding contract](#own-nullable-builtin-primitive-aliases). Enum/const/native/value-class roots have separate contracts; nullable shape borrowing through composition/hierarchy/mappings/SSE envelopes remains rejected, even through false-narrowed aliases. Transparent roots never reset source work: depth 48, checked collection edges 16 and constructor/method slots 240 (non-null Long/Double width two, nullable width one) remain. Independent maximum-width/depth profiles are not Cartesian, Android/KMP/minimum-toolchain or full F04/F07/M02 guarantees.

## Own-nullable builtin primitive aliases

Pure component `$ref` roots with `nullable: true` may target accepted non-null ordinary String/Boolean/Int/Long/Float/Double components. The public alias exposes builtin `T?`; aliases to it and supported wrappers inherit nearest nullable intent, and explicit false descendants use real non-null builtin backing. Canonical roots remain non-null. There is no generated constructor, companion or separate serializer: use reified builtin serialization or the canonical nullable adapter. Shared optional/default-null, required-nullable request fields and optional Patch remain context-specific.

This is separate from intrinsic nullable roots. Otherwise unmarked or false-only aliases directly to non-null builtin targets retain their historical `--validation` admission. A document containing such an unsupported intermediate is still rejected with validation off, even if another alias points to it with nullable intent. With validation on, an own-nullable alias may traverse an accepted legacy non-null alias; canonical source constraints and cached source height are retained without changing the legacy alias declaration.

Bounds require `--validation`; typed constructor/copy/serde, list/map/Patch and HTTP/SSE checks retain them. Nullable values skip primitive checks, required narrowed values reject null. Bare alias assignment/standalone serde is not validation. Existing raw String/null-ASCII HTTP behavior, nullable Int configured-JSON reception, numeric/Boolean JSON and query policies remain unchanged.

**Migration and limits:** these own-nullable inputs were previously rejected; existing accepted non-null alias text/wire and default-off admission are preserved. Root alias grammar stays `$ref`/`nullable`, not a new type-array reference grammar. Enum/const/native/value-class profiles, defaults and general nullable composition/graphs are separate. Nullable scalar intent cannot be borrowed as object/composition/hierarchy/SSE-envelope shape. Alias hops still count toward depth 48; checked edges 16, constructor/method slots 240 and two-slot non-null Long/Double accounting remain. Independent 240 boxed/120 narrowed/48-hop/16 checked probes and maximum-method compilation do not establish Cartesian or platform/minimum-toolchain coverage.

## Array components

Non-null direct array components generate native `typealias <ComponentName><Suffix> = List<T>`. The existing item resolver supplies supported scalars, nullable elements, nested List/Map, component references and inline object/enum/union shapes. Inline declarations are top-level peers named from `<AliasName>Inner`, with global collision checks; a typealias cannot own nested declarations. Named consumers retain the exported alias spelling. This introduces no wrapper object or JSON envelope: the wire value remains an array. Kotlin callers use ordinary collection construction and generic serializers, not a generated alias constructor or `Alias.serializer()`.

The underlying typed plan is linked even for consumers analyzed before the array's declaration. After forward bindings and transparent-cycle validation, checked leaves receive private emission hints: constructor/copy/automatic serde call bounded non-inline property check methods rather than repeating all checks in a 240-field constructor. These are methods, not extra state or serializer fields, and retain the same checks and failure labels; dictionary-only inputs keep their existing output. With `--validation`, container counts, eligible scalar uniqueness and leaf checks propagate through DTO constructor/copy/automatic serde, nested list/map consumers, request-only Patch.Value, typed HTTP body preflight/response postflight and SSE event construction. Root alias assignment or independent collection serialization cannot enforce these checks; nominal DTO item constructors remain validation/recursion barriers. Existing named parameter projections do not become new recursive query encoders.

Transparent cycles through array/dictionary aliases fail with `E_REF_CYCLE`; cycles separated by a nominal DTO remain valid. Root schema/alias graphs retain the existing 48-level guard, checked consumers retain 16 collection edges, and array-valued fields consume one of the 240 constructor slots. [Cumulative named collection-alias depth](#collection-alias-consumer-depth) also checks consumer schema nesting plus one reference hop and cached transparent alias height. These checks do not establish a combined width/depth compilation guarantee or complete consumer-height policy for every future reference graph. Pure component-root reference bindings remain outside this increment. Nullable array roots use the separate profile below; root, consumer and item nullability remain independent.

**Migration:** previously rejected non-null array components now expose native collection aliases. Existing accepted files and dictionary aliases remain unchanged. Malformed newly admitted arrays now report their original `items`/constraint grammar rather than only an unsupported component root. The original `array-component` corpus input explicitly graduates with full artifact checks in core and native CLI; the `root-array` document (`[]`) remains invalid. Original manifest, input and snapshot bytes are retained. The [synthetic envelope](../tests/fixtures/http/array-components.json), [core source/limit contracts](../core/array_component_test.go), [native CLI preservation](../internal/cli/array_component_process_test.go) and [fresh Kotlin consumer](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/ArrayComponentContracts.kt) exercise aliases, top-level enum/model peers, recursive DTOs, four Json configurations, Patch, typed HTTP and still-open fragmented SSE failure closure/reuse. Independent 240 shallow alias fields and one 16-edge alias consumer are compilation probes, not Android/KMP or Cartesian resource proof. Full M03/M06/F04 remains open.

## Named true component roots

OpenAPI 3.1 literal `true` component roots export canonical JsonElement aliases under the separate [named-root contract](boolean-roots.md). Pure root ref chains retain source hops; the separate nullable-alias profile inherits nearest true/false intent with canonical non-null JSON backing. Nullable codecs collapse JSON null to Kotlin null, whereas false narrowing retains JsonNull. Consumer overrides retain existing presence/Patch. Original root warnings, false/version/shape/internal-target exclusions and alias-free codec usage remain explicit.

## Direct true value schemas

OpenAPI3.1 literal `true` in ordinary property/typed array-item slots has the separate [initial unconstrained JSON value contract](boolean-values.md). Required fields use JsonElement/JsonNull, optional fields retain the existing `{}` nullable/default profile without implicit Patch. Original source warnings and false/version/reference/composition exclusions remain explicit; this is not complete Boolean-schema support.

## Primitive positional arrays

OpenAPI 3.1 nonempty ordinary primitive `prefixItems` has the separate [initial positional-array approximation contract](primitive-tuples.md): matching scalar signatures → `List<T>`, different signatures → `List<JsonElement>`, explicit ordinary scalar `items` wins after every original member validates. `W_TUPLE_APPROXIMATION` identifies lost positions/lengths and potential unrestricted-tail narrowing. This does not admit boolean value schemas or general structured/ref/composed tuples.

## Nullable array components

Direct `type: array` with `nullable: true`, or OpenAPI 3.1 `type: [array, null]`, generates `typealias Rows = List<T>?`. Item peers, suffixes, serializers, source checks and forward bindings follow the ordinary array profile. Null roots and null items are independent; this is a native nullable collection, not a wrapper or JSON envelope.

A named reference or supported single-ref `allOf` wrapper with no explicit override inherits the root's nullable intent. Explicit true remains nullable. Explicit false exposes the genuinely non-null backing collection, for example `List<org.example.generated.models.RowsInner>`, rather than a still-nullable `Rows` alias. No additional exported `NonNull` alias is created. Only the root nullable layer is removed; nested nullable items/containers and nominal item identities remain. Component item peers are qualified even in API/SSE packages, and consumers planned before the alias retain its shared target. Historical nullable dictionary overrides are not changed by this array-specific profile.

Shared component fields retain `Rows? = null`, even when required. Inline request DTO required nullable fields have no default; optional inherited-nullable fields use `Patch<List<T>>`, including ref wrappers. Absent omits the key, Null writes JSON null, Value enforces the original leaf/count/unique rules. Required nullable keys depend on `explicitNulls`, as in the [request presence contract](request-presence.md). Narrowed required fields have non-null descriptors and cannot decode JSON null. Independent nullable alias assignment/serde remains unchecked; typed DTO/HTTP/SSE consumers still enforce checks when non-null.

The same original-node cycle, cumulative 48-schema, 16-checked-edge and 240-constructor-slot guards apply; narrowing adds no schema hop or nominal barrier. Nominal item recursion remains allowed, transparent alias recursion does not. Nullable object/primitive component roots, pure root refs and internal nominal graphs are not admitted here.

**Migration:** previously rejected direct nullable array components now generate native nullable aliases. For newly admitted inputs, explicit-false consumers use backing `List<T>` signatures; inherited/true consumers retain the exported alias. Existing non-null arrays, dictionaries and historical corpus artifacts are unchanged. This only graduates the direct nullable-array guard, not nullable object roots or document-root arrays. The [synthetic envelope](../tests/fixtures/http/nullable-array-components.json), [core contracts](../core/nullable_array_component_test.go), [native CLI preservation](../internal/cli/nullable_array_component_process_test.go) and [fresh Kotlin consumer](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/NullableArrayComponentContracts.kt) cover forward peers, source errors, required/default descriptors, four Json configurations, constructor/copy/serde/Patch, typed HTTP and fragmented live SSE. Independent 240 shallow nullable/narrow fields and one 16-edge narrowed consumer are compilation probes, not Android/KMP or Cartesian resource guarantees. Full F04/F07/M03/M07 remains open.

## Root object aliases

A pure named-component `$ref` root whose terminal is an accepted non-null ordinary object DTO generates an exported native typealias. Forward chains use the canonical target's identity, constructor and serializer; they do not copy a DTO or introduce a wrapper:

```kotlin
public typealias RecordAlias = org.example.generated.models.Record
```

Both validation modes accept unconstrained object aliases. If the target contains opt-in checks, `--validation` remains required and the original DTO constructor/copy/automatic serializer owns them. References to aliases expose the canonical target in model/API/SSE signatures. Kotlin callers may use alias constructors and companion serializers, but the alias is not an independent runtime type or overload identity. Alias/direct HTTP method collisions use the existing numeric suffix allocator.

Root alias graphs retain original nodes and Pointers, bounded active-path/cached heights and every reference hop. Nominal DTO recursion through an alias remains a barrier; aliases-only cycles are rejected (the historical default-mode unsupported self/cycle diagnostic is preserved; validation mode uses `E_REF_CYCLE`). Typed uses and ordinary `allOf` expansion include alias hops in the 48-schema budget. Missing/external references, malformed reference values and semantic siblings fail; descriptive metadata/examples remain opaque. Invalid target fields report the target's original source and preserve old CLI output.

This profile includes ordinary object composition targets, but not empty/raw `JsonElement` projections, hierarchy-owned DTO leaves, nullable root aliases, collection/enum/valueclass/native/const/union targets or discriminator graph/mapping aliases (other accepted root targets have their separate contracts). Eligibility is checked against final declarations, so catalog object syntax alone cannot invent a nominal DTO identity or constructor. Existing opt-in scalar-only root aliases retain their independent native-scalar contract. Object property-count aggregation through reference composition and internal nominal schema Pointers are not added. Pure root aliases are distinct from supported inline annotation-only ref wrappers.

**Migration:** previously rejected ordinary object root aliases now emit typealiases and canonical DTO signatures, not newly duplicated request/response models. ```kotlin
@kotlinx.serialization.Serializable
@kotlin.jvm.JvmInline
public value class UserId(
    public val rawValue: kotlin.String,
)
```

Supported underlying types are String, Boolean, Int, Long, Float and Double with their ordinary supported formats, including UUID as an unvalidated String. An explicit type is required. The flag must be boolean; false on the same simple component schemas preserves the existing alias output. Without the flag, existing generated files and call sites are unchanged.

References keep the wrapper's identity and suffix in fields, nullable uses, list elements and dictionary values, including supported nullable/ref-wrapper folds. Different wrappers of String support distinct Kotlin overloads and are not runtime-equal merely because their raw values match. Use the constructor and `.rawValue` explicitly; transparent primitive aliases do not provide this API, while wrapper aliases retain the canonical wrapper API. Kotlin/JVM may mangle value-class method names; no Java reflection/interoperability contract is established.

Automatic kotlinx.serialization writes the **underlying primitive**, not an object with a `rawValue` key. Nested/structured parameters and reference-owned collection aliases keep their documented one-value projections; this is not a new recursive encoder. JSON bodies/responses and SSE payloads retain the wrapper and its serializer. The SSE cursor remains scalar String-only, not a wrapper argument.

**Opt-in migration:** a root String wrapper body is serialized as JSON-quoted text by ContentNegotiation; a bare String/transparent alias root retains Ktor's raw-text behavior. Pure non-null wrapper bindings have the separate [root special alias contract](#root-special-aliases); nullable wrapper bindings and intrinsic roots have the [own-nullable alias](#root-nullable-value-class-aliases) and [intrinsic component](#intrinsic-nullable-value-class-components) contracts. ## Primitive value-class bounds

A simple component with `x-kotlin-value-class: true` can declare String `minLength`/`maxLength` or numeric inclusive `minimum`/`maximum`. String [patterns](#string-pattern-validation) are independently supported. Checks live in the value class's `init`, so caller construction **and automatic JSON decoding** enforce the same rule. References, lists, dictionaries and request-only Patch preserve that validation without generating duplicate use-site checks. Invalid server HTTP/SSE payloads fail decoding; a failed stream closes its input without closing the caller's HttpClient.

```json
{"Name":{"type":"string","x-kotlin-value-class":true,"minLength":1,"maxLength":2}}
```

- Length bounds are nonnegative plain integer literals within Int range. Length counts Unicode codepoints: an emoji surrogate pair counts as one; `e` plus a combining mark counts as two. It is not UTF-16 unit count, grapheme count or normalization. Null/Absent at nullable/Patch use sites is not a String value and has no length check.
- Integer bounds must be integer literals representable by the mapped Int/Long. No widening or fractional/exponent bound rounding is added. Long checks and source-bound ordering are exact, including values near Long extrema.
- Float/Double bounds must map to finite values. Checks use their mapped IEEE representation, including Float rounding/underflow, not arbitrary-precision JSON instance validation. A floating bound also requires a finite runtime value, so NaN/infinity cannot bypass comparisons, even under a permissive Json configuration.
- Reversed source bounds fail with original keyword Pointers; exact ordering is checked before floating rounding. To bound decimal comparison work, numeric bound tokens allow at most 256 characters and exponent magnitude 512. Existing JSON-loader finite-number policy still applies before analysis.
- Wrong scalar/constraint combinations, negative/non-integer lengths, unrepresentable/reversed bounds, false-flag constraints and unsupported semantic siblings fail explicitly. DTOs without `--validation`, primitive aliases, enum/native/temporal/byte mappings, collection cardinality and defaults remain outside this slice. Numeric exclusives and `multipleOf` follow the separate [numeric constraint contract](#exclusive-bounds-and-multipleof).
- Constructor failures use `IllegalArgumentException` with fixed messages, without interpolating raw values. JSON/Ktor can wrap this cause; no particular transport exception subclass is promised. Valid values retain their primitive wire format. No extra serialized fields/helpers or constructor slots are introduced, and wrappers without bounds keep their output unchanged.

[Original fixture](../tests/fixtures/http/value-constraints.json), [Go checks](../core/value_constraints_test.go), CLI failure-preservation/ownership tests and [fresh Kotlin contracts](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/ConstraintContracts.kt) verify Unicode boundaries, exact Long/Float edges, constructor/serde enforcement and invalid HTTP/SSE payloads with client recovery under all four Json default/null configurations. This is the first M12 bounds subset, not complete JSON Schema validation or Android/KMP evidence.

## Opt-in DTO field bounds

Add the bare `--validation` flag to `generate` **and to matching `validate`/`--check` commands**, or set `GenerationOptions.Validation = true`. Default is false: previously rejected ordinary DTO constraints remain rejected and all existing unconstrained output remains byte-identical. Bounds on explicitly enabled primitive value classes do not depend on this flag.

```bash
openapi-kt generate --input spec.json --output build/generated \
  --package-name org.example.api --validation
openapi-kt validate --input spec.json --validation
```

With the flag, direct String/Int/Long/Float/Double **properties of generated DTOs** support the same four [wrapper-bound rules](#primitive-value-class-bounds): Unicode codepoint lengths, inclusive mapped-type bounds, exact source-bound ordering and finite floating values. These properties stay ordinary primitives, not wrappers. `init` checks run on construction, data-class `copy` and automatic JSON deserialization; messages start with the fixed `Field value` label, without raw values/property names. Nullable/optional values are checked when non-null. Request-only nullable optional `Patch.Value` is checked; `Absent` and `Null` retain their original omission/null behavior. Presence/default/required semantics are otherwise unchanged.

The supported contexts include component DTOs, nested inline DTOs, DTO references used in lists/dictionaries, inline HTTP request/response DTOs and SSE object payloads. Per-property local scopes and qualified field access avoid collisions with `value`, `length` and escaped keywords. Synthetic 120-wide bounded Long and 240 nullable Double DTOs compile with their normal slot accounting.

This is **not a recursive validator for arbitrary TypeRefs**. Numeric exclusives and `multipleOf` follow the separate [numeric constraint contract](#exclusive-bounds-and-multipleof). A raw object/map parameter projection has no generated DTO constructor, so its bounded fields are rejected rather than accepted and dropped. Object merge/union/hierarchy limitations remain in force: unsupported common-field or overridden-bound projections fail closed (except the [ordinary primitive conjunction](#flat-inline-allof-primitive-bounds) and its [referenced/nested extension](referenced-allof-bounds.md)); previously documented uniform-union approximation warnings are unchanged and do not become runtime checks. ## Primitive collection-element validation

A single bounded primitive branch plus null in `oneOf`/`anyOf` preserves its leaf checks and existing overlap warnings. ```json

  {"type":["string","null"],"minLength":1,"maxLength":2}}}

Typed HTTP list/map arguments and bodies are checked before dispatch; typed primitive-container success responses after decoding. This is element validation; [typed collection counts](#typed-collection-counts) are a separate increment. ## Bounded scalar uniqueness

With `--validation`, `uniqueItems` must be Boolean on otherwise supported typed arrays. `true` supports homogeneous native **String, Int, Long and Boolean** elements, including nullable leaves and supported transparent scalar references. Strings use exact parsed equality, with no Unicode normalization: `"é"` and `"e\u0301"` differ, while `"a"` and `"\u0061"` are equal after decoding. Integers and booleans use exact native equality; at most one null is allowed. Empty/singleton lists pass uniqueness unless a separate count bound excludes them.

`false` is a validated effect-free no-op, even for supported non-scalar element schemas: generated artifacts and validation metadata are identical to omission. It does not broaden element support, excuse malformed values, or allow the keyword on non-arrays. Both Boolean values are rejected without the opt-in. The [JSON-value array profile](json-unique.md) separately supports direct unconstrained JsonElement/JsonObject leaves with recursive equality. The scalar profile's `true` rejects Float/Double, nested typed list/map/nominal DTO elements, enum/const/native/date/byte projections and value classes, even if projected Kotlin spelling looks like a permitted primitive. A single supported primitive + null fold is allowed; general composition is not. [Array components](#array-components), including the independent nullable-root profile, reuse this same eligibility policy.

The shared check sorts a copy of the supported non-null scalar values and compares adjacent entries; nullable lists count nulls separately. It neither mutates the caller's list nor uses hash sets, stringification, serialization equality or a quadratic pairwise scan. The declared algorithm uses O(n log n) comparisons and O(n) temporary storage, with no new input cap or broader runtime performance claim.

Count, primitive leaf and uniqueness checks coexist. Nullable containers and Patch Absent/Null skip checks, while Patch.Value, DTO constructor/copy/automatic deserialization, transparent dictionary-alias typed consumers, HTTP preflight (before callback/dispatch), success postdecode and SSE event constructors enforce them. Invalid known live SSE payloads end and close the input, preserving client reuse. Erased/discarded projections cannot silently lose `true`; validated `false` has no enforcing check to lose. Source provenance remains outside declaration identity. Unique-only chains obey the same 16 collection-edge guard at the original checked container, 48 schema-depth and 240 serialized-slot limits; nominal constructors are barriers.

Independent primitive/collection alias assignment and collection serializers, later caller mutation and arbitrary requestBuilder overrides remain unchecked transparency boundaries. [Ordinary DTO wire-property counts](#ordinary-dto-json-property-counts) and [direct JSON-value uniqueness](json-unique.md) are independently supported; wider typed/projected uniqueness, inherited/common object counts and broader constraint aggregation remain open, not full V05. JVM smoke evidence does not establish Android/KMP or other platform support.

## Ordinary DTO JSON property counts

With `--validation`, an **ordinary, non-inherited DTO with at least one constructor property**, direct or using the flat-inline profile below, supports `minProperties` / `maxProperties`. Fixed and mixed objects, components, existing nullable inline DTOs and nominal references share this serializer in nested fields, typed list/map values, HTTP bodies/responses and SSE JSON data. Nullable whole values use the existing nullable serializer; JSON null is not a one-member object. [Direct explicitly nullable component DTO roots](direct-nullable-component-counts.md) may retain their own local bounds; nullable allOf, borrowed and member-inferred component count roles remain excluded.

Bounds are nonnegative plain integer literals within Kotlin Int range. Malformed bounds and reversed intervals return `E_SCHEMA_INVALID` at the original keyword Pointer (reversed at `maxProperties`); unsupported contexts or disabled validation return `E_SCHEMA_UNSUPPORTED`. Even `minProperties: 0` explicitly opts into the JSON-only codec. Intervals are not inferred or rejected from Kotlin declaration size.

- **Incoming:** count the original parsed `JsonObject.size` before automatic defaults or unknown-key handling. Unknown keys and explicit null each count once. Missing const defaults do not retroactively increase this source count.

Input acceptance does not guarantee re-encoding acceptance after unknown keys are lost or defaults added; no repair or extras collection is performed.
- **API:** types, constructor/copy parameters, presence annotations, ordinary body-const override behavior and automatic descriptor stay unchanged. Constructors and `copy` are **not object wire-count barriers**. Existing primitive/element/container `init` checks keep their behavior. String and element JSON encode/decode APIs enforce counts; non-JSON codecs explicitly reject.
- **Ownership:** `KeepGeneratedSerializer`, scoped `ExperimentalSerializationApi` opt-in and a private collision-safe lazy wrapper retain the automatic delegate via `generatedSerializer()`, never `serializer()` self-delegation. Direct experimental delegate calls or caller serializer overrides are not promised barriers. No hidden Json configuration or per-consumer counter is added.

Admitted reference/nested-composition object members have an independent [whole-object count profile](referenced-allof-counts.md). Union variants, hierarchy/inherited/typed leaves, count-only/empty counted inline members, const-only models, empty JsonElement aliases, scalar/enum/native aliases and raw/stringified/discarded projections remain fail-closed. Transparent annotation-only references to an independently supported counted DTO keep its nominal codec. Unused components and excluded operations are still validated. Fixed-field additionalProperties approximation and uncollected extras remain unchanged; property counts do not enforce closed-object membership or extra-value schemas.

The wrapper uses fixed `SerializationException` messages without values for count, non-object and non-JSON failures. JSON AST materialization means streaming error locations are not preserved; parser and automatic-delegate errors are **not** claimed sanitized. No performance or frame-size bound is established. ## Exclusive bounds and multipleOf

The same primitive validator supports numeric exclusives and `multipleOf` for intrinsic primitive value classes, opt-in DTO fields, transparent primitive-ref consumers and primitive nested list/map leaves. Constructor/copy/automatic decoding, nullable/Patch.Value, typed HTTP preflight/postflight and SSE data checks retain these conditions. Existing types, constructor slots and wire spellings do not change; direct bounded HTTP scalar slots and raw caller overrides are not newly supported.

- **OpenAPI 3.0:** `exclusiveMinimum`/`exclusiveMaximum` must be Boolean. True requires the corresponding numeric `minimum`/`maximum` and makes its comparison strict; false is a validated no-op, even without a base bound. False alone emits no validator and imposes no finite-only restriction.
- **OpenAPI 3.1:** exclusives must be numeric, independent of inclusive bounds. All declared inclusive and exclusive conditions remain in generated checks, including when mapped Float values round to the same constant. Version-inappropriate representations fail at the original keyword Pointer.
- **Ordering and domains:** source bounds use exact bounded rational comparisons, the existing 256-character/512-exponent work limits and representable native scalar literals. Reversed/empty intersections and empty Int/Long domains fail at a relevant original bound Pointer; integer domains containing no admissible multiple also fail at `multipleOf`. Strict endpoints use direct comparisons, not overflowing native `bound + 1`/`bound - 1` arithmetic.
- **multipleOf:** the factor must be positive and representable, and remain nonzero after mapping. Int/Long checks use native remainder equal to typed zero, without `abs` (including `MIN_VALUE`). Float/Double require finite values and use **strict mapped-IEEE remainder equal to zero**, not exact decimal arithmetic or an implicit tolerance. For example, `0.5` satisfies `0.25`, but mapped `0.3` does not satisfy mapped `0.1`; applications requiring decimal multiples should not use this floating subset.

[Typed collection counts](#typed-collection-counts) are independent of numeric constraints. [Bounded scalar uniqueness](#bounded-scalar-uniqueness) is supported independently; general constraint composition/aggregation, defaults and enum/const/native/date/byte constraints remain unsupported. The 16-collection-edge check limit and raw-projection/no-discard safeguards also apply to these conditions. Constraint-only Int/Long minimum constants use unqualified arithmetic literal expressions, so a legitimate field named `kotlin` cannot shadow an expression package; ordinary scalar/const formatting is unchanged.

**Migration:** formerly rejected supported numeric keywords now generate checks under the applicable opt-in. Defaults and unconstrained output remain unchanged. Inclusive constraints keep their behavior; extreme minimum constraint source text may change only to an equivalent shadow-safe expression. Transparent alias assignment/independent serializers and mutable collection changes remain unchecked outside typed generator-owned consumers. Wrong types/versions, zero/negative/unrepresentable/underflowed factors and unsupported siblings fail closed; diagnostics and runtime messages do not include values.

## String pattern validation

String value-class components (`x-kotlin-value-class: true`) and direct String DTO fields with `--validation` can declare `pattern`, alone or alongside length bounds. Nullable/Patch presence is unchanged: non-null values are validated, Null/Absent are not Strings. Constructors, DTO `copy` and automatic JSON decoding run the same `init` check, including HTTP responses and known SSE payloads.

```json
{"Code":{"type":"string","x-kotlin-value-class":true,"pattern":"^[A-Z]{2}[0-9]+$"}}
```

The original pattern is safely escaped into a Kotlin String and matched with `toRegex().containsMatchIn(value)`. This is **substring search**, not whole-string `matches`: `cat|dog` accepts `hotdog`; add anchors to require a whole match. Patterns are not rewritten, matched in Go or converted into Go-regexp behavior. Fixed validation messages never interpolate the pattern or input value. No serialized fields or constructor slots are added.

The first-version portable grammar supports literal characters (including Unicode), dot/anchors, plain or non-capturing groups, alternation, character classes/ranges, standard `? * + {n} {n,m} {n,}` quantifiers and lazy suffixes, ASCII `\d/\D/\s/\S/\w/\W`, `\n/\r/\t`, and escaped regex metacharacters/backslash. Lookaround, backreferences, inline flags, named/atomic groups, possessive quantifiers, Unicode-property groups, quote blocks, hex/Unicode/octal escapes and word boundaries are explicitly unsupported. Malformed grammar or invalid slot types fail with `E_SCHEMA_INVALID`; unsupported features fail with `E_SCHEMA_UNSUPPORTED`, at the original `pattern` Pointer. Source patterns are limited to 1,024 UTF-8 bytes, 256 parsed syntax nodes and quantifier bounds of 1,000. These bound **generation work**; they do not promise timeout or linear-time matching for the target Kotlin Regex engine. Review schema-supplied patterns as code, particularly ambiguous quantified groups.

Numeric/enum/native/date/byte patterns and raw parameter projections remain outside this direct-slot increment. Direct inline collection-element patterns follow the separate [recursive element contract](#primitive-collection-element-validation). Supported String alias patterns follow the separate [typed-consumer propagation contract](#primitive-alias-validation). Default DTO behavior (without `--validation`) remains rejection. Existing uniform-union constraint approximation warnings do not become runtime checks. `x-kotlin-value-class: false` cannot silently discard a pattern.

[Original pattern fixture](../tests/fixtures/http/patterns.json), [Go grammar/source tests](../core/patterns_test.go), [CLI safety tests](../internal/cli/patterns_process_test.go) and [fresh Kotlin contracts](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/PatternContracts.kt) cover anchors/substring/Unicode/escaped literals, malformed/unsupported patterns, nullable/Patch, intrinsic serde, `kotlin` property name collisions, invalid HTTP/SSE payloads and caller-client recovery under four Json configurations. ## Dictionaries

Ordinary direct primitive dictionary DTO fields now have a separate [typed default contract](primitive-map-defaults.md), including optional initializers, required/Patch presence and opt-in count/value checks.

A direct object schema with explicit `additionalProperties` and no fixed properties generates an object-only dictionary:

- A typed value schema becomes `Map<String, T>`. Values use the ordinary property resolver, including scalars, component references, enums, lists, nested dictionaries and supported inline unions.
- `additionalProperties: true` or an unconstrained value schema (`{}`) becomes `JsonObject`, preserving arbitrary keys and JSON values, including JSON null. An empty object **without** `additionalProperties` retains its existing `JsonElement` approximation.
- Nullable values and nullable dictionaries are independent: `Map<String, Int?>` is different from `Map<String, Int>?`. Optional fields default to null; nullable shared-component fields keep the ordinary nullable default, not request-body presence semantics.
- Component dictionaries, including nullable roots, generate transparent typealiases. Use `serializer<Bag>()` or reified `encodeToString<Bag>` / `decodeFromString<Bag>`, not a generated `Bag.serializer()` member. No new runtime identity or overload distinction is introduced.

Inline value declarations use `<PropertyName>Value` in the containing model; list nesting appends `Inner` as usual. Component aliases cannot contain nested classes, so their value declarations are top-level peers named `<ComponentName><Suffix>Value` (for example `RecordsDtoValue`), in separate files. Primitive-union value wrappers retain their usual prefixes. All peers participate in global case-insensitive collision checks; no colliding name is silently renamed. Local references to dictionary components preserve the alias name.

Transparent alias cycles through dictionaries/lists/nullable references return `E_REF_CYCLE`; a real named object value can break the cycle and enable recursive DTOs. Schema nesting and alias expansion are bounded at 48 levels, including cached alias chains. A dictionary property occupies one JVM constructor slot regardless of its value type; 240 dictionary fields are compiled in the smoke suite.

**Fixed properties and restrictions:** a schema with fixed fields remains a DTO. Explicit additional keys are **not collected**, and `additionalProperties` does not configure `ignoreUnknownKeys` or enforce value/closed-object constraints at runtime. An empty object with `additionalProperties: false` is represented by `JsonObject`, not an enforced empty-object type. These approximations emit `W_ADDITIONAL_PROPERTIES_APPROXIMATION` at the original keyword pointer. Ignored extra-value schemas are still validated, so malformed or unsupported semantics cannot hide there. With `ignoreUnknownKeys=false`, unknown DTO keys fail decoding; with it enabled, they are discarded. Open dictionaries themselves retain their keys.

Pure dictionary `allOf` merging, dictionary union branches/common-value projections, direct root `$ref` aliases, HTTP request/response usage and Patch remain outside this increment. General constraints/defaults remain unsupported. Existing accepted output is unchanged; previously rejected direct dictionary inputs now generate models with the behavior above.

## Flat inline allOf primitive bounds

With `--validation`, an ordinary non-inherited model can conjoin bounds on a repeated **same wire property** in a flat object `allOf` whose members are inline objects. At least one overridden contribution must carry an actual primitive check. Each contribution must explicitly declare the same string/integer/number kind, identical format **presence and value**, and identical effective schema nullability, mapping to String/Int/Long/Float/Double. Existing direct nullable type spellings are allowed. Parent properties contribute last. Ordinary object metadata, required-name union, first insertion position and winning field/type/name/default/presence/Patch behavior stay unchanged.

```json
{"Record":{"allOf":[
  {"type":"object","required":["value"],"properties":{"value":
    {"type":"string","minLength":2,"pattern":"^[a-z]+$"}}},
  {"type":"object","properties":{"value":
    {"type":"string","maxLength":3,"pattern":"^[a-z]+$"}}}
]}}
```

`Record("ab")` passes; `"a"`, `"abcd"` and `"12"` fail. Every contribution first passes the existing version, literal, regex, resource and native-domain rules independently; an invalid earlier source cannot be rescued by a later winner.

- String lengths intersect using maximum minimum and minimum maximum; an empty interval fails at the source keyword closing it. No pattern, one pattern or repeated **identical parsed String** patterns are supported, emitted once. Different patterns are unsupported at the later pattern Pointer; regex satisfiability and Unicode normalization are not inferred.
- Numeric bounds retain four separate fixed categories: inclusive lower, strict lower, inclusive upper and strict upper. Within each category, choose the strongest exact source number, keeping the first equal contribution. OpenAPI 3.0 Boolean exclusives bind only their own source bound; 3.1 numeric exclusives remain independent. Both inclusive and strict checks survive Float/Double mapped rounding ties. Runtime checks still use finite mapped IEEE comparison/remainder, not exact rational instance validation or epsilon.
- Exact source-empty intersections, empty native Int/Long domains and integer domains without an admissible multiple are rejected using bounded rational/BigInt arithmetic. Numeric emptiness points to the restrictive upper source; strict 3.0 attribution uses its modifier. Absent/one/exact-source-rational-equal `multipleOf` factors are supported only after each source's literal, positive, finite and mapped-nonzero checks. Different factors are unsupported at the later factor; mapped equality is insufficient. No LCM is computed.

Only existing primitive-bound keywords plus ordinary type/format/nullable/metadata are eligible. Admitted object-member references and nested object compositions follow the independent [referenced/nested profile](referenced-allof-bounds.md). Property refs/wrappers/unions/collections, union variants, inherited/typed/common getters, enum/const/default/native/date/byte/value-class/custom-serializer aggregation remain outside both profiles. Signature-ineligible discarded checks, ignored extras and raw/stringification projections still fail closed. [Flat inline DTO JSON property counts](#flat-inline-allof-dto-property-counts) and their [referenced/nested extension](referenced-allof-counts.md) have a separate JSON codec contract; inherited/common counts remain unsupported. A nested ordinary model is independently eligible, including in otherwise supported HTTP request/response/SSE consumers; **inline HTTP root allOf bodies are not newly enabled**.

Constructor/copy/automatic serde enforce conjunction with fixed safe primitive messages and private non-inline typed helpers; there are no extra instance/serialized fields, regex caches, constructor slots or hidden Json. Nullable/Patch Absent/Null retain their behavior. Invalid typed construction precedes HTTP callbacks/dispatch; JSON-owned DTO counts keep their separate callback/codec policy. Bad known SSE data terminates and closes live input while preserving client reuse. Alias assignment, mutable containers and arbitrary requestBuilder overrides are not additional validation barriers.

**Migration and limits:** these opt-in schemas were previously rejected. Valid winning Kotlin signatures and wire values are unchanged; invalid constructed/decoded values now throw. Historical unbounded output is unchanged. `W_ALL_OF_APPROXIMATION` and last-property-wins outside this narrow bound conjunction remain: this is not exact object intersection or complete V06/M12. Composition work stays 16,384, global depth 48, checked collection edges 16 and serialized slots 240; native numeric tokens retain 256 characters / exponent magnitude 512, with no numeric-source-count limit. Fresh 120 non-null Long/Double and 240 boxed mixed String/Long/Double aggregate models compile at these boundaries; this boundary evidence is compilation-only, not a runtime/performance or Android/KMP guarantee.

## Object allOf composition

Object `allOf` merges are supported for components, nested fields and array items. Members contribute properties in order; a later member replaces the earlier schema without moving its first insertion position. The object's own properties apply last. Required names are combined and must exist in the final merged shape. Constructor properties and const body properties retain their respective emission rules; changing a const tag does not add it to the constructor or enforce const membership on decoding.

Local object references participate in merges, including multi-level extensions. Their nullable annotations are not inherited. For inline members, the parent's explicit nullable setting takes precedence over the first present inline setting. A field or array-item annotation-only wrapper containing one local reference preserves its named type or native scalar mapping instead of generating a duplicate inline class. Descriptive metadata payloads are not interpreted as schemas.

This is a generation approximation, **not exact intersection validation**. The warning-aware API/CLI reports `W_ALL_OF_APPROXIMATION` at the original `allOf` pointer for object merges. Errors in winning and overridden field schemas retain their original locations; an unsupported earlier field cannot be hidden by an override. Ordinary named-reference recursion remains supported, but cyclic object-merge expansion returns `E_REF_CYCLE`. The 48-level traversal guard includes expanded members and their fields; each object merge additionally permits at most 16,384 object-view/field-contribution steps, returning `E_SCHEMA_LIMIT` rather than expanding a repeated-reference DAG exponentially. Merged models retain the 240 serialized-slot limit.

Scalar or mixed-union `allOf`, union-root inheritance/mixed hierarchy contexts, nullable component roots, direct component reference aliases and annotation-only reference component roots remain diagnosed/deferred. In particular, a root reference-only wrapper does not silently become an empty class or an invented duplicate/alias. Required nullable component fields still use `T? = null`; this extension does not establish request Patch semantics or full union support.

[Go composition contracts](../core/model_contracts_test.go) and [generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/ObjectCompositionContracts.kt) cover merge/override order, required fields, const tags, source pointers, wrapper indirection, nested/list/suffix contexts, JSON configurations, numeric/constructor boundaries and bounded references. Existing accepted P1 snapshots are unchanged; the previously rejected empty-object `allOf` fixture now uses the documented `JsonElement` approximation with warnings.

This applies to fields and list items, including scalar, local component reference, enum, array and inline object types. ## Open string enums

A schema with a string type (or an omitted type) and a non-empty, unique string `enum` generates an open sealed class with a custom kotlinx.serialization serializer:

- each declared value has a named singleton and a `serialName` containing the exact wire string;
- `Unrecognized(serialName)` retains an unknown string and compares/hashes by that string;
- `Status.Serializer.fromSerialName` returns a known singleton or an unknown wrapper without a JSON instance; the companion lookup delegates to it;
- `entries` lazily caches known values in declaration order, so accessing a singleton before the companion cannot capture a partially initialized JVM instance;
- serialization writes a JSON string; decoding rejects numeric, boolean, null, array and object values when the declared type is non-null;
- nullable properties and nullable array items use the ordinary nullable serializer independently.

Components, local component references, inline object properties and array items share this rule. Component suffixes apply to declarations and references. Nested enums are scoped inside their owner; serializer descriptors include the full generated type path. JSON behavior is tested with all combinations of `encodeDefaults` and `explicitNulls`.

Use the declared base enum serializer when encoding a singleton, for example `json.encodeToString<Status>(Status.READY)`. No ordinary Kotlin `enum class`, ordinal serialization or polymorphic object discriminator is introduced.

### Input and naming limits

- Typeless enums retain unique String vocabularies. [Explicit nullable String null members](string-enum-null-members.md) use the nullable codec without stringifying null; other non-string/mixed members remain rejected. Native numeric/boolean components use [scalar projections](#scalar-value-projections); plain String vocabularies have the separate [intrinsic nullable component contract](#intrinsic-nullable-string-enums), while other nullable enum roots remain unsupported. Typed native inline enums have the separate mapping below.
- Empty enum arrays, duplicate wire strings or non-string entries are errors. An individual empty string is valid and is named `VALUE`; unknown runtime strings may contain arbitrary Unicode.
- Member names uppercase ASCII letters, retain digits/underscores, replace each other character with `_`, and prefix a digit-leading spelling with `_`: `in-progress` → `IN_PROGRESS`, `camelCase` → `CAMELCASE`, `1` → `_1`.
- A value with no ASCII letter/digit instead gets a punctuation name (`>=` → `GREATER_EQUAL`) or one `UXXXX` part per UTF-16 code unit (`🚀` → `UD83D_UDE80`). Kotlin/JVM-whitespace-only strings use `VALUE`.
- Case/normalization collisions and enum-owned nested names take `_VALUE`, then `_VALUE2`, etc. in wire declaration order: `high-priority`, `high priority`, `high_priority` → `HIGH_PRIORITY`, `HIGH_PRIORITY_VALUE`, `HIGH_PRIORITY_VALUE2`. `Serializer`, `Unrecognized` and `Companion` cannot be overwritten. A constant matching its enclosing type keeps its spelling; generated type references are fully qualified to avoid accidentally selecting the nested constant as its own supertype.
- Enum type names cannot collide with the generated `Companion`, `Serializer` or `Unrecognized` declarations.
- At most 240 members are supported per enum to bound JVM lookup/initializer size. Larger inputs return `E_ENUM_LIMIT`; the last supported size is compiled and exercised in the Kotlin smoke.
- Unsupported defaults, constraints and semantic extensions still produce diagnostics rather than disappearing from the generated enum.

### Compatibility impact

Explicit string enums generate models. Constants use the wire-sanitized uppercase spelling rather than PascalCase; migrate calls such as `Status.Ready` to `Status.READY`. Known punctuation/empty strings and colliding spellings are supported with the names above. `Serializer.fromSerialName`, companion lookup and `entries` share one lookup table. Existing accepted P1 inputs keep their generated declarations and presence behavior. Native numeric/boolean inline enums are not converted to strings. Their component-root path uses [native scalar projection](#scalar-value-projections), not this open string-enum API. This extension does not establish union, discriminator, request Patch, Android or KMP support.

## Typed discriminator hierarchies

Component unions with an explicit string discriminator and local referenced object/union children generate a **top-level inheritance graph**, with one file per schema node. Hierarchy-owned components are not also generated as standalone unions. Local JSON Pointer escapes and bare local component mapping targets share validated catalog identities; external/missing references, graph cycles and ambiguous multiple-parent/repeated-node ownership are diagnosed, not silently filtered. Ordinary object `allOf` leaves retain borrowed source fields and required/override validation; `allOf` containing union roots is not invented as an inheritance alias.

Each custom level analyzes descendant discriminator fields. Multiple values create a peer open string enum named from the node and field; intermediate abstract overrides and leaf body defaults retain ancestor enum types. Const fields and unpinned **direct-parent** string fields use always-encoded typed enum body defaults (the latter get the selected mapping value). A hierarchy enum field, including a single-member or optional/nullable schema enum, instead remains a **required non-null enum constructor parameter without a default**. Other leaf fields keep their ordinary nullable/default rules. Constructor-empty const-only leaves are consuming fixed-wire singletons; ordinary P1 const-only models remain plain classes. Typed enum body fields occupy one serialized JVM slot.

Explicit dispatch selects the first mapping entry targeting each child, otherwise the original component key lowercased; **model suffixes do not change these hierarchy fallback wire values**. Child field enum values add unclaimed dispatch values afterward. Extra mapping aliases to the same child are not independent routes unless also declared in its field enum. Const values different from mapping keys are not automatically extra explicit routes. There is no exclusive-key presence fallback in this hierarchy path. These rules are generation mappings, not exact schema matching or membership validation.

An intermediate union without an explicit discriminator promotes common varying pinned string fields, using **const-first then enum** dispatch. A single field retains the original codec; [several promoted fields](hierarchy-dispatch.md) use OR within each enum set and AND across fields, with source order and first identical claim. A value shared by a const leaf and an enum leaf selects the const leaf. Without a promoted field, the intermediate uses ordinary sealed polymorphism and class-level leaf serial names instead; it has **no Unknown**. Encoding through that intermediate adds JSON's class discriminator. Encoding through a content-dispatched ancestor delegates directly to the leaf and does not add the intermediate's discriminator, so that ancestor-produced payload may not decode back through a default-polymorphic intermediate. Use the intermediate serializer when its class discriminator is required; no blanket hierarchy round-trip guarantee is made.

Every custom level has its own raw-preserving Unknown serializer. Ancestor and own abstract discriminator properties return typed `Unrecognized("")` stand-ins, not values parsed from the raw payload. Unknowns below multiple intermediate layers implement all inherited abstract properties. Encoding an inner Unknown through an ancestor preserves the complete raw JSON without reinserting discriminator fields. Active dispatch requires JSON objects and primitive tags; unrecognized/missing/null tags select the appropriate layer's Unknown, while recognized invalid mapped fields fail rather than trying another class.

The verified foundation covers explicit, inferred and default-polymorphic levels, four-level typed ancestors/Unknowns, ordinary-base allOf leaves, refs/lists, suffixes and known/unknown wire behavior in all JSON default/null configurations. [Synthetic input](../tests/fixtures/model-semantics/hierarchy-unions.json), [Go hierarchy checks](../core/hierarchy_contracts_test.go) and [actual generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/HierarchyContracts.kt) also cover cached graph depth, malformed mapping, symbol collisions and typed body constructor boundaries. No accepted P1 golden changed.

[Fixed and inherited discriminator fields](hierarchy-fields.md) add single-child fixed explicit levels, generated typed bodies for missing ancestor fields and varying ancestor enum values. Original enum constructor requiredness, const/mapping routes and per-layer Unknown policies remain intact; generated fields count toward the serialized slot limit and do not satisfy missing source required declarations. [Compound and reused tags](hierarchy-dispatch.md) additionally support several inferred finite fields and explicit levels reusing an ancestor tag's canonical enum type and one override. Each reused level retains its own mapping routes and missing fields use the nearest matching edge. Multi-child identical fixed pins, default-polymorphic fixed-singleton leaf contexts, inline/primitive/nullable graph members, multiple parents and hierarchy intersections remain diagnosed pending separate contracts. Object-only union/allOf combinations have their [own contract](union-allof.md); accepted parent/leaf bindings use the separate [root hierarchy alias contract](#root-hierarchy-aliases). Limits are 48 graph levels, 240 branches per union, 240 enum values/serialized model slots and 16,384 graph visits; cached subtrees still contribute their depth. This is not complete M10, general union support or request Patch support.

## Standalone root object unions

A component-root object `oneOf`/`anyOf` without an explicit discriminator reuses the source-aware object planner, but has a **distinct root policy**. Referenced variants are nested under the union using the referenced component's validated Kotlin name (including the suffix); inline variants derive names from their first pinned value. Ordinary fields and list items referencing the root use its named type rather than expanding its graph. Required-key, constructor-size, branch-count, cycle/source-pointer and owner/global-peer collision guards still apply.

A root uses content dispatch when it has a common `type` field, a varying inferred tag, or an exclusive required-key presence branch. It then generates Unknown raw passthrough, with tag values read from the chosen tag field. If this tag path includes an unpinned referenced variant, the generated variant name supplies the implicit value. Consequently **a model suffix changes that implicit wire value**, as well as the Kotlin name; use explicit pinned values when wire tags must remain suffix-independent. Untagged refs do not invent tag values merely because they have component names.

Otherwise the root uses ordinary kotlinx sealed polymorphism: nested subtypes have class-level `@SerialName` and JSON's class discriminator identifies them (default key `type`). This path generates **no Unknown variant or content dispatcher**. Known values acquire a class discriminator on encoding; missing/unrecognized class discriminators fail rather than preserving arbitrary raw payloads. `W_UNION_UNREACHABLE_VARIANT` then means no field-tag/presence route exists, not that normal polymorphic decoding cannot select the subtype. `W_OBJECT_UNION_APPROXIMATION` documents this non-schema-match mapping. Duplicate subtype serial names and default-polymorphic const-only custom-singleton contexts remain diagnosed; no ambiguous subtype is silently dropped.

An ordinary direct local `$ref` field may now own a [closed subtype union default](closed-union-defaults.md): its annotation uses Json.Default's String `type` discriminator and an actual emitted SerialName, validates the selected original plain constructor variant and preserves the named type. Resulting typed values honor caller custom discriminators and array polymorphism. Required/Patch/discarded annotations validate before suppression; target/chain/root/component default inheritance, directly serialized business `type` collisions and wider default roles remain separate.

Unlike inline unions, a root's common single-string enum remains a constructor string, with each variant's own nullable/default rule. It is not an always-encoded body singleton. Const defaults remain body fields; content-dispatched const-only root variants still use fixed-field singletons. Common nullable widening, JSON configurations and Unknown stand-ins retain their independently tested object contracts.

[Typed discriminator roots](#typed-discriminator-hierarchies) enter a separate hierarchy policy. General fixed/missing-field/mixed hierarchy contexts and complex common-map/union contexts remain deferred; direct root bindings have the separate [root union alias contract](#root-union-aliases). Primitive/mixed and nullable/null-branch roots have the separate [root-kind contract](#root-json-kind-and-nullable-unions). Root support does not imply multilevel hierarchy or request Patch support. [Original root fixtures](../tests/fixtures/model-semantics/root-unions.json), [Go root-union regressions](../core/object_union_contracts_test.go) and [actual generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/RootUnionContracts.kt) verify content versus ordinary polymorphism, all JSON configurations, enum constructors, escaped refs and implicit/suffix tags, known/unknown wire behavior, named root refs/lists/recursive DTO references, const singletons, errors and deterministic limits. Existing accepted P1 goldens are unchanged.

## Inline object unions

Field and array-item object `oneOf`/`anyOf` generate a sealed base with **nested** variants (`Envelope.Event.Note`), plus sibling `UnknownEvent` and internal serializers. Primitive-kind wrappers remain siblings under their owner instead. Local object refs and supported object allOf views supply the variant's shape without copying an expanded JSON tree. [Standalone component roots](#standalone-root-object-unions) and [typed discriminator hierarchies](#typed-discriminator-hierarchies) have separate policies; general fixed/mixed hierarchy contexts remain deferred.

The planner searches common fields, then other declared fields, prioritizing string pins over numeric/boolean pins and unpinned fields. Varying const/enum sets identify a tag; `type` has precedence among common candidates. Every declared enum tag value can select the variant, while duplicate values are claimed by the first variant. A still-unselected variant may use a required key that no other variant declares or requires (at least two variants are needed). This permits mixed tag and presence dispatch, including partially reachable unions; optional or merely more-specific keys do not qualify. `W_UNION_UNREACHABLE_VARIANT` points to each original unselected branch, and `W_OBJECT_UNION_APPROXIMATION` to the original composition: dispatch is not exact oneOf match-count validation.

Common scalar, underlying string-enum, primitive-list and unconstrained JSON types become abstract members. Common nullable types widen when any variant allows null/omission, but constructor defaults retain each variant's own nullable/optional rule. A required non-null field widened by another variant becomes `T?` **without a default**; `explicitNulls=false` may nevertheless decode an omitted key as null. Common enum properties use the underlying native type, not a new shared enum. In this inline context a common single-string enum becomes an always-encoded body default, including a referenced enum; multi-value common string enums remain constructor strings. Non-common enums retain ordinary open-enum behavior. Complex common object/map, union or reference-wrapper types and native single-enum body defaults remain diagnosed rather than inventing incompatible shared types.

Const-only variants are data-object singletons with a custom JSON serializer that always emits their fixed fields. Their decoder consumes a JSON value and returns the singleton: extra fields and alternative const values are not retained. A genuinely empty variant is also a data object. Regular variants retain data-class constructors and ordinary always-encoded const body fields, whose mapped scalar values may be replaced on decoding. Ordinary non-union const-only models remain plain classes. Variant names derive from the first pin, retaining the discriminator-specific punctuation convention (`dice.check` → `Dicecheck`), prefixing digits with `V`, and using declaration-position suffixes against case-insensitive owner/Companion collisions. A const-only variant named `Serializer` is diagnosed because it conflicts with its singleton serializer; it is not silently renamed.

Unknown variants capture `rawElement: JsonElement` and encode it verbatim with a passthrough serializer: there is no `rawElement` wrapper key on the wire. Abstract stand-ins use null, empty strings/lists, false or correctly typed numeric zero; an unavailable JSON/generated-class property uses a throwing getter. These stand-ins are not extracted from the raw payload and do not affect encoding. With no usable tag/key the dispatcher returns Unknown directly, permitting any JSON value. Tag/key dispatch expects a JSON object, and a tag read expects a primitive value; wrong outer/tag kinds fail rather than becoming Unknown. A recognized branch with invalid mapped fields also fails instead of falling back. Future root/hierarchy Unknown behavior is not implied by this inline contract.

Union traversal uses the existing 48-level and 240-non-null-branch bounds, local-reference checks, object-view expansion budget and serialized-constructor slot limits. Required-key ordering is retained through borrowed object/allOf views; generated files remain deterministic. [Synthetic inputs](../tests/fixtures/model-semantics/object-unions.json), [Go object-union regressions](../core/object_union_contracts_test.go) and [actual generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/ObjectUnionContracts.kt) verify mixed/no-key/duplicate dispatch, common defaults, const singletons, native/JSON/nullable/ref/list stand-ins, raw preservation, nested/item/suffix names and constructor boundaries under every JSON configuration. Existing accepted P1 goldens are unchanged.

## Primitive-union normalization

Nested fields and array items share a source-aware normalization decision, separate from named component-root generation:

- A string vocabulary plus at least one typed free-string branch folds to the existing **open enum**, not a bare String. Known branches may omit `type`; their unique string values are validated before first-seen cross-branch deduplication. Formats must agree, and const branches prevent the fold. The resulting enum preserves singleton/lookup/Unrecognized/value-equality semantics. Plain null branches apply nullable wrapping afterwards. Closed same-kind enums, same-kind const unions, format disagreements and reference-plus-free-string ambiguity remain diagnosed.
- Plain same-kind/same-format primitive unions fold to the native scalar. Explicit int32/int64/float/double mappings are retained; an unformatted integer widens to Long when a branch bound exceeds Int range. Only string `pattern`/`minLength`/`maxLength` and numeric `minimum`/`maximum` can be approximated in this **uniform nested-fold context**. Consumed slots must have valid types and consistent bounds. Each discarded constraint emits `W_UNION_CONSTRAINT_APPROXIMATION` at its original keyword pointer; no runtime validation or exact oneOf matching is added. Free-string constraints in an open-enum fold follow the same rule; enum-bearing branches still require the ordinary supported enum schema. Other constraints/defaults/unknown keywords, ordinary scalar constraints and root uniform folds remain diagnosed. Patterns are not compiled using Go regexp.
- Distinct native-kind enum/const branches, including local component refs, validate original literals and format before retaining String/Boolean/Long/Double **payload wrappers**. `W_PRIMITIVE_UNION_PIN_APPROXIMATION` points to each original pin; decoding does not enforce enum/const membership. These value wrappers are not const-body defaults or fixed-output singleton objects. Root distinct-kind pins retain the named root/null policy; they never become nested enum aliases.

`W_PRIMITIVE_UNION_APPROXIMATION` retains the composition pointer. Emitted/merged string vocabularies remain bounded at 240; branch/depth/model-slot/name guards are unchanged. Validation and diagnostics retain original source locations without expanding reference trees, and examples remain opaque data.

**Migration:** newly supported inputs were previously rejected, so accepted P1 goldens remain unchanged. Open-enum folds expose known singleton APIs while preserving arbitrary string wire values. Primitive pins intentionally retain native payload values, including values outside their declared membership; callers must not expect body-default constant behavior or quoted enum tokens. Unformatted folded range inference can require Long call-site values and two JVM slots rather than Int; no constraints are silently promised as enforced.

[Original input](../tests/fixtures/model-semantics/union-normalization.json), [Go normalization regressions](../core/primitive_union_contracts_test.go) and [actual generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/UnionNormalizationContracts.kt) cover nested/nullable/list/suffix, merged vocabulary, source pin/constraint diagnostics, native extrema/outside-pin values/strict wrong kinds/no envelopes, all Json default/null configurations and real 120-Long folded/240-member merged-enum compilation. This does not establish dictionaries, complex common types, remaining discriminator graphs, complete F09 or request Patch support.

## Root JSON-kind and nullable unions

Component `oneOf`/`anyOf` roots with distinct string/integer/number/boolean kinds retain an independent named sealed declaration. They reuse the inline primitive planner's native payload wrappers, optional single structured object and dispatch order: object, quoted string, then boolean → Long → Double. For `Choice`, siblings include `StringChoice`, `IntChoice`, `NumberChoice`, `BooleanChoice` and, when applicable, `ObjectChoice`. Named refs/list items retain the root's fully qualified identity and suffix; roots never silently fold into an inline scalar alias. Same-kind duplicate primitive roots and multiple-object primitive mixtures remain diagnosed; distinct-kind primitive enum/const pins use the separate [validated projection contract](#primitive-union-normalization).

A plain null branch or root `nullable: true` adds a sibling `NullChoice` singleton, serialized as JSON `null`, not `{}` or a nullable typealias. Its serializer consumes and requires a literal null. A required root-typed property can therefore contain `NullChoice` while remaining non-null in Kotlin; optional/ref/item nullable annotations are independent Kotlin nullability. The serializer's null payload remains present even with `explicitNulls = false` on a **non-null root-typed field**. This does not change request-body explicit-null guarantees for genuinely nullable Kotlin properties.

Nullable object roots have separate backends:

- Content/tag/key roots dispatch null before the non-null object plan. They retain raw Unknown and recognized-invalid-field failures. Common getters on Null use the same null/empty/false/zero stand-ins as Unknown, not payload extraction.
- Default-polymorphic roots wrap a closed non-null sealed serializer, preserving its class discriminator, `SerialName`, configured discriminator key and array-polymorphism setting. Null has no envelope. Unknown class tags and malformed non-null payloads fail; there is **no Unknown subclass**. The wrapper's subtype inventory excludes Null and honors the caller's Json configuration.

Root branches are bounded at 240, counting the generated null variant once; repeated plain null `oneOf` branches collapse to one null variant with `W_ONEOF_NULL_OVERLAP`, not exact match-count validation. Branch models retain source-aware depth (48), serialized slots (240), ref and metadata checks. Scalar wrappers reuse `W_PRIMITIVE_UNION_APPROXIMATION`; object roots retain `W_OBJECT_UNION_APPROXIMATION`, with original composition pointers. Descriptive text slots must be strings and `deprecated` a boolean; examples remain opaque data, never schema-scanned. Global peer/serializer collisions are rejected; closed polymorphic roots do not reserve an unused Unknown name.

**Migration:** these roots were previously rejected here; existing accepted output is unchanged. Migrating from primitive branches rendered as property-empty object variants requires constructing the native value wrappers and sending native JSON scalars, not empty objects or class envelopes. Null is an explicit singleton/native null payload, not an object-like variant. Deriving common getters from non-null branches is additive for nullable object roots. These are deliberate payload-preserving semantics, not a guarantee of compatibility with an empty-object API/wire representation.

Nullable scalar/enum/object component roots outside this union entry, explicit nullable discriminator graphs, remaining alias/constraint profiles and common dictionary/union contexts stay diagnosed or deferred; non-discriminator union bindings have the separate [root alias contract](#root-union-aliases). This is not full union, hierarchy or Patch support.

## Inline primitive unions

A field or array-item `oneOf`/`anyOf` of distinct string, integer, number and boolean kinds generates a sealed base and **sibling** data-class wrappers in its owner scope. For `Value`, call sites use `StringValue(value)`, `IntValue(value: Long)`, `NumberValue(value: Double)` and `BooleanValue(value)`, not nested `Value.Int` variants. Integer/number wrappers deliberately use Long/Double even for int32/float branches. One non-empty structured object may join the union as `ObjectValue`, with its own generated fields, nested declarations and const body defaults; a referenced object supplies that wrapper's shape rather than becoming its superclass.

The JSON serializer encodes the native payload directly, without a polymorphic envelope. Decoding tests object and quoted string first, then unquoted boolean, Long and Double, independently of schema branch order. With both integer and number variants, an integer-shaped literal selects the Long wrapper; a fractional or out-of-Long-range literal can select Double. Quoted `"true"`/`"1"` stay string values and never enter numeric/boolean dispatch. No matching kind throws `SerializationException`; this path has no Unknown fallback. Nullable unions use explicit plain null branches or parent nullable; nullable list items remain separate from a nullable list.

Same-kind plain scalar branches with identical formats fold to the native scalar rather than generating duplicate wrapper names. `W_PRIMITIVE_UNION_APPROXIMATION` retains the original composition pointer for both folding and kind dispatch: this is not exact `oneOf` match-count/intersection validation, and the Long/Double wrapper mappings may be wider than the declared formats. Distinct-kind enum/const pins and supported uniform-fold constraint approximation use [shared normalization](#primitive-union-normalization). Other validation constraints, unsupported formats, conflicting same-kind formats, member-level nullable annotations, unconstrained object branches, primitive mixtures containing multiple structured objects, and composition parents carrying a sibling type remain diagnosed. Object-only branches have a separate [inline object union](#inline-object-unions) path. Null enum members remain deferred; primitive union component roots use the separate [root-kind contract](#root-json-kind-and-nullable-unions); [standalone object roots](#standalone-root-object-unions) do not share this inline primitive dispatch path.

All wrapper and serializer names are reserved together against owner/nested collisions. Traversal and reference expansion share the 48-level guard; there may be at most 240 non-null branches (`E_UNION_LIMIT`), without reducing the existing single-branch-plus-null folding support. A union-typed constructor field costs one reference slot; its Long/Double wrapper's own constructor uses its native width. [Go primitive-union contracts](../core/primitive_union_contracts_test.go) and [generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/PrimitiveUnionContracts.kt) cover pointers, bounds, all 11 multi-kind primitive combinations, branch order, native wire round-trips, rejected kinds, object/const/ref/list/nested/suffix scopes and JSON configurations. Existing accepted P1 snapshots are unchanged; the previous string/integer oneOf rejection now has a reviewed full-source snapshot.

## Native inline enums

Typed integer, number and boolean `enum` fields and array items use their ordinary Kotlin scalar type, including formats and nullable boxing. This also applies in nested objects and the supported nullable composition fold. They do **not** generate enum classes, constructor defaults, constants or membership checks. `W_ENUM_NATIVE_APPROXIMATION` is reported at the original enum pointer: values outside the declared member list decode and re-encode when representable by the native type. Numeric/boolean wire values remain numeric/boolean, unlike string enum values such as `"1"` and `"true"`.

Enum arrays must be non-empty and literal entries must be unique and representable by the mapped scalar. Integer members require integer JSON literals within Int/Long range; Float members must remain finite after mapping, with ordinary IEEE precision. Null/mixed/object/array members, defaults and semantic constraints are diagnosed at their original locations. Nullable type arrays or `nullable: true` describe nullability separately; a null **enum member** is not supported by this increment. Metadata/example payloads are not inspected for enums. These checks establish the generator's supported subset, not complete JSON Schema validation.

Numeric/boolean component roots and references now use [scalar projections](#scalar-value-projections) to retain native inline wire types while declaring transparent aliases, not open string-token enum classes. Typeless string components/references use the same open enum serializer as typed string components. Native enums retain the ordinary 240 serialized-slot model budget: required Long/Double fields cost two slots, nullable/optional fields one. [Go enum-context contracts](../core/model_contracts_test.go) and [generated Kotlin contracts](../samples/kotlin-smoke/src/main/kotlin/org/example/contracts/EnumContextContracts.kt) cover scopes/suffixes, pointer/shape/range failures, all JSON configurations, values outside membership, typeless 240-member enums and 120-Long native-enum models.
