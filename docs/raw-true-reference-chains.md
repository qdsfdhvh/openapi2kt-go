# Named raw and literal-true reference chains

Finite typed internal `$ref` chains and component-root bridges may terminate at an original named raw empty ordinary object or OpenAPI 3.1 literal `true` component, including their accepted pure named aliases. The new chain exposes transparent `kotlinx.serialization.json.JsonElement` backing, with `?` determined by the nearest explicit true/false along the actual consumer-to-terminal path. Existing direct raw/true declarations and alias spelling remain compatible. This is a bounded F04/F07/M02 extension.

Raw permission requires the unique retained original ordinary Model with no constructor properties and no constants. An empty `allOf` root can qualify after its original grammar and actual Model have been planned. Const-only, nonempty, hierarchy, union and dictionary declarations do not gain raw permission because their own visible fields happen to be empty. Literal `true` instead requires its original JSON ValueAlias. The original catalog, schema node, Pointer, source bytes and actual declaration identity remain distinct from aliases and uses; replacing or repeating the declaration, copying a same-byte source node or changing nullable/codec backing rejects the binding. A Kotlin classifier spelling alone grants no source permission.

Every internal and named hop remains source work through caches and explicit false narrowing. Transparent aliases create no nominal recursion barrier. Depth 48, expansion work 16,384, checked collection edges 16 and constructor/method slots 240 keep their existing limits; both nullable and non-null JSON references consume one slot. Borrowed raw/literal-true internal leaf targets, recursive-cover chains and shape expansion have separate policies. Recursive covers retain their original graph/SCC budget; this extension does not authorize them through a raw/true source role.

The original raw root owns `W_JSON_ELEMENT_APPROXIMATION`; literal true owns `W_BOOLEAN_SCHEMA_PROJECTION`. New alias/hop users do not duplicate those warnings. Empty `allOf` retains its existing composition warning too. Warning denial runs before output IO and preserves previous generated files and unowned files. Original terminal constraints/defaults/required grammar and ref siblings are validated rather than discarded; raw projection does not provide an object-kind or property-count validator.

JSON values include null, strings, numbers, booleans, arrays and objects. A non-null JsonElement serializer retains the JsonNull value; a nullable serializer collapses JSON null to Kotlin null. No generated alias constructor or companion codec is introduced: use reified `serializer<Alias>()` or JsonElement's nullable adapter. Shared optional/default-null, request-required nullable and optional Patch presence remain context-specific. `Patch.Value(JsonNull)` writes null and decodes as `Patch.Null`; it does not retain a fourth presence state. Typed raw dictionary values retain the existing JsonObject approximation, including JsonNull values. Object-union common-field nullability keeps the existing union policy.

HTTP JSON body/response roots preserve the backing JsonElement codec and nullable collapse. Nullable/non-null aliases share erased method identity and existing numeric suffix allocation. Structured query values still use Ktor `toString` projection and its warning, without a new recursive encoder. SSE data uses the configured Json codec; malformed fragmented JSON fails, closes the still-open stream, and leaves subsequent cold collection/client reuse available. Non-null JSON data can carry JsonNull. Reconnect policy remains outside this contract.
