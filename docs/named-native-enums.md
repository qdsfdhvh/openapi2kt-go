# Named native enum sources in borrowed graphs

With `--validation`, supported internal reference chains and borrowed finite List/Map trees can terminate at an actual plain numeric/Boolean enum component or its finite named aliases. For example an internal `Source.properties.hop` referring to `CodeAlias` → `Code`, where `Code` has enum `[1,2,3,4]`, minimum 2 and integer factor 2, retains the same membership and numeric checks through a root bridge or borrowed collection.

This extends [typed native enum consumers](native-enum-consumers.md), [numeric enum bounds](native-enum-bounds.md), and [internal native enum Pointers](internal-native-enums.md). Direct named enum references were already supported in typed consumers; this profile admits the source through the internal/borrowed graph seam. Public Kotlin types remain scalars/typealiases and wire encoding remains unchanged. Independent alias assignment/serialization alone has no checking barrier. Actual DTO constructors/decoders, HTTP input/result consumers and SSE data construction check their linked scalar values.

## Source and declaration authority

The graph retains its actual named catalog source, original schema, vocabulary array/member nodes, mapped validation object and scalar export. Final validation requires the original `ScalarAlias` occurrence exactly once. The separate [nullable root profile](nullable-native-enums.md) requires the actual nullable `ValueAlias` and its original check object. A missing/repeated export, same-name replacement declaration, substituted source/member node or changed cached check plan cannot authorize the binding. Lexical internal entry owners remain separate from the canonical named terminal. No fabricated component or copied expanded schema is created.

Forward borrowed containers share existing catalog DFS dependency traversal for admitted named sources. Internal and named alias hops accumulate against the existing 48 source depth; cached lookup and nullable narrowing do not reset them. Checked container traversal still allows 16 edges, raw vocabulary 240 members and serialized/operation construction 240 slots. Required Long consumes two slots. Existing expansion-work and precision/exponent limits remain.

An explicit nullable annotation on the internal hop/root bridge follows the existing nearest-override path; `nullable:false` narrows the consumer and preserves checks/source work. [Nullable native enum roots](nullable-native-enums.md) separately admit intrinsic nullable components and own-nullable/false aliases under validation. Native overrides, value-class/const annotations, String/null-only vocabularies and general enum composition/intersections remain separate; [explicit nullable native null members](native-enum-null-members.md) have their own validation-only contract. Original malformed vocabulary/bounds diagnostics retain their source Pointers. Defaults remain direct DTO annotations only.

## Compatibility and checks

Default-off generation retains its old unsupported policy at this graph seam. Already supported checked/direct inputs retain output. Newly admitted internal/borrowed named source inputs were previously rejected; invalid mapped values fail the opted-in typed checks. Numeric constraints follow the [numeric enum bounds profile](native-enum-bounds.md), including the floating `multipleOf` exclusion. String enum nominal owner behavior remains unchanged.

Raw/stringification projections, discarded allOf fields and ignored additionalProperties still reject enforcing checks that would disappear. Vocabulary and bounds participate in dedup/merge and name-lock identity; changing canonical checks cannot replay an old checked shape. Persisted format versions are unchanged.
