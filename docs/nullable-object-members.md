# Nullable ordinary object-union members

An ordinary inline object member of `oneOf` / `anyOf` may declare `nullable: true` or `type: ["object", "null"]`. The union retains that original member's fields, constructor, codec and source node. Its null intent contributes to the surrounding union's nullable view without making each physical variant nullable.

Named root unions retain the existing non-null sealed classifier and Null singleton. Inline unions use a nullable Kotlin view over their actual nested classifier. Aliases, explicit false, Unknown, required/shared/request presence and Patch follow the existing [union reference contract](union-nominal-owners.md). Member-derived nullability is distinct from a literal null-only branch: it does not trigger the single-branch-plus-null folding rule.

Multiple nullable object members, or a nullable member plus a literal null branch, retain the original `W_ONEOF_NULL_OVERLAP` warning for `oneOf`. This warns that generated dispatch does not validate exact match counts. Tag/key dispatch order and raw Unknown payload preservation remain unchanged.

Every original member is validated, including required names, source keywords, discarded fields and constructor checks. Root Null singletons count toward the existing 240-branch limit; physical serialized fields retain their existing slot limits. Source depth 48, work 16,384 and checked collection edges 16 remain unchanged. Nullable primitive members, nullable allOf intersections, arbitrary nullable reference borrowing and general JSON Schema validation remain separate contracts.

This accepts previously rejected direct ordinary nullable object members. Existing unrelated accepted inputs retain their APIs and wire behavior.
