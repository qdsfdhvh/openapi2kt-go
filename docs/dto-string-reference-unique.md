# DTO String enum reference getter uniqueness

Under validation, ordinary DTO uniqueItems accepts fields referencing already
supported plain unformatted String enum sources. Existing named/internal finite
chains and root bridges retain their actual lexical classifier, nearest
nullable intent and source-role admission. Getter keys compare actual serialName:
a known member and same-name Unrecognized are equal; unknown runtime strings
remain open. JSON null and String "null" remain distinct.

Consuming own-default fields resolve the original target without constructing
a default-free copy. Annotations remain strict against the original vocabulary,
including required fields before initializer suppression. Omitted optional
fields use their actual final constructor initializer. Explicit equal values
are duplicates at the second outer default value Pointer. Component factory
annotations are not inherited; existing target/hop default restrictions,
constructor/copy/Patch and codec/wire contracts remain.

Internal enums can have a deferred physical name during preflight. A private
abstract serialName signature therefore defers that name check to the final
original-enum barrier. It does not infer enum permission from a Named spelling.
The final plan must retain exactly one original enum and one occurrence of its
schema origin, with the actual current physical name, original planner object,
schema/Pointer and unchanged vocabulary/member names/wires. Missing, repeated,
renamed, copied or foreign enum declarations reject. Original intermediate
alias objects and their finalized physical target types are recorded before
the first barrier; a changed alias target cannot hide behind an abstract key.

The scalar reference proof also keeps raw reference-chain trees, original
physical input paths, member/item identities, catalog/binding/nullable/height
states, actual getter types and initializer/null policies. Capture work/bytes
share16,384/8MiB; reference/path entries are charged and original snapshots are
memoized. Source48, default-key16,384work, annotation16,384nodes/32KiB,
member240/checked16/JVMslots240, deterministic identity and ownership/name-lock
formats retain their rules. No schema/type/enum/serializer is invented.

Formatted/bounded String enum references and other unadmitted const/collection/
nominal/raw/native-override/value-class getter roles remain separate. Existing
open enum runtime behavior and other getter-family contracts are unchanged.

`bash scripts/test.sh feature dto-string-reference-unique` freshly generates
Data/Plain baseline/validation and combined optimized/locked output. Four Json
settings exercise actual RefStateDto/BorrowOwnerDto.Mode classifiers,
named/internal/escaped bridge chains, own defaults, required/nullable fields,
known/Unrecognized equality, distinct unknown strings, inline DTOs, existing
getter families, Patch, duplicate HTTP responses and fragmented SSE closure/
client reuse. The baseline retains prior primitive references where native
reference permissions require validation. An independent input compiles240
String enum reference getters with240 referring arrays. Core/source tests check
strict defaults, actual enum/alias identity and physical type mutations,
original nodes/paths and exact capture budgets/reuse. Native CLI failures
preserve old output; bounded fuzz covers aliases, options, determinism and
omitted/explicit initializer keys. Wider graph/platform/final candidate gates
remain separate.
