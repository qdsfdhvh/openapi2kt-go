# Nullable allOf product unions

Supported object unions inside `allOf` may carry explicit nullable intent at the product root. `nullable: true` and `type: ["object", "null"]` preserve the same original object alternatives, fields and Cartesian dispatch as the [object composition contract](union-allof.md).

A standalone named product follows the existing root-union policy: it keeps a non-null sealed classifier with a `Null<Name>` singleton. Its direct serializer decodes JSON null to that singleton. Transparent root aliases without an explicit nullable override keep that carrier; a nullable alias uses Kotlin's nullable adapter, which decodes JSON null as Kotlin null. An explicit false alias restores the non-null carrier, including its Null singleton. This is the same carrier-versus-nullable-view distinction as [retained union references](union-nominal-owners.md).

An inline product uses a nullable Kotlin view over its actual non-null nested classifier. Its physical variants retain their original constructors and non-null codecs. Internal/root references to that retained nested product inherit nullable intent; explicit false narrows to its physical classifier. Shared nullable defaults, request required-nullable and Patch remain controlled by the existing usage context.

Root null intent never rewrites original schema nodes or makes all product variants nullable. Original source fields, discarded members, validation, aliases, actual unique declarations and cached source heights remain checked. Nullability on intersection members, nullable borrowed shapes, primitive/dictionary intersections, discriminator intersections and general JSON Schema intersections retain their diagnostics.

A named Null singleton counts toward the existing 240-branch limit, so a nullable named product has at most 239 non-null alternatives. Inline nullable views do not add a physical null variant. Source depth 48, work 16,384, checked edges 16 and constructor limits remain unchanged. Independent resource probes do not establish simultaneous maxima or additional platform support.

Previously rejected explicit nullable products now generate an actual union and its original codecs; other accepted inputs retain their call sites and wire behavior.
