# Special scalar and JSON references in positional arrays

OpenAPI 3.1 positional members and schema tails may reference existing named bigint, byte/binary, primitive value class, caller-native, native-date and ordinary empty-model JSON declarations through their accepted finite named/internal chains. Open dictionaries (`additionalProperties:true`) use the existing collection planner, including direct inline positional sources. This extends D01/D03/D06 and F04/F08/M02/M03/M07/Q05. Each original source validates before selection; tuple syntax grants no new general resolver, composition or provider declaration.

Uniform prefixes retain the same original terminal and actual nullable view. Distinct sources/views use the existing raw projection; an explicit schema tail selects its own codec after every prefix validates. True/false tails retain their existing List approximation. `W_TUPLE_APPROXIMATION` remains: positions, exact length and false-tail maximum length are not enforced. Original source warnings remain, including ordinary empty-model `W_JSON_ELEMENT_APPROXIMATION`.

## APIs and wire

| Original source | Selected collection element |
|---|---|
| `x-native-type:bigint` | Numeric Long; the decimal-string serializer remains a direct DTO/Patch field policy |
| `format:byte` / `binary` | ByteArray with signed numeric-array JSON, including empty arrays; Base64 is not its default literal grammar |
| Primitive value class | Actual retained wrapper, constructor checks, scalar codec and boxed collection layout |
| Caller-native classifier | Actual provider class and serializer; no generated replacement or inferred layout |
| `x-native-type:date` | Actual Instant and ISO codec |
| Ordinary named empty object model | Existing JsonElement projection, including JsonNull |
| Open dictionary | Existing JsonObject projection and original alias/backing |

Nearest accepted alias/consumer nullable intent and intrinsic root views retain their existing policies. Non-null JsonElement admits JsonNull; nullable JSON views decode JSON null to Kotlin null. JsonObject admits objects and explicitly nullable null views. HTTP JSON roots, shared DTOs, request Patch and SSE reuse the selected codecs. ByteArray inside a List remains JSON; this does not change raw standalone ByteArray HTTP delegation. Provider-owned nullable/inline layouts and platform guarantees are not inferred from names.

## Outer annotations

Ordinary tuple fields, component roots and eligible independent collection aliases may own outer defaults. Bigint literals are signed Long numbers; bytes are signed byte arrays. Actual value class raw scalars and retained opt-in constructor checks validate annotations, while the final wrapper codec owns decoding. Native-date literals use the existing timestamp grammar. Empty-model JSON retains every data key/value. Open dictionary defaults must be objects and satisfy retained opt-in property counts, including through aliases.

Caller-native values use only existing supported scalar literal validators. For an opaque provider classifier, an empty collection or an independently nullable null element is defensible; an unproved non-null provider literal still rejects. Runtime consumers may construct actual provider instances normally. Container/element nullability remains independent. Targets, intermediate aliases and positional child annotations are not inherited or newly granted. Required/Patch annotations validate before initializer suppression, preserving required arguments and Patch.Absent. Helpers/factories decode fresh collections through the actual retained type.

## Identity, budgets and migration

Proof retains original paths/nodes/catalogs, canonical source/profile, actual unique export and name, provider/native marker, physical value class/checks, selected/backing addresses and cached reference height. Same-byte replacements, copied final types, duplicate exports or a classifier with matching Kotlin spelling do not grant authority. Discarded prefixes retain source validation, codec dependencies and incoming reference work. Boolean additionalProperties is a dictionary keyword rather than an extra schema-value depth edge; tuple depth matches the original ordinary collection control.

Source48, shared capture16384-step/8MiB, default16384-node/32KiB, checked16 and JVM240 limits remain. The shared capture now retains both canonical and actual named-alias catalogs/heights. **Compatibility impact:** previously accepted tuples whose complete named-alias captures exceed the existing shared cap can now fail E_MODEL_LIMIT, without replacing old output. This tightening also applies to earlier supported tuple references; it does not alter output/name-lock formats. Newly eligible special/open-dictionary tuple inputs gain the APIs above. Existing accepted Kotlin/wire contracts retain their source roles.
