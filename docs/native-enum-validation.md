# Native enum membership on DTO fields

With `--validation`, actual generated DTO fields carrying direct `integer`, `number` or `boolean` enum schemas retain their Kotlin scalar/wire type and enforce membership. This includes nested DTOs, supported allOf retained fields, object-union variant fields, inline request/response/error DTOs and SSE DTO payloads. Without validation their output and `W_ENUM_NATIVE_APPROXIMATION` remain unchanged. Open String enums retain known/unknown token behavior.

```json
{"type":"object","properties":{"code":{"type":"integer","enum":[1,2]},"enabled":{"type":"boolean","enum":[true]}},"required":["code","enabled"]}
```

Constructing or decoding the generated checked DTO requires `code` to equal 1 or 2 and `enabled` to be true. Checks use a private non-inline member helper with a fixed safe error message. Copying a data-class value invokes its checked constructor. Optional missing/null values and nullable fields retain their existing presence semantics; required values still require constructor arguments. Optional inline request fields retain `Patch.Absent`; `Patch.Null` is allowed where nullable, while `Patch.Value` must satisfy the vocabulary. A schema default still belongs to the original vocabulary and never replaces required request presence.

Int/Long membership uses representable exact Kotlin integer literals. Float/Double membership compares the mapped finite Kotlin values with `==`; source numbers that round to the same Float/Double become one accepted mapped value. For example Float enum `[16777216,16777217]` maps to 16777216f. Integer `1` and number `1.0` can coexist in an existing number vocabulary but map to one runtime comparison; original duplicate-literal validation remains unchanged. Signed zeros compare equal. NaN and infinities fail checked field construction. This scalar contract cannot distinguish JSON numbers erased by decoding to Float/Double and does not claim exact arbitrary-precision JSON numeric membership.

Original enum member validation is retained: nonempty homogeneous representable values, original duplicate identities, null-member admission/rejection and formats all use original nodes and source Pointers. [Null native enum members](native-enum-null-members.md) separately admit one null only in explicitly nullable numeric/Boolean vocabularies under validation. Checked vocabulary is limited to 240 raw members. Numeric token/exponent work uses the existing 256-character/±512 limits. Integer minimum initializers use arithmetic expressions to avoid shadowing by a legal `kotlin` field. Existing 240 JVM serialized slots, 48 schema depth and 16 checked collection edges remain unchanged; enum membership does not introduce a new collection traversal.

## Scope and projection boundaries

[Numeric enum plus bounds](native-enum-bounds.md) additionally combines retained numeric constraints and membership with bounded intersection/default checks.

This extension is direct DTO field enforcement. [Typed native enum consumers](native-enum-consumers.md) additionally retain checks through plain component scalar aliases/named refs, direct List/Map leaves and direct HTTP scalar/parameter/SSE payloads. Independent alias assignment/serialization remains unchecked. Primitive union pins and generic composed constraints keep their existing approximation/unsupported policy. Named DTOs used inside List/Map enforce these checks in their own constructors; standalone aliases remain unchecked. Native overrides, value-class annotations, null-only vocabularies, and general enum constraint intersections remain outside these profiles. [String null members](string-enum-null-members.md) preserve the separate open enum codec contract. Numeric enum bounds follow the separately documented bounded contract. General String enum membership validation is separate from the existing open enum wire contract.

Under validation, a raw projection or discarded allOf field that would lose a direct numeric/Boolean enum check is rejected at the original `enum` Pointer. It does not silently become a raw map or drop a checked vocabulary. The default-off projection contract remains unchanged. Constraints/default/example payload values are never treated as schema edges.

Mutable caller collections and requestBuilder overrides are existing validation boundaries. Membership is checked when the DTO constructor/serializer builds it; this adds no later object mutation barrier or arbitrary JSON validator. Typed HTTP responses and SSE DTO payloads use their generated serializers, so an invalid decoded field fails with existing request/cancellation ownership semantics.

## Compatibility and naming state

Turning validation on now enforces direct native enum DTO fields and removes their approximation warning. Existing validation-enabled callers that supplied nonmembers must use a declared mapped value. Default-off generated call sites and wire output stay unchanged. Validation-enabled raw/discarded projections that cannot retain membership now fail explicitly. These differences are intentional V05/M08/M12 changes.

Vocabulary participates in typed equality, dedup/merge and hoisted-name lock identity. Unrelated old primitive fingerprint slots stay byte-identical; enum-bearing checks use a separate domain wrapper. A locked shape's vocabulary change produces the existing `E_NAME_LOCK_CHANGED` diagnostic and no partial files/state. Manifest/config/name-lock format versions are unchanged; changing a stored validation profile still requires the existing lifecycle policy.
