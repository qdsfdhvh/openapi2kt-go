# JSON 首期兼容矩阵

[Discarded structured const declarations](discarded-structured-const.md) extend D04/M07–M11 source validation to fixed-DTO extra-key schemas and overridden pinned fields. Valid literals produce no helper/property/default or typed-kind warning; existing extra-key projection, winning-field codecs, original malformed-source diagnostics and budgets remain. [Validation without temporary initializers](discarded-const-validation.md) addresses a measured D08 allocation bottleneck without API/wire/format changes. Strict membership, general const/enum graphs and platform/final acceptance remain separate.

[Pinned structured const data](pinned-structured-const.md) extends D04/M07–M11 object-union variants and hierarchy leaf bodies with non-null JsonObject/JsonArray defaults. Data wires are excluded from scalar/compound/inferred tags and literal subtype names; const-only structured variants are parameterless stateful classes. Same-kind alternate values, original sources/warnings/limits and typed scalar discriminators remain. Discarded declarations have their own validation contract; broader const/enum composition and general platform/final acceptance remain open.

[Nullable allOf 成员交集](nullable-intersections.md)：D01/D02/F04/F07/M09/M11，无显式 root override 时 allOf 按成员 null 集合交集、union 成员按并集，保真实 ordinary DTO/product 物理构造器、alias 最近 intent、root Null carrier 与 inline nullable view、原 source/预算及 Patch/HTTP/SSE。**兼容性变化**：混合 nullable/non-null inline allOf 不再沿用首个成员，null default/data 须按迁移合同调整；原 explicit root override 与持久格式不变。一般组合/所有权、common bounds 与跨平台验收仍开放。

### M07：必须分开测试的字段状态

下面针对 **inline 对象请求及其递归 inline 子树**。引用 component 不拆分 request/response 类型，保留普通 nullable 模型；根 union 请求、response 与 deepObject 不开启 Patch。inline 对象中的 union 属性继承上下文，不等于根 union 请求开启 Patch。

| required | schema nullable | 请求体 Kotlin | 关键 wire |
|---|---|---|---|
| 是 | 否 | `T` | 必须提供值 |
| 是 | 是 | `T?`，无默认值 | 必须传 null 或值；`explicitNulls=true` 时 null 有键，独立于 `encodeDefaults` |
| 否 | 否 | `T? = null` | 缺省不发，非 null 发值；不是严格表达所有非法状态 |
| 否 | 是 | `Patch<T> = Patch.Absent` | Absent 不发、Null 发 null、Value 发值 |

- response 的可空属性允许保持 `T? = null`；const 不进入 Patch。
- Patch 的 Absent 在 `encodeDefaults=true` 仍不得发送；独立序列化 Absent 要报错。
- `ofNullable` 与 `orAbsent` 区分“清空”和“保持”，不能合成一个含糊工厂。
- 测试 inline request 顶层、内联嵌套/union variant、集合元素、字典值与引用 component 的差异；共享组件引用和根 union 请求保持无 Patch，不自动新增 `NameRequest`。
- inline 对象请求的 required nullable 不设默认值；共享组件、响应与根 union 请求的普通 nullable 默认仍可能省键。`explicitNulls=false` 不保证 null 键。必须验证两个配置的全部组合，不把一个请求上下文的正确性外推到其他上下文或配置。
- optional body 本身的缺省和“body 内某字段可空”是不同问题，分别测试。

### M08–M10：unknown 不是一个统一策略

enum 的未知字符串、普通 union 的未知对象、显式多层 discriminator、SSE 的未知 event 是四个契约。普通 union 已按合同保留原始 JSON Unknown fallback；已实现 SSE 子集忽略未知 event。多层层级需逐层 runtime 验证，不能因为一个路径有 fallback 就宣称全覆盖。

### SSE 验收特别项

- emitter 和 event model 共用同一 payload type 解析结果，不在两处猜类名。
- 首期后端选用 Ktor `client.sse`，SSE 用 Json 默认忽略未知字段，允许注入 Json；自定义流式后端不在本阶段范围内。
- 用 loopback server 或受控 byte channel 测分块边界、CRLF、多行 data、comment/空帧、断连、取消；MockEngine 的普通一次性 response 不足以证明 streaming 正确。
- 事件名缺省、reconnect/retry、重连时 header 行为与 Ktor 版本关联，P0/P3 固定兼容依赖后记录实测契约，不臆造保证。
