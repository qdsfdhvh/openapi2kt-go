# Known false-class JVM generic signature limits

The generator rejects a provably oversized JVM constructor or instance Data `copy` signature containing an actual retained [false component](false-component-roots.md) or [owner-nested false class](literal-false-fields.md). List/Map generic arguments retain those classifier names even though their erased descriptors contain only the collection classifier. Long names can therefore exceed the JVM's 65,535-byte modified UTF-8 constant limit below the existing 240-slot cap.

The check runs after model style and shape transformations. It uses actual emitted `FalseValue` declarations and lexical owners to establish nominal lengths. Nullable wrappers, known builtin scalar boxing and inline List/Map syntax contribute conservative lower bounds. An unbroken inline List chain ending in a non-null actual false class also contributes Kotlin's wildcards for the nested Lists and abstract terminal class. Map, nullable-inner and alias variance remains uncounted. Arbitrary `Named` spellings, alias backings and value classes do not establish a false classifier's length.

The constructor bound includes its parameter signature and `void` return. The instance Data `copy` bound includes the parameters and actual retained owner return classifier. Plain classes have no Data copy API and keep their independent constructor bound. Static Data `copy$default` uses the separate [erased descriptor check](false-nominal-jvm-limits.md); generic argument text is not added to that descriptor. Existing [builtin generic](jvm-signature-limits.md), [List variance](jvm-list-variance-limits.md) and [Data copy](jvm-copy-signature-limits.md) checks remain.

**Migration:** some previously generated sources that failed Kotlin compilation with `UTF8 string too large` now fail generation with `E_MODEL_LIMIT` at the original model Pointer. Generate, check and validate preserve existing output. Within-budget Kotlin bytes, APIs, wire behavior and ownership/name-lock formats remain compatible. Split the model or shorten names to reduce signature size. Plain style can remove an overflowing Data copy method, but changes the public model API and retains its own constructor limit.

`bash scripts/test.sh feature false-generic-signatures` freshly compiles and runs baseline and optimized optional/required Data/Plain models, explicit required constructor calls, Data copy and serialization under all four `encodeDefaults`/`explicitNulls` combinations. For a synthetic 316-byte package and `WideDto` owner with inline `List<FalseValue>` fields, Plain180 has a 65,343-byte constructor Signature; Data179 has a 65,312-byte instance copy Signature. The original producer's Plain181 and Data180 fail compilation and now reject during generation. These dimensions are probes, not general field-count limits. See [core boundaries](../core/false_generic_signatures_test.go), [bounded fuzzing](../core/false_generic_signatures_fuzz_test.go), [classifier authority](../internal/schema/false_generic_signatures_test.go) and [native preservation](../internal/cli/false_generic_signatures_process_test.go).

This is a lower-bound rejection check, not a proof of general JVM feasibility. Unknown aliases/value classes, omitted variance, synthetic serializer/default constructors, method bodies, metadata and other platform limits retain their own boundaries. Source48, false-work16,384, value16,384, default32KiB, checked16, JVM slots240 and enum240 limits and the existing resource probes remain unchanged.
