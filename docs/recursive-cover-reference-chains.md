# Reference chains to named recursive JSON covers

Finite typed internal/named reference chains and component-root bridges may terminate at an original accepted OpenAPI 3.1 [complete recursive JSON-kind cover](recursive-json.md), including its transparent named aliases. Incoming paths may return through another root bridge. The new path exposes `kotlinx.serialization.json.JsonElement` backing, with nearest explicit nullable true/false on the actual consumer-to-terminal path. Existing direct cover declarations/alias spelling and JSON behavior remain compatible. This is a bounded F04/F07/F10 extension.

The complete original reachable graph grants source permission, together with its unique retained JSON ValueAlias. Original catalog/node/Pointer, every reachable cover/reference node and source bytes, SCC height, incoming reference hops and actual declaration are recorded separately. Replacing same-byte graph nodes, changing a descendant or graph-edge grammar, missing/replacing/repeating the actual alias or changing its codec rejects permission. Rechecking original graph grammar does not trust an old successful height cache. Raw/literal-true/caller-native JSON spelling cannot substitute for a cover source role.

Source work adds the incoming transparent hops to the complete graph suffix: a self-cover retains height 2, a mutual pair 4, a pair with two transparent graph ref nodes 6, and a pair pointing onward to a self-cover 6. Consumer/container nesting adds its existing steps. Caches and explicit false narrowing preserve both segments; no alias introduces a nominal barrier. Depth 48, expansion work 16,384, checked collection edges 16 and constructor/method slots 240 remain. JSON references use one slot in both nullable and non-null views. Ref-only cycles cannot establish complete cover authority; graphs retain exact existing six-kind/version/keyword rules.

Non-null JsonElement admits JsonNull; nullable backing collapses JSON null to Kotlin null. Reified alias serializers and JsonElement's nullable adapter retain that policy without generated constructors or companion codecs. Shared default-null, required nullable request fields and optional Patch stay context-specific. `Patch.Value(JsonNull)` and `Patch.Null` share JSON null and decode as Patch.Null. JSON dictionaries retain the existing JsonObject approximation. Object-union common fields reached through these new cover paths use the same typed resolver and actual path nullable intent, so explicit false remains non-null JSON and retains JsonNull; this does not borrow the cover as a nominal union shape.

Numeric wire behavior remains the caller's JsonElement backing codec. Exponent spelling and large-number precision can change during encoding as documented by the original cover contract; transparent aliases perform no additional numeric conversion and promise no original-token/arbitrary-precision preservation.

Each original complete-cover root emits `W_RECURSIVE_JSON_PROJECTION` once; aliases/internal hops do not duplicate it. Warning denial precedes output mutation and preserves generated/unowned files. Original descendant constraints, malformed cover kinds, missing targets, nullable graph-edge siblings and transparent-use siblings are validated rather than discarded. Nominal allOf/union/hierarchy shape borrowing and SSE-envelope borrowing stay excluded; supported typed SSE data and JSON HTTP values use the configured codec. Fragmented malformed SSE data fails and closes a still-open channel; cancellation closes the stream and subsequent cold collection/client reuse remains available. Structured query encoding remains Ktor `toString` with its existing warning.
