# Inline values owned by object-union variants

Object `oneOf` / `anyOf` variants and supported object union-in-`allOf` products can contain fields with the same wire name whose inline schemas need their own declarations. Each variant retains its original nested object or union, constructor and codec. Lists and dictionaries of these values retain their own item/value classifiers as well.

For example, two variants with inline `value: {id: string}` schemas produce `Choice.A.Value` and `Choice.B.Value`. Callers access `value` after selecting the variant. The sealed base does not expose a common `value` property: identical structure does not make those separately owned Kotlin classifiers interchangeable. References to an actual shared named declaration keep the [common nominal contract](union-common-nominals.md).

Each original variant is planned and validated in full. Required names, nullable intent, request Patch, field checks, discarded allOf sources and resource limits are preserved. Different inline structures remain distinct. Invalid fields in any variant still fail generation before output commits. Scalar common properties and tag/presence dispatch keep their existing order; Unknown preserves the raw payload without acquiring a fabricated inline property.

The change accepts previously rejected inline common-wire object/union fields, including finite List/Map paths and supported allOf object values. It does not introduce a shared inline owner, structural subtyping or a new model-merge policy. Unsupported original schema keywords and composition profiles retain their diagnostics. Source depth 48, expansion work 16,384, checked collection edges 16 and serialized JVM slots 240 remain unchanged; independent width/depth probes do not establish simultaneous maxima or other platform support.
