# Scalar array defaults on ordinary DTO fields

String schemas with `format: uuid` use [Kotlin Uuid](nullable-uuid.md), including admitted scalar/collection defaults. UUID lexical checks, canonical text and the String-to-Uuid migration apply; original source-role and validation restrictions remain.

Finite direct ordinary DTO arrays whose items are further inline List/typed Map containers use the separate [nested builtin default profile](nested-builtin-collection-defaults.md). That profile preserves native types and per-layer checks; [direct nested temporal leaves](nested-temporal-collection-defaults.md) have their own extension, while enum/nominal/ref trees remain excluded.

Ordinary DTO properties with a direct `type: array` and direct scalar `items` accept a representable array `default`. Element types are String, Boolean, Int, Long, Float and Double, plus direct String `format: date` / `date-time` mapped to LocalDate / Instant; nullable elements are supported independently of container nullability. This extends M01/M02/M03/M07 and exercises the existing A03/A05/A08 request, response and SSE contracts.

An eligible direct builtin `items` schema can also own an independent annotation under the [child-default contract](inline-builtin-collection-child-defaults.md). It never supplies an array initializer or element.

```json
{"type":"array","items":{"type":"integer","format":"int64"},"default":[1,2]}
```

On an optional property this produces `List<Long>?` with a typed list initializer. Missing JSON uses the initializer, explicit null stays null, and supplied lists override it. Required properties have no constructor initializer: their annotation is validated, but callers still provide the argument. `explicitNulls = false` retains the serializer's existing inference for required nullable properties. Optional explicitly nullable inline request fields keep `Patch.Absent`; missing keys never become a default update.

An empty default is a typed empty list. Null container defaults require explicit schema nullability. Each original member must fit the mapped element type; null members require nullable items. Invalid elements report their original `/default/index` location before output is committed. Float and Double defaults use their mapped values, so equivalent source number spellings share an effective initializer. Array order remains significant.

Private file-level helpers parse validated JSON into typed lists. Field names such as `kotlin` and `kotlinx`, integer minimum values, quotes, dollar signs and supplementary Unicode retain their values. Each construction obtains its own list. The generated API exposes Kotlin's read-only `List` interface; it does not promise deep runtime immutability.

This profile applies to ordinary shared, nested, inline request/response and SSE DTOs, including supported ordinary object `allOf` merging. Overridden original defaults are still validated. DTO reuse, hoisting and name locks include effective default values. A changed default cannot silently reuse a frozen different shape.

With `--validation`, these defaults can be combined with the existing `minItems`, `maxItems`, scalar `uniqueItems`, and direct primitive item checks. The generator validates the annotation even on required and Patch fields, then retains the same checks for supplied values in constructors, data-class copies, decoding and typed HTTP/SSE consumers. A null container or nullable null element bypasses only its own non-null checks. An empty default still requires valid constraint syntax and must satisfy any minimum count.

Default counts fail at `/default`; a repeated or invalid member fails at its original `/default/index`. Uniqueness uses decoded String, Boolean and exact Int/Long equality, including `0` versus `-0`, escaped strings and at most one null. Float/Double uniqueness stays unsupported. String length uses Unicode codepoints; pattern defaults use the existing printable-ASCII matching boundary. Numeric defaults use the existing exact integer and mapped floating checks, including rounding at exclusive bounds. Floating `multipleOf` remains unsupported. Without `--validation`, constrained array defaults are rejected.

## Date and timestamp elements

```json
{"type":"array","items":{"type":"string","format":"date"},"default":["2024-02-29"]}
```

An optional ordinary DTO field receives `List<LocalDate>?` with a typed initializer. `date-time` similarly produces `List<Instant>?`. Generation validates each original member with the existing [temporal literal rules](special-scalars.md). Timestamp array defaults additionally require the common Go/Kotlin form: four-digit year, uppercase `T`/`Z`, two-digit time fields, at most nine fractional digits after a dot, and `Z` or an offset within ±18:00. Go-only spellings such as a comma fraction, single-digit hour, excess precision or an oversized offset are rejected before emitting a Kotlin initializer. Invalid dates, timestamps, JSON kinds or non-nullable null members fail at `/default/index`, even when the annotation belongs to a required field or Patch and creates no initializer. Empty arrays still validate the entire item schema. The formerly rejected empty `date` array field is retained verbatim as a positive regression.

The private JSON helper uses the existing temporal serializers, outside constructor scope so fields named `kotlin`/`kotlinx` cannot shadow packages. No new codec is generated. Defaults retain source temporal strings in generated initializer identity; equivalent timestamp spellings are not promised to share a name-lock fingerprint. At runtime Instant serialization follows its normal ISO canonicalization, including timezone normalization; exact original timestamp text is not a wire guarantee. Each constructed default list is independently decoded.

Both temporal types support independently nullable items, an explicitly nullable null container default, empty defaults and the existing required/Patch rules. With `--validation`, `minItems`/`maxItems` constrain both the default annotation and supplied typed values; invalid constructor/data-class copy/decoded values fail. Temporal `uniqueItems: true` follows the [mapped-value uniqueness contract](temporal-unique.md), including equivalent Instant offsets/fractions in default annotations. String/numeric temporal item constraints remain rejected, including on empty defaults. `uniqueItems: false` retains its existing validation-enabled metadata behavior. No temporal ordering, date-bound or string-length validation is inferred from the String source type.

This admission is limited to direct `date`/`date-time` items. Named/internal references, enum/const elements, native-date or caller-owned mappings, and default annotations on roots/wrappers/collection leaves retain their separate exclusions. Finite direct nested temporal field trees have the linked [extension](nested-temporal-collection-defaults.md). Direct temporal dictionary fields have the separate [Map default contract](primitive-map-defaults.md#date-and-timestamp-values). Existing primitive-array outputs and helpers are unchanged.

## Remaining boundaries and verification

Array defaults on roots, reference/composition wrappers, list/map value positions, pinned union/hierarchy fields, or nested/nominal/const/native elements remain outside this profile. Direct numeric/Boolean and plain String enum items have separate [native](native-enum-collection-defaults.md) and [String](string-enum-collection-defaults.md) collection-default contracts. Constraint aggregation across overridden array fields remains unsupported; original annotations and checks cannot be silently discarded. Schema keywords inside string data remain data. Source depth and constructor limits remain unchanged, and input acquisition stays offline.

These inputs previously failed with `E_SCHEMA_UNSUPPORTED`. Existing accepted inputs retain their generated API and wire behavior. The earlier empty String-array counterexample remains verbatim in the regression tests as an explicit admission. See the [fixture](../tests/fixtures/http/primitive-array-defaults.json) and `bash scripts/test.sh feature primitive-array-defaults` for Data/Plain, validation and the four JSON option combinations, HTTP and chunked SSE assertions. General collection defaults, schema composition and platform support remain separate work. The [checked fixture](../tests/fixtures/http/checked-array-defaults.json) and `bash scripts/test.sh feature checked-array-defaults` cover validation-enabled Data/Plain generation, four JSON configurations, runtime constraint failures, required/Patch states, HTTP and chunked SSE closure/reuse. Previously rejected constrained arrays are admitted only under validation; accepted unconstrained inputs retain their API, wire behavior and name-lock identity. The same fixtures/routes now include direct temporal defaults, required temporal fields, Patch.Absent/Null/Value, ISO wire and invalid temporal HTTP/SSE payload closure/reuse, plus temporal count constructor/copy/serde failures. [Core temporal regressions](../core/temporal_array_defaults_test.go) cover original member Pointers, preserved exclusions, counts and frozen-default identity; [native preservation](../internal/cli/primitive_array_defaults_process_test.go) includes an invalid leap-day default with unchanged prior output. These JVM profiles do not establish Android/KMP, other engines or minimum dependency compatibility.

## Scalar tuple field defaults

An ordinary DTO field may also own a default when [an accepted prefixItems array selects a direct scalar element](tuple-field-defaults.md). The shared scalar list helper/value checks and required/Patch policy are reused; no positional or tuple-length validation is inferred. Original prefix sources validate before tail selection or empty/null annotation handling. Prefix-only uniqueness and additional root/ref/nominal/default roles retain their independent contracts.
