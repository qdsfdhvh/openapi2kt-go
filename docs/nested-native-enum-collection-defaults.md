# Directly nested native enum collection field defaults

Component root annotations use the separate [finite nested component factory contract](nested-component-defaults.md); these factories do not become field initializers.

An ordinary DTO field may declare its own outer `default` on an already accepted finite direct inline List or typed `Map<String, T>` tree. Terminal leaves are limited to existing integer, number, or Boolean enums mapped to Int, Long, Float, Double, or Boolean. The same rule applies to List/List, List/Map, Map/List, Map/Map, and longer finite mixed paths. A default does not admit an otherwise unsupported schema or create an enum wrapper or new codec.

```json
{
  "type": "array",
  "items": {
    "additionalProperties": {
      "type": ["integer", "null"],
      "enum": [1, 2]
    }
  },
  "default": [{"first": 1, "nil": null}, {}]
}
```

As an ordinary optional `codes` field, this schema has type `List<Map<String, Int?>>?` and a typed initializer. Missing JSON uses the default, explicit null remains null, and an explicit collection replaces the entire default tree. Each initializer evaluation decodes an independent tree through a typed JSON helper bound to the final actual TypeRef; empty collections retain their full generic types and null remains nullable. The public List/Map interfaces do not promise deep immutability. Numeric/Boolean JSON remains native scalar wire data and does not use String enum `serialName`, entries, or `Unrecognized` APIs.

[Single-layer native enum collection defaults](native-enum-collection-defaults.md), [nested builtins](nested-builtin-collection-defaults.md), [nested temporal values](nested-temporal-collection-defaults.md), and [nested String enums](nested-string-enum-collection-defaults.md) retain their respective contracts.

## Original vocabulary, nullability, and presence

Every non-null default leaf must have the correct original JSON kind, be representable as the mapped Kotlin scalar, and belong strictly to the **original enum vocabulary**, with validation either off or on. Numeric membership uses bounded exact source numbers before Float/Double rounding: enum `[1]` does not admit a Float default of `1.000000001` even if the mapped values match. Original integer token grammar, Int/Long ranges, native enum duplicate rules, and numeric precision and exponent limits remain unchanged.

Explicit nullable intent is independent at every List, Map, and terminal layer. An annotation null requires the corresponding schema node to be explicitly nullable; the Kotlin nullable view of an optional field does not authorize it. Container nullability does not propagate to leaves, and nullable leaves do not create Patch. A nullable leaf need not list null in its enum. If the original vocabulary contains null, the existing [validation-only null-member contract](native-enum-null-members.md) still requires at least one non-null scalar and at most one null, preserves original member indices, and counts null toward the 240 raw enum member limit. Null does not make an empty non-null numeric-bound intersection valid.

Required fields, including required nullable fields, retain required constructor parameters without initializers after full annotation validation. Missing-required-null inference with `explicitNulls=false` is not strict required-key validation. An optional explicitly nullable field in an ordinary inline request remains `Patch.Absent` after full validation; a missing key does not become a default update. Patch.Null/Value retain their bare wire representation. See [request presence](request-presence.md).

Ordinary shared or nested DTOs and ordinary inline request, response, or SSE payload DTOs can consume this field profile. Ordinary DTOs inside Lists or Maps retain their existing nominal validation barrier. Ordinary object allOf retains later-field override: every original discarded annotation, complete vocabulary, constraint, and resource budget is validated before override, required/Patch suppression, or optimization. Override cannot remove enforcing checks. Existing checked NoDrop may reject at the original enforcing enum Pointer before traversing a discarded default, preserving error precedence. Collection or enum check aggregation across contributions and union/hierarchy field roles are not extended.

## Validation, original source, and NoDrop

With validation off, supplied values retain the native scalar approximation and the leaf's `W_ENUM_NATIVE_APPROXIMATION`; **strict annotation membership does not close the runtime vocabulary**. With `--validation`, existing mapped membership and bounds metadata checks non-null supplied values along the recursive typed consumer tree, and checked sources no longer emit that approximation warning. Constructors, Data copy, automatic serialization, Patch.Value, typed HTTP pre/postflight, and SSE payloads retain their existing check boundaries. Bare collection assignment, standalone alias/scalar codecs, subsequent mutation, and requestBuilder replacement are not schema validation barriers; existing HTTP/SSE wire and lifecycle contracts remain unchanged.

With `--validation`, List min/maxItems and typed Map min/maxProperties at each layer, as well as existing numeric enum inclusive/exclusive bounds and Int/Long factors, constrain both defaults and supplied values. A default must satisfy retained bounds even if it belongs to the original vocabulary. Float/Double supplied membership and bounds retain mapped finite-value semantics, with no epsilon or exact runtime decimal comparison. Int/Long/Boolean enum lists separately support [native uniqueness](native-enum-unique.md), retaining membership and bounds; floating enum `multipleOf`, Boolean numeric/String bounds, and `uniqueItems:true` for container elements remain rejected. See also [finite floating-point uniqueness](floating-unique.md) for Float/Double enum lists. `uniqueItems:false` retains only the effect-free no-op grammar for otherwise supported arrays under validation. **String bounds/patterns and general constraint aggregation are not extended.** Constrained schemas without validation remain rejected. NoDrop guards for ignored extras, raw/stringification projections, and discarded checks remain in place.

Even an empty or null default first validates the whole schema tree and original vocabulary before traversing the value. Errors retain the original `/default/<index>/<escaped-key>/...` Pointer, original enum member index, or constraint Pointer. Each Map is checked in source order and its keys are canonicalized only after success. Default keys such as `$ref`, `type`, `/`, and `~` are opaque data, never schema or references. Array order is preserved.

## Scope and resources

This profile adds only an ordinary direct inline field's own outer default. Inner container or leaf defaults, root/named/reference/wrapper/target/chain defaults, and default inheritance remain outside it. An allowed typed Map may omit type or declare object/nullable-object; nonempty fixed properties or required, Boolean/open dictionaries, untyped JSON, prefixItems, composition wrappers, and recursive trees retain their existing boundaries. A shared native classifier does not imply new default admission for caller-native/provider, const, value-class, DTO, union, hierarchy, or named/borrowed terminals.

All caps remain unchanged: **8 MiB** input, source depth **48**, **16** checked collection edges, **16,384** units of analysis work, and **240** each for serialized constructor slots and raw enum members. Before canonical allocation, each original default independently preflights **16,384 JSON values** (including containers and null) and **32 KiB of compact JSON**. Successful canonical JSON has a separate **32 KiB** cap; keys and scalar contents count in bytes, and value traversal is also limited to depth 48. Required/Patch/discarded annotations count toward the same budgets. Exceeding a cap is rejected at the original Pointer without returning partial artifacts, name-lock state, or warnings; the native CLI preserves old owned and handwritten files under its existing transaction. Individual source48/checked16/slots240/bytes32KiB probes do not establish a maximum-width-by-maximum-depth, compiler-heap, or platform guarantee.

## Actual types, optimization, and migration

Helpers bind the final actual scalar/container TypeRef after dedup/merge/hoist, without inventing an owner or constructing a classifier by Kotlin text substitution. Actual aliases and types, independent nullability, retained check trees, and effective canonical defaults all contribute to optimization and [name-lock](name-lock.md) identity. Reordering Map keys at any layer preserves output and lock identity; changing the effective default, nullable layer, or retained checks cannot reuse a different frozen shape. Native enum runtime mapped-check identity and strict source default membership are separate domains; not every raw numeric spelling creates a new runtime identity. Required/Patch annotations without initializers add no runtime default identity. Existing default-free, single-layer, and other leaf contracts retain their output, occurrences, opaque lock format, ownership, and CAS.

Migration impact: direct nested own-default inputs that previously returned `E_SCHEMA_UNSUPPORTED` at the original leaf enum can now be generated; consumers must regenerate and compile. Existing accepted inputs retain native Kotlin call sites, numeric/Boolean wire behavior, and validation-off approximation. Validation still checks existing mapped membership and bounds and adds no general runtime validator. This scope relates to M01/M03/M04/M07/M08 and existing M12/V05/A03/A05/A08; it **does not complete general D03/D04/D05, unified candidate, platform, or release acceptance**.
