# Internal ordinary DTO references

This bounded F04 profile binds typed schema Pointers to the **existing nested DTO**, rather than expanding or copying its object shape. [Hierarchy-owned nested DTOs](hierarchy-nested-owners.md) and [composition-owned DTOs](composed-nested-owners.md) extend the owner contexts through actual retained lexical provenance, including unique allOf/oneOf/anyOf constructor occurrences and root collection peers. Full internal reference graphs remain open.

## Canonical owner

An unencoded local reference such as `#/components/schemas/Tree/properties/node` may target a direct ordinary object in a direct ordinary component's `properties` object tree. Each enclosing object has explicit/inferred object type, direct nonempty properties, no composition/ref/enum/const/native/value-class identity, and at least one non-const constructor property. The component must not be a hierarchy node. The original direct-property profile does not include array/map-owned objects; those have the separate extension below. Composition/union-owned objects and empty/raw or const-only targets remain excluded. Root reference aliases have the separate binding profile below.

The target keeps its physical owner, for example `org.example.generated.models.TreeDto.Node`. Component suffixes affect `TreeDto`, not nested `Node`. Ref consumers use that fully qualified classifier, its constructor/copy, companion serializer and nested classifier owners. Direct typed references create no new catalog component, model copy, serializer, exported alias or `NonNull` peer. The separate root-alias profile adds only an exported typealias. All original owner fields, bounds, collisions and unsupported keywords must still validate, including unused definitions.

The direct-reference profile is a typed-use binding only. [Nullable ordinary DTO union members](nullable-object-reference-members.md#composed-and-internal-constructor-sources) separately admit eligible unique internal constructor sources. Shape expansion in object allOf, hierarchy branches or mappings and SSE envelopes remains excluded; component-root aliases have the separate profile below. Finite nominal-ending internal chains have the separate profile below. The same typed binding covers shared/inline DTO fields, direct JSON HTTP bodies/responses and typed SSE data fields. References still target component schema edges, not arbitrary schema anchors below HTTP paths. Finite borrowed collection targets retain their existing builtin-only admission. Ordinary direct lists/maps **containing a direct nominal ref** may use the classifier as an element/value.

## Recursion, nullability and checks

Direct self/mutual references terminate at nominal DTO identities instead of expanding schemas. Transparent-only ref/container cycles still fail under their existing policies. An explicit consumer `nullable: true` or false overrides the target's intrinsic intent; absent overrides inherit it, including annotation-only single-ref wrappers. Item/value intent and required/optional presence remain independent. Shared nullable fields keep default-null; inline request required-nullable fields have no default, optional nullable fields use Patch. Referenced DTO interiors keep shared-component semantics unless an ordinary HTTP consumer requires the separate [directional readOnly/writeOnly profile](directional-models.md); its operation-owned clones do not change the original nominal binding or canonical component.

Original DTO constructor/copy/automatic serialization barriers retain opt-in checks. Raw JSON or stringification projections cannot silently discard checks. Dereferencing consumes one schema step and stops at the nominal barrier; physical owner nesting still validates separately. Depth 48, checked collection edges 16 and JVM constructor/method slots 240 remain unchanged. A 240-field nominal consumer is not a width-by-depth compilation guarantee or platform claim.

## Finite internal reference chains

A typed use may follow a finite chain of annotation-only internal `$ref` nodes to an eligible canonical DTO above. Every intermediate reference remains under actual component schema edges; named component-root terminals and root aliases to internal nodes are separate capabilities. No schema or classifier is copied. The nearest explicit true/false nullable annotation in the chain precedes terminal intrinsic intent, and an explicit consumer override precedes both. Wrappers, request Patch/required nullable and list/map elements follow the same effective intent.

Every erased dereference contributes to the depth-48 source budget at every consumer. A nominal terminal ends expansion: self/mutual DTO recursion through a finite chain is valid, but transparent-only cycles retain `E_REF_UNSUPPORTED` at the original use. Missing/malformed intermediate refs retain their original hop locations. Transparent collection aliases that consume a chain preserve its erased work in their cached consumer height; nullable wrappers and false narrowing cannot discard it. The typed DTO's own constructor/serializer remains the validation barrier.

This extension does not widen borrowed builtin List/Map admission to nominal leaves: those finite graphs keep their original builtin-only contract, even when a child ref chain reaches a DTO. Collection-owned DTOs have the extension below. Remaining owner contexts, shape expansion, external refs, enum/const/native terminals and general nominal graphs remain outside these profiles. Root aliases initiating such a chain have the separate profile below; chains ending at direct named ordinary DTOs have the independent named-terminal profile below. Other named root terminals remain excluded.

**Migration:** previously excluded finite internal nominal-ending chains now produce existing canonical DTO signatures and wire values. The direct-DTO fixture and all historical snapshot bytes remain unchanged; the original single-hop-to-DTO exclusion is explicitly graduated to a canonical-owner positive assertion. Existing transparent-cycle exclusions remain. The new fixture is `tests/fixtures/http/schema-internal-dto-chains.json`; `bash scripts/test.sh feature internal-dto-chain` reuses the fresh canonical DTO runtime harness, with separate chain source-budget probes. Full F04 and platform/Cartesian resource guarantees remain open.

## Collection-owned DTO targets

Typed Pointers (including the finite chains above) may terminate at ordinary constructor-bearing DTOs physically owned below direct Lists/typed Maps. Supported paths mix direct `properties`, `items` and schema-valued `additionalProperties` edges, starting at a direct ordinary object or collection component. Boolean/open-map values, prefixItems/composition/union/hierarchy owners, ref-followed shape ownership and fixed-object additionalProperties scratch declarations are not owners in this profile.

Ownership follows the existing declaration planner, not the ref consumer. A property List/Map contributes `Inner`/`Value` to its local declaration name without introducing a namespace for the container: `OwnerDto.RowsInner`, or `OwnerDto.BatchesInnerValueInner.Child`. A direct root collection emits a top-level peer: `RowsDtoInner` or `MappingDtoValue`, **not** `RowsDto.Inner`/`MappingDto.Value`. Suffixes remain on the root name only. Repeated references reuse the physical classifier/constructor/copy/companion serializer; the complete shared declarations must confirm every bound classifier has constructor properties. Collision and invalid-field checks remain unchanged. Root aliases do not own copied peers.

Container nullability is not item/value DTO nullability. Intrinsically nullable DTO leaves retain their physical non-null classifier and typed inherited nullable intent; a consumer true/false override and chain-nearest override keep the existing precedence and Patch policies. Nominal self/mutual recursion, including recursion through a root collection alias, terminates at the DTO barrier. Dereferences and cached transparent aliases keep all existing source-hop/depth/slot budgets; physical owner nesting validates separately. Existing target constructor/copy/serde checks and raw-projection NoDrop remain in force. Borrowed builtin List/Map graphs still exclude nominal leaves; this extension admits DTO targets, not new container-shape expansion.

**Migration:** the unchanged array-item/map-value negative cases in the direct-owner table explicitly graduate to canonical `OwnerDto.NodesInner`/`OwnerDto.NodesValue` positives. Other exclusions stay negative and historical fixtures/snapshots stay byte-for-byte unchanged. The synthetic fixture is `tests/fixtures/http/schema-collection-owned-dtos.json`; core/native contracts and `bash scripts/test.sh feature collection-owned-dto` cover the new API/wire profile. This contract does not certify tests, full F04, every resource combination or any additional platform.

## Finite internal chains to named ordinary DTOs

A typed internal `$ref` chain may also terminate at a **direct named ordinary constructor-bearing DTO**, including an intrinsically nullable DTO. The terminal keeps its real component catalog entry, physical top-level classifier, constructor/copy, nested classifiers and serializer; no copied DTO or new alias is generated. Nominal self/mutual recursion stops at that classifier.

Only annotation-only internal hops are admitted. The nearest explicit internal nullable override wins over terminal intent, and an explicit consumer override wins over both. Shared defaults and inline request Patch/required-nullable rules are unchanged. Every internal edge and the final named edge count toward source depth, including cached List/Map consumers and explicit false narrowing. The maximum source depth remains 48; a property with 45 intermediate internal refs, its incoming ref and final named ref reaches that limit.

Named DTO aliases have the independent extension below. Scalar/collection/raw/const-only terminals, composition/union/hierarchy owners, borrowed builtin container graphs and shape expansion remain excluded. Root aliases initiating these chains have the independent bridge profile below. Final shared declarations must confirm a constructor-bearing physical owner even for unused owner fields; apparent DTO syntax cannot fabricate a classifier. Invalid source keywords and raw projections cannot discard checks.

**Migration:** these chains previously failed with `E_REF_UNSUPPORTED`; existing accepted DTO APIs and wire behavior are unchanged. The historical chain-to-its-own ordinary named owner exclusion graduates explicitly without changing its input. The synthetic fixture is `tests/fixtures/http/schema-named-dto-chains.json`; core/native contracts and `bash scripts/test.sh feature named-dto-chain` define the verification surface for nullable/Patch, four Json configurations, HTTP and fragmented live SSE, with separate width/depth compilation probes. This is a bounded F04/F07 increment, not full reference-graph or platform support. Existing alpha packages are unchanged.

## Finite internal chains through named DTO aliases

Typed internal chains may terminate through existing annotation-only named `$ref` aliases whose canonical target is a direct named ordinary DTO or an eligible property/List/Map-owned internal DTO. Named alias chains reuse their existing root binding and physical classifier. Canonical node/Pointer and actual catalog identity are retained; no schema, classifier, serializer or alias is fabricated. Nested classifier access uses the physical owner, not a typealias-owned namespace. Shape-expanded/composed DTOs, hierarchy/union/raw/scalar/collection/const-only targets are not admitted by this extension.

Nullable priority is: explicit consumer intent, nearest explicit internal-hop intent, effective nearest named-alias intent, then terminal intrinsic intent. Both true and false survive inheritance and cached transparent List/Map consumers. Shared defaults, inline required-nullable fields and optional Patch remain unchanged. Each incoming/internal/named-alias/final-target edge counts toward depth 48; the named alias's cached height is added to, not replaced by, internal work. Nominal recursion remains a barrier; transparent-only alias/internal cycles remain rejected with their existing source diagnostics. Missing or malformed alias definitions retain their original source locations and full owner validation is still mandatory, even when unused.

The final shared declarations must confirm the canonical constructor-bearing owner. Borrowed builtin container admission still disables nominal terminals. Root aliases starting at internal chains that cross into named roots have the separate bridge profile below. AllOf/union/hierarchy shape expansion, external refs and nonordinary aliases remain excluded; this typed-use increment is not a general alias graph.

**Migration:** these typed chains previously failed with `E_REF_UNSUPPORTED`; already accepted APIs and wire behavior remain unchanged. The earlier direct-named profile's alias-to-DTO negative and the root/internal-alias profile's internal-chain-to-alias negative explicitly graduate with their inputs unchanged. Synthetic fixtures are `tests/fixtures/http/schema-named-dto-alias-chains.json` and `tests/fixtures/http/schema-internal-dto-alias-chains.json`; `bash scripts/test.sh feature named-dto-alias-chain` defines fresh data/plain × validation and all-optimization profiles, four Json/Patch/HTTP/live fragmented SSE assertions and independent width/depth probes. This is a bounded F04/F07 increment; full graphs, platform and Cartesian resource guarantees remain open. Existing alpha packages are unchanged.

## Component-root aliases through internal chains to named DTOs

Annotation-only component roots may cross finite internal `$ref` nodes into existing named ordinary DTOs or aliases to eligible direct/property/List/Map-owned DTOs. The root exports a typealias to the original physical classifier, with the same constructor/copy/serializer and nested-classifier ownership. Binding retains original nodes, Pointers and real catalog entries; it never expands shapes or fabricates components.

Forward named dependencies use the existing catalog DFS before typed-chain admission. Every root/internal/named-alias/final-target edge counts toward depth 48 at each consumer and in transparent collection caches. Own root intent precedes nearest internal intent, effective named-alias intent and terminal intrinsic intent; explicit consumer true/false overrides all of them. False narrowing cannot discard erased work. Shared/default-null and inline required-nullable/Patch behavior stay unchanged. DTO recursion terminates at physical identity. Mixed transparent cycles retain the named catalog cycle policy; internal-only cycles retain their existing unsupported-target policy.

The hierarchy-filtered registry and final shared declarations must confirm a real ordinary constructor-bearing owner, including unused aliases. Nonordinary targets, hierarchy/union/composition owners, borrowed builtin nominal leaves, object/hierarchy/union/SSE-envelope shape expansion and external/encoded refs remain excluded. This extends typed binding, not general graphs.

## Component-root aliases to internal DTOs

This separate bounded profile admits annotation-only component-root `$ref` aliases whose target is an eligible canonical internal DTO from the owner profiles above, directly or through their finite internal chains. Named root-alias chains may end at such a binding. The exported Kotlin `typealias` points to the original physical classifier (`OwnerDto.Node`, `RowsDtoInner` or `MappingDtoValue`), never a copied model or fabricated catalog component. Typed consumers use that same classifier, constructor/copy and serializer. Nested classifier access stays on the canonical path, such as `OwnerDto.Node.Child`; a Kotlin typealias does not expose new nested classifier owners.

The root alias keeps its original schema/name/Pointer; its target keeps the original terminal node/Pointer. Own alias nullable intent precedes the nearest referenced alias/internal-chain intent, then terminal intrinsic intent; a consumer true/false override precedes all of them. Root collection nullability does not leak into a DTO leaf. Required/optional/Patch and shared interiors retain the existing policies. Every named/internal hop remains in source depth and transparent collection-alias cache height, even after nullable narrowing. Nominal self/mutual recursion terminates at the physical DTO; transparent-only cycles do not become DTOs.

Only complete shared declarations can confirm a constructor-bearing owner. Unused root aliases must also fail if the apparent target becomes a const-only/raw projection or a hierarchy-owned classifier. Full owner/field validation, original diagnostics, deterministic generation and failure preservation remain mandatory. Object allOf shape expansion, union/hierarchy branches or mappings, SSE envelopes, borrowed builtin container graphs are not widened by this profile; internal chains crossing into eligible named root terminals have the independent bridge profile above.

**Migration:** these root aliases previously failed with `E_REF_UNSUPPORTED`. This profile is available in the current source; existing `v0.1.0-alpha.1` packages are unchanged and do not include it. The unchanged historical property-owner and root-array-item alias negatives graduate explicitly to canonical-owner positives; other exclusions and all existing fixture/snapshot bytes stay unchanged. The new synthetic fixture is `tests/fixtures/http/root-internal-dto-aliases.json`. Core/native and fresh Kotlin tests must verify constructor/copy/reified and canonical serialization, four Json configurations, request Patch, direct HTTP and typed fragmented SSE data. [Core contracts](../core/root_internal_dto_alias_test.go), [physical-node/catalog tests](../internal/schema/root_internal_dto_aliases_test.go), [native preservation](../internal/cli/root_internal_dto_alias_process_test.go) and `bash scripts/test.sh feature root-internal-dto` provide the verification surface.
