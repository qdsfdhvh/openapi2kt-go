# Scalar defaults on DTO fields

[Referenced String enum scalar fields](referenced-string-enum-scalar-defaults.md) accept their own annotations on already admitted plain enum paths, preserving the actual lexical classifier, strict original vocabulary and open runtime Strings.

[Referenced native enum scalar fields](referenced-native-enum-scalar-defaults.md) accept their own annotations on already admitted numeric/Boolean enum references, preserving scalar literals, strict original vocabulary checks, required/Patch and existing validation admission.

[直接嵌套 native enum 集合字段默认值](nested-native-enum-collection-defaults.md)仅接受 ordinary direct inline finite List/typed Map 字段自己的 outer default，terminal 为既有 Int/Long/Float/Double/Boolean enum。完整原词表/exact numeric membership、schema/checks 与预算先于 required/Patch suppression 和 allOf override 验证；native scalar wire、逐层 nullable 和实际优化/锁身份不变，ref/named/root/child/default-inheritance 等角色不扩张。

[Referenced String enum collection field own defaults](referenced-string-enum-collection-defaults.md) extend the same own-default role to plain String enum leaves, and [referenced native enum collection field own defaults](referenced-native-enum-collection-defaults.md) to native numeric/Boolean leaves. [Referenced temporal collection field own defaults](referenced-temporal-collection-field-defaults.md) extend only ordinary direct local `$ref` fields' own outer annotations through already accepted finite List/typed Map paths with standard date/date-time leaves. Actual aliases/codecs, original source/nullable/check authority and required/Patch/budgets remain; target/chain/root/child/native roles stay separate.

[Referenced standard temporal scalar field defaults](referenced-temporal-scalar-field-defaults.md) separately accept only an ordinary direct `$ref` field's own annotation through already admitted date/date-time paths, preserving actual LocalDate/Instant codecs, original lexemes, required/Patch and source authority. Native/collection/target/chain/root/composition roles remain separate.

[Referenced builtin scalar fields](referenced-scalar-field-defaults.md) separately accept an ordinary direct local `$ref` field's own default through already admitted named/internal finite builtin6 paths. Actual literal/check/source/nullable authority and required/Patch remain; target/chain/root/wrapper defaults are excluded.

[Referenced builtin collection fields](referenced-collection-field-defaults.md) separately accept a direct ordinary field's own default through existing named/internal List/typed Map references. Target/chain defaults are rejected; nullable precedence and actual typealias/check identity remain with the resolver.

Direct ordinary DTO finite List/typed Map trees have a separate [nested builtin default contract](nested-builtin-collection-defaults.md). It reuses supported pure schemas and builtin leaves, preserves required/Patch and original diagnostics, and bounds the whole default annotation. [Direct date/date-time leaves](nested-temporal-collection-defaults.md) extend only this finite inline field tree. [Plain unformatted String enum terminals](nested-string-enum-collection-defaults.md) separately extend only the outer ordinary field's own default on already admitted inline trees, retaining lexical classifiers, open runtime Strings and strict original annotation membership. Per-layer nullable/count checks, required/Patch/discarded validation and whole-tree budgets remain; nested String enum bounds and other default roles stay excluded.

Direct ordinary String, Boolean, Int, Long, Float, Double, LocalDate and Instant fields in generated DTOs accept a representable schema `default`. This is the initial M01/M07 default contract. The original field node supplies both the value and its diagnostic Pointer.

An optional field gets a Kotlin constructor initializer and uses that initializer when JSON decoding omits the key. For example, `{"type":"string","default":"ready"}` on an optional property produces `String? = "ready"`. A supplied value overrides the default; an explicit JSON null remains null. A null default requires explicit schema nullability, rather than the incidental nullable type used for optional fields.

A required field with a schema default still has no Kotlin constructor initializer. This also applies to required nullable fields, including shared DTOs in this newly accepted profile. The value is validated as an annotation; callers must provide the argument. JSON's `explicitNulls = false` may infer null for a missing required nullable field under the existing serializer behavior, so this does not establish strict required-key validation.

Optional explicitly nullable fields in ordinary inline request objects keep `Patch<T> = Patch.Absent`, even with a non-null or null default annotation. Missing request keys must not become updates. `Patch.Null` and `Patch.Value` retain their existing wire states. Object-union variants keep their existing ordinary optional-field policy and may have separate defaults for the same abstract property. Unknown union peers retain raw passthrough and their existing abstract-field fallbacks.

Defaults work in shared components, nested DTOs, DTOs used through List/Map references, supported allOf object shapes, union variants, inline request/response DTOs and SSE payload DTOs. Supported allOf shapes retain their documented later-property override rule; every discarded original default must still pass its source type checks. Discarded validation constraints without an existing aggregation contract remain rejected.

## Literal and validation rules

Strings use Kotlin literal escaping. Numbers must fit their mapped Kotlin type; integer defaults must be integral, and non-finite/overflowing floating defaults fail. Temporal defaults must parse as the accepted ISO date or instant. Private file-level parsing helpers and arithmetic minimum-value expressions prevent legitimate field names from shadowing package qualifiers.

With `--validation`, default values must satisfy retained field checks. String length counts Unicode codepoints. Pattern defaults are limited to printable ASCII values and patterns for portable generation-time matching; broader runtime patterns retain their existing grammar. Integer bounds and `multipleOf` use the existing bounded exact arithmetic. Floating default bounds compare the mapped Kotlin Float/Double values, including rounding ties at exclusive endpoints. Defaults combined with floating `multipleOf` remain rejected. All literal/constraint failures return diagnostics before any output commit.

Direct enum fields have the separate [enum default contract](enum-defaults.md). Direct null-valued scalar/enum fields have the separate [null-only default contract](null-only-defaults.md). This initial direct scalar profile rejects defaults on scalar component roots, composition wrappers, collection elements/values, enum/const/native/value-class fields, byte/binary scalars and structured object defaults; direct `$ref` fields use the bounded linked contract above. Direct scalar-array DTO properties, including date/date-time items, have the separate [array default contract](primitive-array-defaults.md); direct scalar dictionaries, including date/date-time values, have the [map default contract](primitive-map-defaults.md). A default on a DTO field is not a general metadata exemption. The generator never follows references or interprets schema keys inside a default value.

## Optimization and compatibility

Model merging, operation deduplication and hoisting compare emitted defaults, so different defaults remain distinct. Name locks keep the frozen legacy fingerprint for existing inputs and use a separate fingerprint domain for newly accepted default-bearing declarations; the persisted opaque-hash format remains version 1. Replaying a lock whose emitted default changed fails the existing shape-change contract.

These inputs were previously rejected. Existing accepted inputs without schema defaults retain their Kotlin signatures, wire behavior and lock fingerprints. The [original rejected fixture](../tests/fixtures/p1/invalid/unsupported-default.json) and its manifest remain intact and are covered by explicit core/native positive assertions. The [synthetic envelope](../tests/fixtures/http/model-defaults.json), Go source/limits tests and `bash scripts/test.sh feature model-defaults` cover the new profile; fresh Kotlin consumers exercise all four `encodeDefaults`/`explicitNulls` combinations, missing/null/value, required/Patch semantics, unions, containers, HTTP and SSE. This does not close general defaults or platform acceptance.
