# Direct nullable component DTO property counts

With `--validation`, a direct ordinary, non-inherited DTO component root may combine explicit intrinsic nullability with its own `minProperties` / `maxProperties`. The original root must have direct properties and retain at least one constructor property. Both existing spellings work: OpenAPI 3.0 `type: object, nullable: true` and OpenAPI 3.1 `type: [object, null]`. The existing properties-inferred object spelling with explicit root `nullable: true` also remains eligible.

```json
{"openapi":"3.1.0","components":{"schemas":{
  "Record":{"type":["object","null"],"minProperties":1,"maxProperties":2,
    "properties":{"value":{"type":"string"}}}
}}}
```

The physical Kotlin declaration stays the canonical non-null serializable DTO. Its constructor, Data-class `copy`, property getters and companion serializer retain their APIs; Plain-class keeps its existing absence of `copy` and `componentN`. Direct typed references inherit `Record?`, while the nearest alias/consumer `nullable: false` uses the same physical non-null class. Nullable typealias companion calls still return the canonical non-null serializer. Use `serializer<Record?>()`, a reified nullable alias or `Record.serializer().nullable` for root null.

The existing [whole-object count serializer](model-semantics.md#ordinary-dto-json-property-counts) retains the automatic `generatedSerializer()` delegate and descriptor. It decodes counts from the actual parsed `JsonObject` **before** defaults or unknown-key handling. Unknown keys and explicit null keys count once each, even with `ignoreUnknownKeys=true`. Encoding checks the actual delegated object **after** serialization under the caller's `encodeDefaults` and `explicitNulls`. Constructor properties, filtered keys and subsequently applied defaults are not substitute counts.

For example, `{"unknown":null}` satisfies the example's minimum before the delegate discards that key. Its decoded `Record()` can then fail encoding when the caller's settings produce `{}`. `{"value":null}` is one physical member; root JSON `null` is handled by the nullable adapter and skips object counts. Null does not bypass generation-time schema validation, invalid fields/defaults or source-role guards.

Counts remain JSON-only, including min=0. Constructors and `copy` are not whole-object count barriers; existing primitive/collection checks still run at their original constructor/copy/decoding boundaries. The generator adds no fields, slots, hidden Json settings, nullable root defaults, per-consumer counters or count preflight. Direct experimental delegate calls and caller serializer/requestBuilder replacements retain their existing boundaries.

Bounds use the existing grammar: plain nonnegative Int-range integers; wrong kinds, decimal/exponent spellings, negative zero, overflow and reversed intervals fail at the original keyword Pointer, reversal at `maxProperties`. Original source-node/Pointer/depth checks run before local bound checking and consolidation. This profile owns only the direct root's local count source; composition sources cannot borrow that permission. Validation-off still rejects count keywords.

Typed nested references, List/Map values, nullable/narrowed aliases, request required-nullable/Patch and ordinary defaults retain their existing codecs and presence policy. HTTP uses the caller's ContentNegotiation Json. Count encoding can fail after the request callback and prevents engine dispatch; existing primitive construction failures occur at their earlier boundary. Success responses check the incoming object before unknown loss/defaults. SSE counts only JSON data with its separate injectable Json; invalid known data or delegate failure closes a still-open fragmented input and preserves caller-client reuse. SSE envelopes retain their non-null policy.

`allOf` nullable component counts, reference-wrapped roots, root nullability discovered only from inline composition, hierarchy/common/inherited/union roles, AP-only dictionaries as nominal DTOs, empty/count-only/const-only models, raw/stringified projections, inline HTTP root allOf and generic intersections remain outside this increment. AP-only dictionaries retain their separate typed-size contract. Existing [nullable allOf DTOs](nullable-allof-dtos.md) and [referenced/nested allOf counts](referenced-allof-counts.md) do not gain permission to combine those roles. Discarded fields and ignored extras cannot lose checks.

Only effective checks/counts enter existing declaration equivalence and owned shape-lock identity. Equal admitted roots may merge to the canonical classifier; changed counts remain distinct. Frozen owned shapes reject count drift. Name-lock/manifest formats, allocation/occurrence rules, original resolvers and source budgets are unchanged: source depth 48, checked collection edges 16, serialized slots 240, composition work 16,384, input 8 MiB and the existing default byte/value limits. Independent boundary probes do not establish simultaneous maximum resources, performance gains, Android/KMP or minimum-toolchain support.

**Migration:** previously rejected direct explicitly nullable counted component DTOs can generate with validation enabled. Invalid JSON encode/decode now fails at the existing serializer boundary; valid Kotlin call sites and wire behavior retain their canonical APIs/codecs. General D05/V05/V06 and nullable allOf counts remain open.
