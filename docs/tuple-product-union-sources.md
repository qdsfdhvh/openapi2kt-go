# Product union tuple sources

OpenAPI 3.1 positional arrays may use existing object unions inside `allOf`, directly or through existing named/internal product references and pure aliases. This extends D02/D03/D06 and F08/M03/M07/Q05 through the actual product planner, without adding a general intersection validator or resolver role.

The original allOf/oneOf/anyOf graph produces the same bounded Cartesian alternatives as [object union composition](union-allof.md). Original contribution order, required-field union, later field overrides, tag conjunctions, key-presence fallback and Unknown codec remain. A tuple does not introduce a replacement DTO or raw substitute for a selected sealed product. Component roots retain actual root classifiers and Null carriers; inline views retain independent Kotlin nullability. Shared/operation contexts keep their original planner policies.

Every prefix and schema tail completes source validation before selection. Uniform sources use the same original terminal and effective null view; separate inline nodes and different null views remain mixed `List<JsonElement>`. Explicit schema tails own the actual selected element codec. Boolean tails retain existing List approximation: positional types, exact length and false-tail maximum length are not enforced. Primitive/dictionary/discriminator intersections outside the existing composition contract still fail, including when raw or scalar tails discard their prefixes.

## Outer annotations

Ordinary consuming field, component-root and independent collection-alias own defaults decode through the actual selected product serializer. An object annotation must select a known conjunction/presence variant and satisfy that original merged constructor's required keys and supported member literal rules. Unknown fallback does not authorize a default. Root Null carrier, nullable alias adapter and inline nullable classifier retain their different JSON-null behavior. No target, intermediate or child annotation is inherited. Required and Patch annotations validate before initializer suppression; required arguments and `Patch.Absent` remain.

Original allOf source work remains visible after projection, including erased operands, references, overridden fields and discarded source validation. Factories may retain the exact original deferred nominal before final linking; successful generation still proves its unique final declaration and exact actual type address. The source validator returns facts rather than scratch emission candidates.

## Source identity and limits

The retained plan checks original root/path/catalog nodes, the original product role, actual sealed declaration/nominal origin, exact variant pointers, conjunction vocabulary, consumer/backing addresses and cached source heights. Same-byte copied source or variant declarations do not acquire authority. Const/default/enum payloads remain JSON data; metadata-named data nodes retain identity without schema-reference permission. Captured internal reference wrappers do not enter catalog-only allOf shape resolution.

Source depth48, cumulative16384-step/8MiB snapshots, product branch240, default16384-node/32KiB, checked-depth16 and JVM240 limits remain. Cartesian overflow is rejected before expanded alternatives allocate. Source cycles and invalid discarded annotations fail with original Pointers and no partial artifacts. Generation remains deterministic/offline and preserves existing output on failure.
