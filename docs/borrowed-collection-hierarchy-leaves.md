# Borrowed collections with named hierarchy leaves

Finite internal List and typed Map paths, and component root aliases exporting those containers, may reuse existing named hierarchy parents, intermediates, leaves and supported nullable aliases. A List of a hierarchy parent uses its canonical sealed classifier; a Map of a leaf keeps the physical leaf constructor and serializer. Containers do not add inheritance nodes, typed tag vocabularies or variant namespaces.

This extends [named hierarchy reference chains](hierarchy-reference-chains.md). Admission requires the original catalog/schema node/Pointer and hierarchy-source role, followed by one actual retained Hierarchy declaration and its original parent lineage. Ordinary object syntax on a leaf does not authorize this role. Missing/replaced/repeated hierarchy declarations, changed physical parent/tag rules/enums/leaf models, copied original source nodes and changed alias/source heights are rejected. Parent and child sources remain original, including branch-array and semantic keyed/ordered identity; no expanded schema document or fabricated component is introduced.

Known/Unknown dispatch, fixed/generated/inherited discriminator fields and direct codecs retain their existing contracts. Physical inheritance and canonical direct serializers remain non-null. Typed nullable aliases/views use nullable codecs. Container and item/value nullable intent remain independent; nearest explicit consumer/ref/alias true/false overrides inherited intent without resetting cached source work. Inline request Patch and required nullable inputs keep their existing semantics.

The hierarchy is a nominal recursion barrier. All preceding transparent named/internal and collection edges count toward source48. Work16,384, hierarchy branch240, checked collection depth16 and JVM slots240 remain unchanged. Each collection-valued property or parameter occupies one slot. Separate probes do not establish every maximum combination or additional platform support.

Container validation remains opt-in at typed constructors/Patch.Value/HTTP pre-postflight/SSE event data. Leaf constructor/automatic serde checks remain nominal. Existing structured parameter projection and warnings are unchanged. Invalid source preserves old output. Fragmented SSE failures and cancellation close still-open input, with repeated cold collection and client reuse following the existing SSE contract.
