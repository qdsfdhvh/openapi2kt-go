# Nullable members in named hierarchies

A named discriminator hierarchy may include a direct `{ "type": "null" }` member, an explicit nullable `$ref` member or a supported nullable named alias as a member. Those members give the containing hierarchy nullable intent at typed references and transparent aliases. The physical sealed/data/object classifiers, inheritance and direct serializers remain non-null; Kotlin nullable adapters handle JSON null. No hierarchy-owned Null subtype is generated.

A nullable child schema alone retains the [intrinsic hierarchy contract](intrinsic-nullable-hierarchies.md): its direct physical membership does not make the parent nullable. A nullable alias used as a member carries its effective alias intent, including nullability inherited from the target's null members. A branch `nullable: false` overrides that member intent; the nearest explicit alias false also blocks it. A schema-level false does not remove its explicitly declared null member. A consumer or exported alias can still narrow the resulting typed hierarchy to the canonical non-null classifier.

## Mapping and codecs

Nullable aliases in discriminator mappings select the canonical non-null child serializer for recognized objects. Mapping intent alone does not add parent nullability. Existing first-canonical mapping routes, per-layer enums, const-first/compound dispatch and raw-preserving Unknown remain. A recognized malformed object fails; nullable decoding does not turn it into Unknown. False-narrowed codecs reject JSON null under the existing physical codec contract; supported intrinsic nullable singleton codecs also reject null directly.

Required/optional properties, request Patch, list/map elements, JSON HTTP bodies and SSE data use the same typed intent. Patch.Null sends explicit null, while Value carries a physical non-null hierarchy instance. SSE remains cold, known payload failures close fragmented inputs, and callers can reuse the client. [Internal chains and root bridges](hierarchy-reference-chains.md) retain every original reference hop and nearest intent.

## Original graph and limits

Discovery borrows original named nodes and forms reverse dependencies for alias-member nullable propagation. Each true fact propagates once under a 16,384 work bound; schema JSON is never expanded or mutated. The actual hierarchy planner validates every member/mapping and final declaration ownership before emission. General shape composition continues using its independent nullable-borrowing policy.

Pure null contributes no physical child or parent edge, but still consumes source work and depth. At least one real named child must remain. The raw hierarchy member limit remains 240, including every null member. Source depth remains 48 with cached alias heights; false narrowing cannot erase hops. Multiple nullable/null members in oneOf emit `W_ONEOF_NULL_OVERLAP` because dispatch does not enforce exact oneOf match counts. Null member keywords beyond `type`, malformed nullable values, transparent/hierarchy cycles, repeated parents and illegal tag sources remain errors at original Pointers.

This adds support for previously rejected nullable member/mapping inputs while preserving accepted physical declarations and wire behavior. [Hierarchy-owned direct nested DTO references](hierarchy-nested-owners.md) have a separate provenance contract. Inline hierarchy nodes, multiple parents, general borrowed nominal ownership, hierarchy intersections and full JSON Schema validation remain separate.
