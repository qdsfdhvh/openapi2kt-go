# Component root aliases to borrowed internal collections

Explicit component root aliases may export original finite internal List/typed Map trees whose leaves use the admitted builtin scalar grammar. Internal paths, finite internal hops, named export aliases and return paths through exports retain the original backing. New nullable true/false uses follow the nearest explicit consumer-to-terminal intent; root container nullability and element/value nullability stay separate. This is a bounded F04/F07/M03 extension to the existing borrowed typed-use contract.

The borrowed terminal has its actual lexical SourceCatalog, original owner schema, node, Pointer and source bytes. It does not become a canonical component or acquire a nominal classifier. Entry components, terminal owners, nested leaf owners and emitted root ValueAlias declarations remain separate. The original finite reachable collection/ref/leaf graph retains node/Pointer/byte identity and its ordered path-parent member/item identities. Identical-byte copied roots or nested ref replacements cannot grant permission. Root exports share their original TypeRef/check objects and content; old direct borrowed consumers retain per-use parsed checks. Unique actual original root ValueAlias occurrence, linked backing, cached alias/collection height and path nullable must still match before emission. Missing/replaced/repeated exports, mutated backing/check content, graph or cache reject.

Each incoming ref hop, transparent root alias, nested item/value ref and collection edge contributes source work. Null wrappers add none, false narrowing does not reset it, and cached source suffixes cannot hide new consumer depth. Scalar leaves and containers retain their finite source grammar; borrowed trees containing named/nominal leaves or crossing catalog terminals are separate profiles and still reject here. Transparent cycles across root/ref/container edges fail; no model is invented to break them. Depth 48, checked collection edges 16, work 16,384 and field/method slots 240 remain. All List/Map containers use one JVM slot independent of nullable backing. Width and depth probes are independent, not Cartesian resource claims.

Kotlin root aliases construct native collections and use ordinary reified List/Map serializers without alias companions. Root/null JSON wire, nested leaf checks, required nullable inline inputs and optional inherited-nullable Patch retain the original contracts. Bare alias assignment or independent List/Map serialization is unchecked; validation opt-in applies at DTO construction/serde, Patch.Value, typed HTTP pre/postflight and SSE payloads. Eligible builtin uniqueItems and nullable leaves keep their existing comparison behavior. Original check objects use bounded model check functions; wide checked HTTP/SSE inputs use the existing private non-inline input helpers. Public signatures and callback/preflight order remain unchanged.

All source grammar, including unused exports, validates before output: unsupported defaults/ref siblings, invalid counts/bounds or leaf formats preserve original diagnostic Pointers. Shape allOf borrowing does not gain collection permission. Semantic failure and warning denial preserve existing manifest-owned and unowned output. Structured query values retain Ktor `toString` projection/warnings. Fragmented SSE wrong-kind/null/syntax or check failure closes still-open input; cancellation closes the stream, cold collection and client reuse remain available. No reconnect policy or recursive query encoder is added.
