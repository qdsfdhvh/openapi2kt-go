# Kotlin model style

`GenerationOptions.ModelStyle`, `--model-style` on generate/validate, and config defaults/spec `model_style` select `data_class` or `plain_class`. Empty uses the historical `data_class` default. Invalid CLI tokens/repeated flags are usage errors; invalid configured tokens are configuration errors. Core rejects unsupported styles before loading the document. A command-line style override requires one selected configured spec, like other generation overrides.

```bash
openapi-kt generate --input tests/fixtures/catalog.json --output build/generated/plain \
  --package-name org.example.plain --model-style plain_class
```

```toml
config_version = 1
[defaults]
model_style = 'plain_class'
[[specs]]
name = 'example'
input = 'specs/example.json'
output_dir = 'generated'
package_name = 'org.example.plain'
```

## API and wire contract

Default and explicit `data_class` have identical generated bytes and warnings. Plain style changes **class APIs**, not wire names, type bindings, constructor properties/default arguments, field getters, init validation, serializers or file ownership. DTOs, nested/request models, union payload/Unknown classes, hierarchy leaves, enum `Unrecognized`, and SSE data/id envelope classes use ordinary classes with explicit value methods instead of data classes.

Plain consuming classes have:

- The same public constructors/getters/serializer companions and checks.
- Explicit `equals`/`hashCode` over **constructor fields only**, in their existing order. Body constants, SSE event names and Unknown common-field fallback getters do not enter these methods, just as in the previous data classes.
- `toString()` returning the actual generated simple class name, without field values.
- **No generated `copy` or `componentN` methods.**

Known enum/union singleton data objects, zero-constructor const-only ordinary classes, sealed parents, typealiases, value classes and caller-owned classifiers retain their existing category. Const-only ordinary classes retain identity equality; singleton objects remain singleton objects. Runtime `Patch.Value` is a shared utility, not a consuming DTO: its helper body/API remains unchanged even when specs use different styles.

### Equality and hashing

Floating constructor fields use data-class value semantics, including nullable fields: NaNs compare equal, distinct NaN bit payloads use the usual canonical hash, and positive/negative zero remain distinct. Collections delegate to their ordinary equality/hash behavior. Arrays compare by **reference**, not contents; statically array-typed constructor fields hash their contents. Generic array hashing is shallow, not recursive deep-array equality.

Private hash overloads let Kotlin resolve array typealiases supplied by callers, rather than guessing external classpath types. An `Any` field holding an array still uses the ordinary identity hash; it must not be changed by runtime `is Array` dispatch. Provider value classes/objects retain their own equality/hash contracts. Serialized array round trips create new arrays, so model `equals` is not a wire-round-trip assertion: compare arrays with `contentEquals` or compare JSON trees.

## Migration and limits

Opt-in plain style intentionally removes deconstruction and `copy`; construct a replacement explicitly or continue using `data_class`. Code relying on the data-class pretty `toString` must also change. Do not claim call-site compatibility between these two styles. No new binary ABI shim is emitted. Style is selected before source emission on the typed plan, not by rewriting generated text.

This option alone does not implement deduplication, hoisting, merging or persisted name locks. It changes the available methods; it is **not** evidence of reduced Kotlin compilation time, memory, allocation or packaged size. Keep defaults when comparing correctness, then measure equivalent builds separately. Android/KMP/cross-platform and minimum-toolchain guarantees require their own executed verification.
