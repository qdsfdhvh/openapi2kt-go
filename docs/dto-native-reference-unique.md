# DTO native enum reference getter uniqueness

Under validation, ordinary DTO uniqueItems accepts fields referencing an
already-supported Int/Long/Float/Double/Boolean enum scalar. Existing direct
named/internal finite chains and root bridges keep their original reference
admission, actual scalar mapping, nearest nullable intent and membership/bounds
checks. This extends DTO getter equality, not general reference/type grammar.

Keys compare actual mapped values, including floating rounding and normalized
signed zero. Nonfinite floating keys reject. Own field defaults retain strict
original vocabulary membership before mapped equality; an omitted default and
an explicit equal scalar are duplicates at the second outer annotation value
Pointer. Required annotations validate before initializer suppression; target
and alias component factories are not inherited by consuming fields. Existing
nullable native enum and explicit null-vocabulary permissions remain opt-in.

The scalar reference proof retains the original chain, physical document path,
node/member identities, owners, aliases, type/check data and actual initializer.
Named native terminals additionally require their actual nativeEnumOrigins
export, original vocabulary, captured membership/check signature and retained
ScalarAlias/ValueAlias identity. Original planner declarations are recorded
before the first final barrier, so matching name/type bytes cannot substitute
a copied intermediate alias. Internal owners keep actual lexical model origin;
source trees are never copied or expanded to grant equality.

Capture work/bytes share the existing16,384/8MiB budget. Traversed reference/path
entries are charged and original node snapshots are memoized. Source48,
default-key16,384work, annotation16,384nodes/32KiB, member240/checked16/JVMslots240,
output ownership and name-lock identities retain their contracts. Missing or
cyclic references and malformed vocabularies/defaults retain original errors.
Other reference getter families, caller-native/const/value-class/composed or
nominal projections retain separate boundaries.

`bash scripts/test.sh feature dto-native-reference-unique` freshly generates
Data/Plain with baseline and validation plus combined optimized/locked output.
The unchecked control retains the prior primitive reference source where
nullable/internal native references require validation; the checked fixture
keeps full native vocabularies and nullable paths. Four Json settings exercise
native membership/default equality, named/internal/escaped bridge chains,
required/no inheritance, existing getter families, Patch, duplicate HTTP
responses and fragmented SSE failure/closure/reuse. An independent input
compiles240 native scalar reference getters with240 referring arrays. Source
tests mutate membership checks, actual exports/aliases, original nodes and
initializers and verify exact capture budgets/reuse. Native CLI failures
preserve old output; bounded fuzz verifies aliases, options, determinism and
omitted/explicit initializer keys. Wider graph/platform/final candidate gates
remain separate.

**Migration:** eligible DTO uniqueItems inputs with already-supported native
enum scalar references formerly rejected now generate under validation.
Existing accepted APIs, enum approximation/wire contracts and persisted formats
retain their rules.
