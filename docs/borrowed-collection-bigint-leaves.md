# Borrowed collections with named bigint leaves

Finite schema-internal List and typed Map segments and root container exports may end at original named `x-native-type: bigint` scalars or supported aliases. Native backing remains signed Kotlin Long. Original marker, canonical component/schema/Pointer, semantic node identity and one actual retained ScalarAlias or nullable ValueAlias export authorize the leaf. A caller-native `kotlin.Long` spelling or same-byte source copy does not grant bigint authority.

[Named bigint chains](bigint-reference-chains.md) supply the source role. Numeric containers and typed root bodies keep ordinary Long codecs: borrowed List/Map, Patch of a container, HTTP JSON root containers and SSE encode JSON numbers. A direct object scalar field or Patch of a scalar retains `LongAsStringSerializer` decimal strings. The helper belongs only to emitted declarations needing that field override; public scalar and container aliases do not own or carry the serializer. Existing decoder tolerance is unchanged; bigint is limited to signed Long rather than arbitrary precision.

Nearest explicit nullable/false intent remains path-local. Item/value and container nullability are independent; false narrowing keeps complete cached source work. Transparent bigint aliases introduce no nominal recursion barrier. Source48, checked collection16, work16,384 and serialized JVM slots240 remain unchanged. Collection/reference values take their existing boxed slots; separate probes do not establish combined maxima or additional platforms.

Container constraints remain opt-in at DTO/Patch.Value/HTTP preflight/postflight/SSE payload consumers. Bare List/Map codecs do not enforce counts. Shared optional null defaults and inline request required-nullable/Patch presence retain their contracts. Wrong JSON kind, null at non-null root and Long overflow fail through existing codecs. Structured query parameters keep existing projection. Fragmented SSE decoding/count failure or cancellation closes still-open input; subsequent cold collection and client reuse remain valid. Native generation failures preserve owned output.
