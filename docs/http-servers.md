# HTTP server defaults

The generator accepts `servers` on the document, Path Item and Operation, including URL variables with string defaults. HTTP and SSE use the same resolved prefixes.

## Selection and variables

An operation selects the first server from the nearest declared array: Operation → Path Item → document. An absent array inherits; a present empty array explicitly selects the default empty prefix. If no level declares a server, the existing empty-prefix behavior remains.

Each `{name}` in the selected URL is replaced with that variable's required string `default`. Repeated occurrences use the same default. An optional `enum` must be a nonempty string array containing the default. Variable maps are unordered; server arrays retain preference order. Descriptions are validated as strings.

Every server and variable is validated, including unused variables, later servers, overridden parent arrays and excluded APIs. Missing variables, unmatched braces, unsupported semantic fields, wrong types and invalid enum defaults fail at the original JSON Pointer. Template delimiters or CR/LF in defaults are rejected; replacements are not recursively interpreted. There is no runtime server picker or variable argument: callers select a different target with `basePath` or the final request callback.

Variable expansion has a **document-wide 8 MiB byte budget**, charged across all declared HTTP server URLs, including unselected and overridden sources. It prevents a small template from multiplying large defaults across servers or operations. Exceeding the budget returns `E_INPUT_LIMIT` at the closing server's `/url` Pointer before output IO. The existing input limit is unchanged.

## Kotlin override behavior

For inputs declaring only document-level servers, existing constructors and generated bytes retain their established shape:

```kotlin
val client = ApiClient(httpClient) // resolved document default
val other = ApiClient(httpClient, "https://example.test/custom/")
```

For inputs with a retained operation or path-level server, the aggregate constructor uses `basePath: String? = null`. A null argument selects each operation's resolved default. Any supplied non-null prefix, including `""` or a string equal to the document default, overrides all operation defaults. API group constructors accept the same nullable prefix; existing positional String calls remain valid.

```kotlin
val defaults = ServerScopeApiClient(httpClient)
val override = ServerScopeApiClient(httpClient, "https://example.test/custom/")
```

Equal defaults share one immutable internal helper file per API package. Helper identities depend on the resolved prefix, so multiple named specs can share identical helper bytes independently of client naming. No default URL is repeated in every method. The manifest owns helper files and removes obsolete ones using the existing ownership rules.

Normalization preserves the previous document-server contract: leading slashes are stripped, then a nonempty prefix gains a trailing slash even if it already had one. Thus `/v1` becomes `v1/`, while `https://example.test/api/` becomes `https://example.test/api//`. Relative prefixes still need caller configuration supplying a host. Explicit non-null constructor prefixes are used unchanged; callers supply their desired separator.

The final request callback can override the generated URL. Server variables do not change path-parameter segment encoding, parameter order, caller client ownership, plugin installation, success selection or SSE collection/cancellation behavior. There is no specification acquisition or network IO in generation.

## Verification

- [Core tests](../core/http_servers_test.go): variable and scope grammar, original Pointer, deterministic maps, shared defaults, exclusion, cumulative expansion limits and unchanged root-only shape.
- [Native CLI tests](../internal/cli/http_servers_process_test.go): generation/validate/check/no-op, shared named-owner helper bytes and failure preservation.
- [Synthetic input](../tests/fixtures/http/servers.json) and [fresh consumer](../samples/kotlin-http-smoke/src/main/kotlin/org/example/contracts/ServerContracts.kt): actual HTTP URLs, relative caller defaults, escaped path values, callback/direct-group/global overrides, cold SSE and still-open channel closure/reuse.
- `bash scripts/test.sh feature http-servers`: fresh Data/Plain × validation off/on with all four Json configurations. The `http` route includes the same consumer.

These contracts add server defaults and precedence within the existing HTTP/SSE subset. They do not establish all URI schemes, a runtime template API, platform support or complete OpenAPI HTTP validation. See [remaining work](remaining-work.md) for the separate parameter, media and composition gaps.
