# Reference chains to named collections

Finite typed internal/named reference chains and component-root bridges may terminate at original named arrays, typed dictionaries or JsonObject projections, including their accepted named aliases. New paths expose native List/Map/JsonObject backing with nearest explicit nullable true/false along the consumer-to-terminal path. Existing direct named collection declarations and aliases retain their output/wire contracts. This is a bounded F04/F07/M03 extension; borrowed internal collection roots remain separate.

Permission requires the actual unique original ValueAlias, original catalog/schema node/Pointer/source bytes and linked backing. Original TypeRef addresses and check objects remain shared through forward planning, rather than copied or expanded. Backing snapshots become final after all forward aliases have been linked, before late HTTP/SSE consumers. Missing/replaced/repeated declarations, same-byte copied source roots, mutated backing/check content or missing/repeated original inline item peers reject. Top-level Model/enum/union item peers keep their actual canonical package and constructor/serializer owners; a typealias cannot own new nested classifiers.

Incoming transparent hops and the original collection graph suffix count separately. The final canonical named edge is counted once; cached root aliases do not reset or double-count it. Deferred consumer provenance rechecks original suffix height after forward planning. Null wrappers add no source step. Depth 48, checked collection edges 16, work 16,384 and constructor/method slots 240 remain. Containers use one slot regardless of root nullability; nominal item declarations remain recursion/validation barriers while transparent collection cycles fail. Existing direct dictionary override behavior remains compatible; new path binding narrows the actual root backing only and retains nullable elements/values.

List/Map values use Kotlin collection construction and reified serializers; JsonObject remains object-only. Original inline item DTO constructors/serializers are available through canonical peers, not fabricated alias companions. Nullable containers, nullable elements, optional presence and request-only Patch states stay independent. Shared nullable fields retain default-null; inline request-required nullable fields have no default and optional inherited-nullable fields use Patch. Bounds and eligible scalar uniqueItems still require validation opt-in. Constructor/automatic serde, Patch.Value, typed HTTP pre/postflight and SSE data retain original container/leaf checks; bare alias assignment and independent collection serialization remain unchecked.

New named collection check objects receive the existing model emission hints after stable forward linking, including first late HTTP/union bindings. This retains private constructor checks for wide Map fields, with original shared check objects and no change to direct-only dictionary emission. The 240 Map-field probe checks construction/decoding and final-field leaf rejection.

Wide operations with at least 64 checked inputs emit private, non-inline input check functions, sharing only identical rendered types and generated checks. This keeps repeated container/leaf loops out of a single JVM method while preserving each input's preflight order, original checks, error labels, nullable handling and cold SSE timing. Public signatures and request callback order remain unchanged; small historical operations retain inline checks. The 240 checked Map-parameter and 239 checked SSE-parameter probes compile and assert final-input failure before callbacks or engine calls.

Root collection/null JSON wire behavior and erased method identity keep the existing numeric suffix allocator. New collection views qualify item peers in API/SSE packages. Structured query values still use Ktor `toString` projection with its existing warning. Fragmented SSE wrong-kind/null/syntax or constraint failure closes a still-open channel; cancellation closes the stream and subsequent cold collection/client reuse remains available. No reconnect or general recursive query encoding is added.

Original source grammar, required/default/count/item constraints, ref siblings and unused components remain validated. Semantic errors preserve original diagnostic Pointers and previous CLI output. Warning denial also preserves generated and unowned files. Collection spelling does not grant nominal shape borrowing or borrowed-container nominal-leaf permissions.
