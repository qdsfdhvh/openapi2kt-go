# Interrupted output transactions

The generator detects leftover `.openapi-kt-stage-*` entries in an output root and refuses to proceed with `E_RECOVERY_REQUIRED` (native CLI exit code 4). This is the supported interruption policy. It preserves the current generated files, manifest, naming-lock metadata, transaction journal and backups; it does not infer that a stage is safe to discard.

The rejection applies to direct generation and `--check`, configured full/partial/reconcile generation, named-owner batches, and direct/configured naming-lock state reads. Locked validation, explicit [disable/reset](name-lock.md#explicit-disablereset-lifecycle) action validation, and configured [owner rename](output-owner-rename.md) and [explicit root move](output-root-move.md) or [locked-owner adoption](ownership-migration.md#locked-owner-adoption) read/check/validate/apply also refuse such a root because they need the retained state. Ordinary unlocked validation does not inspect an output root and does not change it.

A stage entry is enough to trigger refusal: it may be empty, contain an old journal format, or contain a malformed journal. The detection does not deserialize untrusted recovery instructions, traverse backup paths or execute journal operations. The writer also replans under cooperative locks, preventing a stale pre-lock plan from ignoring an intervening transaction. Owner rename additionally compares exact manifest and every owned lock's bytes in preflight and under the complete sorted root lock set, and its metadata-only journal commits each manifest last while leaving Kotlin untouched.

On an ordinary commit failure the existing transaction restores old generated files and the manifest. On an obstructed rollback it still tries to restore other affected roots, retains the affected stage/journal/backups and returns the same recovery diagnostic. This is normal-failure rollback, not crash/power-loss atomicity across files or filesystems.

Keep the affected tree and its backups before investigating a manual restoration. There is no automatic `recover` command. Do not delete stages or change manifest versions merely to suppress the diagnostic; they may hold the only previous generated bytes or naming-lock state.

Coverage includes native direct/configured full/partial/reconcile/check and locked-validation refusal, malformed and retained journal contents, unchanged tree snapshots, output fault-injection rollback tests and locked/multi-root preservation. The executable tests are [native refusal](../internal/cli/recovery_rejection_process_test.go), [direct abandoned stage](../internal/cli/process_test.go), [batch failed rollback](../internal/output/batch_recovery_test.go), [single naming-lock failed rollback](../internal/output/name_lock_single_fault_test.go) and [owner lock batch preservation](../internal/output/name_lock_owners_batch_test.go). Rename-specific refusal and metadata rollback entry points are [output contracts](../internal/output/owner_rename_test.go) and [native CLI contracts](../internal/cli/owner_rename_process_test.go). This policy satisfies detection-and-rejection; [explicit complete root move](output-root-move.md) separately uses sorted source/target locks, exact owned byte/attribute CAS and normal-failure rollback while retaining recovery evidence. Partial/disjoint inventory moves and automatic recovery remain unimplemented. [Explicit same-root locked-owner adoption](ownership-migration.md#locked-owner-adoption) supports only a complete direct v3 tree and one named v4 owner with exact Kotlin/raw-lock preservation and retained recovery evidence.
