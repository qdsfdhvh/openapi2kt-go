# Finite reference chains to named byte/binary scalars

Typed internal references may follow finite `$ref`/nullable-only paths to an original named string byte/binary component or eligible alias. Component-root bridges and later named/internal chains retain original `kotlin.ByteArray` backing and source format, catalog Schema/Pointer and actual retained declaration identity. No DTO, value class, generated byte codec or nominal depth barrier is introduced.

## Source authority and transparent work

The original byte/binary format authorizes this source role; a caller-native ByteArray with identical Kotlin spelling remains a separate profile. The canonical source snapshot/node/Pointer and unique retained ScalarAlias or intrinsic nullable ValueAlias are rechecked. Missing, replacement, duplicate original occurrences, changed format/source and copied nodes cannot authorize a chain. First HTTP/union uses take the same shared resolver and final authority path.

From consumer to terminal along the real path, nearest explicit nullable true/false wins; absent inherits cached suffix and intrinsic intent. A root override before a hop differs from a hop before a root. False uses real non-null ByteArray, with complete named/internal source work preserved. Source depth 48, work 16,384 and slot cap 240 remain; ByteArray references consume one JVM slot in either view. Depth, model width and HTTP/SSE method width inputs are tested independently.

## JSON arrays versus raw HTTP

Model fields, list/map elements, Patch.Value and SSE data use the builtin signed numeric-array JSON serializer. Nullable reified serializers and ByteArraySerializer nullable adapters retain existing null/range/kind/null-element handling. There is no typealias companion `.serializer()` or generated byte helper. ByteArray values are compared by content or serialized JSON tree, including DTO/union round-trips and copy where available.

Ktor root request/response bodies remain raw bytes even with application/json. A null root request sends ASCII `null`; a response containing those bytes is a non-null byte array, not Kotlin null. Malformed JSON bytes remain raw HTTP data. This behavior differs from model/Patch/SSE payload decoding and is verified separately; the new chains do not turn roots into Base64 or nullable JSON-array HTTP round trips.

Fragmented still-open SSE streams decode signed arrays/null, reject malformed/range/null-element/non-null payloads, close on failure/cancellation and preserve cold-flow reuse. Automatic reconnect/resume remains outside the generator subset.

## Migration, boundaries and checks

Previously rejected named byte/binary chains now emit native ByteArray aliases. Original negative inputs remain as explicit native-backing positive graduations; no historical fixture bytes are rewritten. Existing direct profiles and generated output/reports remain unchanged.

Only original named byte/binary sources gain this role. Caller-native ByteArray, borrowed internal byte leaves, raw/true/recursive carriers and shape borrowing retain separate contracts. The full existing format/scalar grammar still rejects unsupported keywords at original source Pointers. Borrowed collection trees do not gain named terminals incidentally.
