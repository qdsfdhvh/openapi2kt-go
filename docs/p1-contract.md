# P1: JSON model-generation contract

[Output ownership](output-ownership.md) distinguishes current native CLI version1 single-owner writes from the internal version2 named-owner transaction foundation. The additive [local configuration envelope](configuration.md) now connects local TOML `--config`/`--spec` generation to version2 ownership, with normal-failure disjoint-root batch rollback but without automatic migration/crash atomicity. [Shared runtime_package](runtime-package.md) relocates existing Patch/bigint utilities without changing their codecs or default output. [Explicit exact-match v1 ownership migration](ownership-migration.md) is available; it changes metadata only and requires a selected spec and `--adopt-legacy`. [Explicit complete root move](output-root-move.md) separately copies existing v1–v4 owned output to a concrete destination with byte/attribute/ownership preservation, source/target locks and CAS; partial/disjoint config inventory moves and v3-to-v4 remain outside it. Default core generation and legacy direct output are unchanged.

[CLI metrics](cli-metrics.md) are opt-in report metadata for read/generate/warning-policy/check-or-commit, nested options/parse/analyze/transform/emit boundaries, planned output size and available Darwin/Linux process-lifetime peak RSS. Core options and Kotlin/artifact/manifest hashes remain unaffected; failures retain actual entered phases. Default reports have no metrics, and core subphases are not independently timed.

The independent [CLI warning policy](warning-policy.md) adds opt-in `--deny-warnings`/repeatable exact `--allow-warning CODE` to generate/validate/check. Unallowed successful-generation warnings fail with `E_WARNING_DENIED`, exit 1, original Pointers and all warnings retained, before output IO; core/default generation and Kotlin output are unchanged.

[Own-nullable raw root aliases](model-semantics.md#root-nullable-raw-aliases) separately bind accepted non-null final empty ordinary Models, preserving raw JsonElement identity, source budgets, nullable/false typed intent and request presence. Nullable codec carrier collapse is documented; [intrinsic nullable raw components](model-semantics.md#intrinsic-nullable-raw-components) separately admit direct empty ordinary JsonElement? roots with real backing narrowing. Neither profile admits intrinsic hierarchy/union roots or arbitrary graph normalization.

[Intrinsic nullable builtin primitives](model-semantics.md#intrinsic-nullable-builtin-primitives) separately admit direct ordinary String/Boolean/Int/Long/Float/Double nullable roots and aliases to those targets, preserving builtin backing/nearest intent, original source work and opt-in typed checks. Bare aliases/codecs are not validation barriers; root String HTTP retains raw-text null behavior. Non-null scalar-ref opt-in is unchanged; [own-nullable aliases to non-null primitive targets](model-semantics.md#own-nullable-builtin-primitive-aliases) have their separate transparent backing/source/typed-check contract.

> Contract for the initial model-only implementation. Implemented extensions are recorded in [model semantics](model-semantics.md). Executable coverage lives in `core/*_test.go`, `internal/cli` process tests, `internal/output` transaction tests, and the [Kotlin smoke](../samples/kotlin-smoke/README.md). The broader roadmap remains in [development-plan.md](development-plan.md).

## Scope

P1 defines Kotlin serialization **models only** from a single local JSON document. The additive [bounded YAML adapter](yaml-input.md) now loads into the same ordered tree and analysis/emission pipeline. An additive [HTTP subset](http-client.md) now generates clients for supported operations without changing model-only artifacts. The additive [SSE subset](sse.md), [simple value classes](model-semantics.md#simple-primitive-value-classes), [wrapper bounds](model-semantics.md#primitive-value-class-bounds) and [opt-in DTO bounds](model-semantics.md#opt-in-dto-field-bounds) / [ordinary DTO JSON property counts](model-semantics.md#ordinary-dto-json-property-counts) are now available. Initial [shared-root hoisting](hoist-models.md) moves repeated same-role ordinary DTO/enum roots to models with exported API aliases and explicit shared-package migration. Initial [operation-model deduplication](deduplicate-models.md) folds equivalent ordinary DTO/enum roots into aliases with explicit identity/nested-classifier migration; general model merging remains outside this subset. An opt-in [plain model style](model-style.md) removes data-class copy/component APIs while retaining constructor-field value equality/hash and wire behavior. The [file/stdin boundary](local-input.md) keeps acquisition in external tools; the old downloader/configuration metadata are removed without changing the pure core or generated Kotlin. Complete HTTP/SSE capabilities and broader multi-spec configuration beyond the local configuration envelope, remaining request-only presence contexts, general fixed/mixed/nullable discriminator hierarchies, broader validation/value classes and model-size optimizations remain later milestones. Direct dictionaries are an implemented [model extension](model-semantics.md#dictionaries).

Reject unsupported semantic constructs with a diagnostic rather than silently dropping them. Nonempty `paths` are analyzed by the separate HTTP subset; unsupported operation semantics or paths containing no operations are rejected. An unsupported declared component schema is an error even when unreferenced.

### Inputs and models

- OpenAPI version `3.0.x` or `3.1.x`; object root and non-empty `components.schemas` for model-only inputs. Supported HTTP documents may omit components.
- The [special scalar subset](special-scalars.md) supports direct dates/Instant/ByteArray/native-bigint/JsonNull mappings; bigint field encoding differs from container/root encoding and root ByteArray travels raw through Ktor.
- Primitive components now generate transparent typealiases, with primitive references inlined through the shared scalar resolver; see the [extension contract](model-semantics.md#primitive-components). [Array components](model-semantics.md#array-components) independently generate native collection aliases with top-level item peers, original typed checks and named consumers. [Nullable array roots](model-semantics.md#nullable-array-components) inherit nullability through direct/ref-wrapper uses; explicit false exposes a qualified non-null backing collection, retaining item nullability and checks without extra exported aliases. Shared default-null versus inline request required/Patch policies remain context-specific.
- Named object schemas with properties; string, boolean, integer/int32/int64, number/float/double, arrays with declared items, local named-object references, and nested object properties.
- Explicit typed/open dictionaries use `Map<String, T>` / `JsonObject`, including component aliases, nullable roots/values and nested value declarations. Fixed-field extras are not collected; closed/extra-value restrictions are not runtime validation. See the [dictionary contract](model-semantics.md#dictionaries).
- `nullable: true` and a 3.1 single-type-plus-null type array. Multiple non-null types are deferred. Nested single-non-null-plus-null `oneOf`/`anyOf` now share nullable normalization; see the [extension contract](model-semantics.md#nullable-composition-fields).
- Required non-null properties have no default. Optional properties use nullable types with `= null`. Component nullable properties use `= null` in this model-only slice; this is not a request-body presence contract.
- Array-item nullability is separate from array nullability. References to object components may be recursive without recursively expanding declarations. The independent [terminal scalar schema Pointer subset](model-semantics.md#terminal-scalar-schema-pointers) borrows builtin component-internal leaves for typed consumers, with original source checks and explicit true/false nullable overrides; the additive [finite List/typed Map target profile](model-semantics.md#finite-collection-schema-pointers) preserves the same borrowed identity with direct nesting and terminal-only internal scalar-ref children. [Finite internal scalar reference chains](model-semantics.md#internal-scalar-reference-chains) and [finite collection reference chains](model-semantics.md#internal-collection-reference-chains) are separately supported. The latter admits finite nested collection refs while retaining source, nullability and cumulative budgets. Those borrowed profiles do not add internal nominal targets. Separately, [ordinary object root aliases](model-semantics.md#root-object-aliases) preserve an exported native typealias while typed uses share the canonical DTO identity/serializer. Every alias hop counts toward schema depth; target validation and source errors remain original. [Collection root aliases](model-semantics.md#root-collection-aliases) preserve canonical native List/Map/JsonObject targets, nearest true/false/absent root intent and original checks/peers/source budgets. Root-bound nullable maps can expose genuinely non-null backing views; direct historical dictionary false behavior is unchanged. [Special root aliases](model-semantics.md#root-special-aliases) additionally preserve accepted non-null enum/valueclass/native/const targets, their original wire/checks/defaults and const early-exit source budget. Bare builtin scalar aliases remain validation-opt-in. [Non-discriminator union root aliases](model-semantics.md#root-union-aliases) retain canonical root serializers/variant owners, Unknown/null/closed wire and complete source hops. [Hierarchy root aliases](model-semantics.md#root-hierarchy-aliases) preserve canonical parent/leaf/mapping identities, inherited tag owners and erased graph-edge work, diagnosing duplicate canonical children. [Raw root aliases](model-semantics.md#root-raw-aliases) retain empty-object JsonElement projection and transparent method erasure; use the JsonElement serializer rather than an invented DTO constructor. [Nullable ordinary DTO root aliases](model-semantics.md#root-nullable-object-aliases) retain nearest true/false intent, typed consumer overrides and canonical constructors/checks; reified serialization or the canonical nullable adapter handles null, while the alias companion remains non-null. [Intrinsic nullable direct DTO components](model-semantics.md#intrinsic-nullable-dto-components) retain the physical canonical data class while typed uses inherit or explicitly narrow root nullability. [Nullable plain String-enum aliases](model-semantics.md#root-nullable-string-enum-aliases) preserve canonical vocabulary/serializer ownership and typed nullable intent. [Intrinsic nullable plain String enums](model-semantics.md#intrinsic-nullable-string-enums) also preserve physical vocabulary/serializer ownership while typed uses inherit root intent. [Own-nullable primitive value-class aliases](model-semantics.md#root-nullable-value-class-aliases) preserve canonical constructors/bounds and primitive wire; nullable Long/Double uses are boxed, narrowed required uses retain two slots. [Intrinsic nullable primitive value classes](model-semantics.md#intrinsic-nullable-value-class-components) independently preserve non-null physical wrappers and typed inherited/false-narrowed intent. [Own-nullable temporal aliases](model-semantics.md#root-nullable-temporal-aliases) separately preserve accepted non-null date/date-time/date-native targets and canonical ISO serialization with nearest nullable/false intent. [Intrinsic nullable temporal components](model-semantics.md#intrinsic-nullable-temporal-components) export transparent nullable native roots with inherited/false-narrowed typed intent; source work is not nominalized. [Own-nullable bigint aliases](model-semantics.md#root-nullable-bigint-aliases) independently preserve canonical Long roots/nearest intent, string field/Patch versus numeric root/containers and boxed/required slot accounting. [Intrinsic nullable bigint components](model-semantics.md#intrinsic-nullable-bigint-components) separately export transparent Long? aliases, inherited/false intent and original source/noDrop accounting with unchanged field-string/root-number codecs. [Own-nullable byte/binary aliases](model-semantics.md#root-nullable-bytebinary-aliases) preserve signed-array JSON model/Patch/SSE codecs and legacy raw Ktor roots; response bytes `null` are not Kotlin null. [Intrinsic nullable byte/binary components](model-semantics.md#intrinsic-nullable-bytebinary-components) independently retain the same projection with transparent public ByteArray? roots/inherited-false intent/original noDrop source accounting. [Native JSON classifier erasure](model-semantics.md#native-json-classifier-erasure) separately unifies accepted canonical caller-native JsonElement/JsonObject HTTP signatures with builtin JSON projections and assigns ordinary suffixes to previously uncompilable collisions; nominal type and wire policies remain unchanged. [Own-nullable caller-native aliases](model-semantics.md#root-nullable-caller-native-aliases) independently retain provider-owned classifiers/codecs and nearest nullable/false intent; API members and wire are not inferred from the native marker. [Intrinsic nullable caller-native components](model-semantics.md#intrinsic-nullable-caller-native-components) separately export transparent nullable provider roots with inherited/false typed intent and unchanged source/shape-borrowing boundaries. Other root binding profiles remain unsupported.
- Typed or typeless string enums now use an open sealed class and custom serializer, including component and inline forms; see the [extension contract](model-semantics.md#open-string-enums).
- Inline object unions use nested variants, tag/required-key dispatch, const-only singletons and Unknown raw passthrough; see [inline object unions](model-semantics.md#inline-object-unions). [Standalone root object unions](model-semantics.md#standalone-root-object-unions) have a separate implemented policy; [Typed discriminator hierarchies](model-semantics.md#typed-discriminator-hierarchies) have another implemented policy; general fixed/mixed hierarchy contexts remain deferred; canonical root aliases have their separate contract.
- Typed local discriminator graphs generate top-level inheritance, peer string enums, required hierarchy enum constructors and per-custom-layer raw Unknowns, with explicit/inferred/default-polymorphic caller differences. General fixed/mixed contexts remain deferred; see [typed hierarchies](model-semantics.md#typed-discriminator-hierarchies).
- Inline primitive unions use sibling JSON-kind wrappers and at most one structured object; component roots have a separately verified [named kind/null contract](model-semantics.md#root-json-kind-and-nullable-unions), including strict null singletons and closed nullable-polymorphic object roots. See [inline primitive unions](model-semantics.md#inline-primitive-unions).
- [Primitive-union normalization](model-semantics.md#primitive-union-normalization) preserves nested open-enum vocabularies, uniform scalar/range width and source-located constraint approximations, and validates distinct-kind enum/const pins before native payload projection; it does not enable root scalar folds or runtime membership/constraint enforcement.
- Typed numeric/boolean inline enums and component aliases/refs retain native scalar wire types, with membership approximation warnings; see [native inline enums](model-semantics.md#native-inline-enums).
- [Scalar value projections](model-semantics.md#scalar-value-projections) retain native root/item const aliases and always-encoded body defaults through const component refs, with explicit root/item membership approximation and native enum migration contracts.
- Scalar const properties now use non-null body defaults and always encode, including ordinary const-only plain classes; see the [extension contract](model-semantics.md#scalar-const-fields).
- Object `allOf` merges and annotation-only field reference wrappers now use source-aware resolution with approximation warnings; see the [extension contract](model-semantics.md#object-allof-composition).
- `@Serializable` models with `@SerialName` preserving wire keys. Preserve property declaration order; sort files and other unordered symbol inventories deterministically.
- Empty object components become `typealias ... = JsonElement`; empty nested objects and unconstrained `{}` properties use `JsonElement`. This deliberately permits more JSON values than an object-only schema and does not validate object shape. No zero-parameter data class is emitted.
- Unconstrained/nullable component roots outside the named union, array/dictionary or direct ordinary nullable DTO entries, general fixed/mixed/nullable discriminator hierarchies and general composition, non-scalar const contexts/default values, dictionary composition/common-union projections, schema constraints beyond the opt-in bounds subsets, formats/extensions outside the [special scalar subset](special-scalars.md) are deferred and diagnosed, not silently flattened. String `uuid` maps to `kotlin.uuid.Uuid`; see the [mapping and migration](nullable-uuid.md).
- Ignore descriptive metadata (`title`, `description`, `example(s)`, external documentation) without interpreting payload keys as schema keywords. Schema text annotation slots must be strings and `deprecated` a boolean; examples remain opaque data. Unknown schema keywords that could affect semantics must not silently disappear. `readOnly` and `writeOnly` select which fields a request or response carries. [`readOnly`](read-only-fields.md) is honoured where a dedicated request model exists: an inline request body projects the field as `Patch.Absent`, so a request omits it by default while staying overridable. A `$ref` request body reuses the component model shared with responses, so there it is accepted and inert. `writeOnly` remains **rejected** by the `unsupported-writeonly` corpus fixture, because dropping a field from responses needs the mirror projection and responses reuse the same model.
- External or missing references, malformed required lists, invalid schema-slot types, duplicate JSON keys, and naming collisions are errors. JSON syntax diagnostics must not echo the input payload.

Inputs are limited to 8 MiB; the strict decoder accepts at most 127 simultaneously open JSON containers, and schema traversal permits at most 48 levels. Models are limited to 240 serialized-field JVM slots (non-null Long/Double consume two); this reserves space for generated serialization and default-argument parameters. Const body properties consume no primary constructor slots but still count toward the serialization constructor budget. Wider models return `E_MODEL_LIMIT`. These independent analysis budgets are not a guarantee that every width/depth combination compiles on Kotlin/JVM: very wide, deeply nested generic collection signatures can exceed compiler/class-file resources even for direct schemas. Independent shallow-wide and single-field-deep compilation checks do not establish Cartesian worst-case compilation or platform/performance guarantees; that combined resource limitation remains open.

Naming and Kotlin literal escaping are centralized. Components use PascalCase plus the optional suffix. Existing ASCII property identifiers (including underscores) are preserved; other names normalize to lower camel case, digit-leading names gain a prefix, and Kotlin keywords are backticked. Wire keys always remain in `@SerialName`. Model/property names without ASCII letters/digits are rejected. Their collisions are errors, not silent renames. Enum member spellings have a separate uppercase/operator/Unicode naming and collision-suffix contract in [model semantics](model-semantics.md#input-and-naming-limits). Nested models are scoped inside their owner; component references are fully qualified to avoid shadowing.

Output paths derive from validated ASCII Kotlin package segments. Keywords, the reserved `kotlin` namespace, path traversal and platform-reserved basenames are rejected. Component filenames are compared case-insensitively; property collision checking is also conservatively case-insensitive.

## Core interface

The Go module is `openapi-kt`, with public package `core` and command `cmd/openapi-kt`; binary name `openapi-kt`. Public Go module publishing coordinates remain undecided. The project uses [MIT](../LICENSE); product releases follow the [versioning policy](versioning.md). Internal packages are not a stable public API.

The core public carriers and entry points are:

```go
type GenerationOptions struct {
    PackageName string
    RuntimePackage string   // Existing Patch/bigint helper package; empty uses models
    ModelStyle ModelStyle  // Empty/DataClass: historical APIs; PlainClass: explicit value methods
    DeduplicateModels bool // Initial operation-local ordinary DTO/enum roots only; default off
    HoistSharedShapes bool  // Repeated same-role roots to models, exported API aliases; default off
    QualifyHoistedNames bool // Keep owner-qualified shared name; requires hoisting
    LockHoistedNames bool // Initial name state; requires hoisting; core remains IO-free
    ModelNameSuffix string
    APIClientName   string   // HTTP extension; empty means title-derived
    ExcludeAPIs     []string // HTTP extension; exact API class names
    Validation      bool     // DTO/ref/element/container bounds and DTO JSON counts; default false
}
type GenerationRequest struct {
    Document []byte
    Format InputFormat // core.Auto, core.JSON or core.YAML
    SourceName string
    Options GenerationOptions
    PreviousNameLock []byte // Nil fresh state; nonnil strict versioned state requires locking
}
type GeneratedFile struct {
    Path string // validated slash-separated relative path
    Content string
}
type GenerationArtifacts struct {
    Files []GeneratedFile
    NameLock []byte // Nil default; canonical metadata when locking; not a Kotlin artifact
}
type Diagnostic struct {
    Code string
    Message string
    Pointer *string
}
type Diagnostics []Diagnostic // implements error

type GenerationReport struct {
    Artifacts GenerationArtifacts
    Warnings []Diagnostic
}

func Generate(request GenerationRequest) (GenerationArtifacts, error)
func GenerateWithDiagnostics(request GenerationRequest) (GenerationReport, error)
```

Structured errors are `core.Diagnostics`; use `errors.As` to inspect them. Callers must not mutate document bytes concurrently with generation. `Generate` returns only artifacts; callers needing non-fatal analysis warnings use `GenerateWithDiagnostics`. Both functions produce identical files. An error returns no report or partial artifacts. Warnings have stable `W_` codes and original JSON Pointers; messages do not echo schema values or source filenames. Warning order is deterministic: sorted components and declaration-order analysis. Nullable-fold warnings follow child resolution; object-merge warnings follow overridden-field validation and precede resolution of final fields. The current warning contracts are:

- `W_ADDITIONAL_PROPERTIES_APPROXIMATION`: fixed-field DTOs do not collect extra keys or enforce extra-value restrictions; empty closed objects use `JsonObject` without enforcing emptiness. The pointer identifies the original `additionalProperties` keyword.
- `W_BOOLEAN_SCHEMA_PROJECTION`: the [initial3.1 direct true value profile](boolean-values.md) and separate [named true component roots](boolean-roots.md) project admitted value slots/roots to unconstrained JsonElement including JsonNull. Optional fields keep existing `{}` presence; no implicit Patch or general Boolean composition support; named roots have their own reference/exclusion contract. The original literal Pointer identifies the source.
- `W_JSON_ELEMENT_APPROXIMATION`: an empty **object** schema maps to `JsonElement`, which can also carry non-object JSON. A truly unconstrained `{}` is not this approximation and does not warn.
- `W_OBJECT_UNION_APPROXIMATION`: object unions use tags/key presence, standalone-root default sealed polymorphism or typed hierarchy field/class-discriminator dispatch rather than exact oneOf match-count validation.
- `W_UNION_UNREACHABLE_VARIANT`: no generated tag/exclusive-required-key branch selects the original variant; content dispatch uses Unknown, while a default-polymorphic root instead requires a class discriminator.
- `W_PRIMITIVE_UNION_APPROXIMATION`: same-kind scalar folding or distinct-kind dispatch uses a generation mapping, not exact oneOf match-count validation; integer/number wrappers use Long/Double.
- `W_UNION_CONSTRAINT_APPROXIMATION`: a supported uniform nested primitive/free-string branch constraint is validated then not enforced; its original keyword pointer is retained.
- `W_PRIMITIVE_UNION_PIN_APPROXIMATION`: a distinct-kind primitive enum/const pin is validated but its native union payload serializer does not enforce membership; its original pin pointer is retained.
- `W_HTTP_REQUEST_UNION_PROJECTION`: a nullable nominal request union keeps its declaration non-null; requestBody.required controls parameter nullability and the Unknown peer can carry raw JSON null. Primitive/array branches in root request unions instead become unreachable empty singletons encoding `{}`; use Unknown for their actual raw payloads. This context does not use component primitive-union wrappers.
- `W_HTTP_PARAMETER_PROJECTION`: a structured parameter/filter value uses delegated Ktor `toString`, not recursive encoding or enum-map unwrapping; raw parameter unions do not validate membership.
- `W_HTTP_FILTER_UNION_PROJECTION`: an inline filter field uses raw JsonElement rather than primitive payload wrappers, retaining ordinary model defaults and no Patch.
- `W_HTTP_FIELD_UNION_PROJECTION`: a validated request-only field/list-element/map-value union uses raw JsonElement, without native payload wrappers or membership validation. Existing nullable/default/Patch rules apply; component and ordinary root-union field policies are unchanged.
- `W_HTTP_VALUE_PROJECTION`: fixed-field objects below simple HTTP containers use raw JSON maps rather than typed DTO properties, defaults or field validation. This does not change model-property generation.
- `W_HTTP_RESPONSE_PROJECTION`: a multi-branch HTTP response union is exposed as raw JsonElement, without generated variants or union-membership validation. The bounded response empty-union policy also reports each projected empty branch, yielding Unit or a nullable single object/ref when applicable. It does not alter model-property or request-body union handling.
- `W_ENUM_NATIVE_APPROXIMATION`: typed numeric/boolean inline and component/ref enums, and HTTP simple-operation string enum projections (including supported nullable/open-enum union folds), use native scalar handling rather than enum-membership validation.
- `W_CONST_SCALAR_APPROXIMATION`: scalar const root/item value projections retain native serializers without literal-membership enforcement. Object fields referencing const components instead retain body-default semantics.
- `W_ALL_OF_APPROXIMATION`: object members are merged with later property overrides and combined required names, not exact intersection validation. Original composition pointers are retained, including referenced definitions.
- `W_ONEOF_NULL_OVERLAP`: nullable folding of a `oneOf` with multiple plain null branches does not enforce the exact match count. `anyOf` does not have that exclusive-match limitation.

Warnings originate in the shared analyzer, not a scan of example/default/const payloads. They do not establish support for otherwise rejected schemas or complete JSON Schema validation.

Diagnostics support JSON serialization with `code`, `message` and optional `pointer` fields. An absent pointer is omitted; a pointer to an empty string identifies the document root. Internal normalization/type/emission representations stay private. No core filesystem writes, environment reads, subprocesses, or network requests.

`Auto` uses the source extension, or JSON parsing for an extensionless source (including stdin). `.yaml` / `.yml` selects the [bounded YAML adapter](yaml-input.md); unknown extensions require an explicit format. Explicit `JSON` parses bytes as JSON; parsing failure must not trigger YAML fallback. Explicit `YAML` also accepts JSON syntax under the YAML profile. `SourceName` is for format detection, not for embedding machine-specific paths into generated code.

## CLI contract

```text
openapi-kt generate --input <file-or-> --output <directory> --package-name <package>
openapi-kt generate --input <file-or-> --output <directory> --package-name <package> --check
openapi-kt validate --input <file-or-> [--package-name <package>]
```

Both commands accept the bare boolean `--validation` to opt into DTO, [primitive-ref](model-semantics.md#primitive-alias-validation), [collection-element bounds](model-semantics.md#primitive-collection-element-validation), [typed container counts](model-semantics.md#typed-collection-counts) and [bounded scalar uniqueness](model-semantics.md#bounded-scalar-uniqueness), plus [ordinary DTO JSON property counts](model-semantics.md#ordinary-dto-json-property-counts) (default false; no `=true/false`, value or repetition), `--input-format auto|json|yaml`, `--diagnostic-format text|json`, and the HTTP extension's `--api-client-name` and repeatable `--exclude-api` options. `generate` additionally accepts `--model-name-suffix`. Validation uses a neutral internal package if no package was supplied and does not write files.

Exact `--input -` selects caller-owned stdin: bounded 8 MiB plus one detection byte, read until EOF before analysis/output, auto JSON, same parser/policy/metrics/check/name-lock semantics as files. It is never closed and is untouched on help/argument errors or ordinary file input; `./-` remains a literal file. Read errors are `E_INPUT_IO`, oversized input `E_INPUT_LIMIT`; failures preserve output. The [local configuration flags](configuration.md) remain, but configured `input = '-'` is rejected and no stream replay is provided. The removed download command returns usage errors; old download tables fail rather than being ignored. See [input/migration contract](local-input.md). Exit codes: 0 success, 1 input/config/generation error, 2 CLI usage error, 3 check differences, 4 input/filesystem/output failure.

In JSON mode, emit one JSON document to stdout for command results; human progress belongs on stderr. Successful `generate`, `validate` and read-only `--check` results include a separate `warnings` array when non-empty; `diagnostics` remains the error list. Warning-free results retain the original JSON shape. Text warnings go to stderr with control characters in pointers escaped; stdout still contains the success/difference summary. Warnings do not change exit codes or file contents. Failed generation/output transactions report errors rather than a successful warning report. Errors contain stable codes and safe messages, not source payloads or raw OS errors containing full paths.

Ordinary DTO counts are serializer-owned, not constructor/copy checks: incoming raw members count before defaults/unknown loss, outgoing actual delegated JSON members count under caller configuration. The JSON-only opt-in retains the automatic descriptor/delegate via experimental `KeepGeneratedSerializer` / `generatedSerializer()`; non-JSON codecs reject, even for min=0. HTTP callbacks can precede outbound rejection, but invalid encoding prevents dispatch; SSE counts JSON data through its separate Json and closes failed live input. Inherited/union/reference-composed/count-only empty or const-only models and discarded projections remain unsupported. See the model contract for migration, toolchain and AST/error limitations; historical unconstrained output is unchanged.

Opt-in [flat inline allOf primitive-bound aggregation](model-semantics.md#flat-inline-allof-primitive-bounds) adds conjunction only for eligible repeated direct ordinary-model properties, preserving the winning signature/presence and existing approximation warnings. Four independent numeric categories and identical parsed patterns/exact factors are bounded; refs/nested composition/union/common/hierarchy/collections do not gain primitive aggregation. [Flat inline ordinary DTO counts](model-semantics.md#flat-inline-allof-dto-property-counts) independently fold whole-object bounds in member order then root, after all sources pass local grammar/interval checks; empty intersections retain the original closing-keyword Pointer. Existing output without a new eligible group stays byte-identical; this is not complete schema validation.

## Output ownership

- Generate and validate all artifacts before mutation.
- Versioned manifest records the exact generated relative paths and hashes for this single output owner.
- Reject unsafe paths, symlink escapes, duplicate/case-insensitive conflicting paths, malformed manifests, unowned destination collisions, and modified owned files rather than deleting user edits.
- Preserve unowned files and remove only stale manifest-owned files. A renamed package cleans its previously owned files.
- Stage writes and retain rollback information until manifest commit succeeds. On recoverable commit failure, restore prior generated files and manifest. Do not claim power-loss or multi-filesystem crash atomicity.
- Serialize writers to a given output root; do not add a long-running daemon.
- `--check` compares generated contents, stale owned files and manifest state without creating/changing the output root or its contents.
- A no-change successful run leaves generated-file mtimes unchanged.

The default single-owner manifest is `.openapi-kt-manifest.json`, with `version: 1` and a relative-path-to-SHA-256 `files` map. The [internal single-owner name-lock adapter](name-lock.md#initial-internal-single-owner-output-transaction) separately uses version3 with a fixed metadata hash; ordinary/named-owner entry points reject that version; explicit [disable/reset](name-lock.md#explicit-disablereset-lifecycle) uses the guarded metadata transaction and a migration report, with direct version3-to-version1 allowed only by disable. The explicit [internal named-owner adapter](name-lock.md#initial-internal-named-owner--multi-root-transaction) separately supports version4 per-owner metadata and normal multi-root rollback, not automatic version3 migration; [explicit exact single-owner v3→v4 adoption](ownership-migration.md#locked-owner-adoption) preserves the same-root Kotlin inventory and raw lock through metadata-only CAS/journaling. Opt-in `--lock-hoisted-names`/config `lock_hoisted_names` route through these transactions; neither relaxes Kotlin path validation. Locked validation reads existing state without writing; it needs the matching output root and profile. A persistent `.openapi-kt.lock` coordinates cooperative CLI writers through nonblocking OS file locks (`flock` on supported Unix hosts and `LockFileEx` on Windows). A busy root fails with `E_OUTPUT_BUSY` rather than waiting indefinitely. Output directory arguments containing `..` are rejected. The output root itself and generated entries/parent directories inside it cannot be symlinks; ancestors above the explicitly selected root use normal filesystem resolution.

Transactions stage under `.openapi-kt-stage-*` on the output filesystem. `transaction.json` records destination paths, backup/staged filenames, and whether each destination previously existed. An ordinary commit failure rolls back; if rollback itself fails, backups remain. A leftover stage directory causes `E_RECOVERY_REQUIRED`: inspect and preserve its journal/backups before any manual recovery. There is no automated recovery command yet. Do not simply delete backups to silence this error.

Safety errors (including modified owned files, unowned collisions and malformed manifests) return exit 4 in both generation and check modes; safe differences return 3 in check mode. Checks do not acquire/create the writer lock or mutate any output entry. They are a point-in-time comparison, not a snapshot guarantee against concurrent external changes. Locking coordinates cooperating writers; it is not a security boundary against concurrent hostile filesystem mutation.

## Verification

Core tests cover the public interface with supported synthetic inputs and negative cases. CLI tests execute the actual binary and check exit codes, diagnostics, cross-working-directory determinism, `--check`, unowned-file preservation, changed generated files, stale files, invalid JSON/YAML, and output escape attempts. Checks are tested with absent and busy writer locks, and safety errors are exercised in both generate and check modes. Transaction failure injection covers replacement, creation, stale removal, manifest commit, and backup retention when rollback cannot finish.

A minimal Kotlin/JVM smoke check compiles freshly generated files using the serialization compiler plugin when templates first land or materially change. It must not use handwritten replacements for generated classes. Routine P1 verification primarily uses Go tests and reviewed generation snapshots; ordinary DTO round-trip tests are deferred. Generated string-enum custom serializers, primitive alias/reference extensions nullable composition fields and scalar const body properties and object allOf merges have runtime serialization tests; Patch and union serializers will require corresponding runtime coverage when implemented. Initial compilation evidence covers the actual toolchain used, not an untested minimum-version promise.

No license selection, package publication, Git initialization, or release automation is part of this slice.
