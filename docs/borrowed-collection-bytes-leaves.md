# Borrowed collections with named byte leaves

Finite internal List/typed Map segments and root container exports may end at original named `string` byte/binary scalars and supported aliases. Native backing remains ByteArray. Original format/schema/Pointer/canonical owner, semantic node identity and one actual retained ScalarAlias or nullable ValueAlias authorize the leaf. A caller-native ByteArray spelling or same-byte source copy cannot grant this source role.

[Named byte reference chains](bytes-reference-chains.md) supply source authority. ByteArray nested in List/Map/Patch-container/DTO and SSE uses signed numeric arrays, such as `[[-128,-1,0,127],null]`. A borrowed List/Map HTTP root is still a container and uses JSON. A standalone ByteArray Ktor root keeps raw bytes: a null request sends ASCII `null`, and a response with those four raw bytes returns that array rather than Kotlin null. No Base64 or custom byte codec is introduced. Freshly decoded arrays must be compared by content or encoded JSON rather than array identity; existing mutability and copy behavior remain.

Nearest explicit nullable/false intent remains path-local and separate for container and item/value. False narrowing retains complete cached source work. Transparent aliases are not nominal recursion barriers. Source48, checked collection16, work16,384 and serialized JVM slots240 remain; independent probes do not establish simultaneous maxima or Android/KMP acceptance. Structured parameters retain their current Ktor projection.

Counts remain opt-in at DTO/Patch.Value/HTTP preflight-postflight/SSE payload consumers. Bare List/Map codecs do not enforce container counts. Shared optional null defaults and request required-null/Patch presence retain their contracts. Provider byte codec rejects out-of-range numeric values and incompatible JSON kinds. Fragmented SSE parse/count/null failure or cancellation closes still-open input; cold collection and subsequent client reuse remain valid. Native generation failure preserves owned output.

Existing accepted API/wire and opt-in defaults remain. Caller-native/raw/true/recursive JSON leaves, general reference/composition graphs and actual Android/KMP require separate contracts and evidence.
