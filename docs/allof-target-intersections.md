# Nested allOf DTO targets as allOf operands

An allOf operand may reference an original nested ordinary allOf DTO under a
direct ordinary object owner. For example, `Owner/properties/payload`, where
payload has allOf object members, retains the actual `OwnerDto.Payload`
constructor and contributes its original fields to Consumer. Direct internal
Pointers, finite internal chains and root bridges share this behavior.

The target uses the existing composed-DTO source snapshot and final unique
retained constructor proof. Its original nodes, named shape-reference edges,
alias heights and actual lexical catalog/Pointer remain authoritative; a copied
Consumer cannot authorize a missing owner, substituted source or ambiguous
occurrence. No component or classifier is invented. The target's named allOf
source references keep their original source-depth/work budgets. Nested source
cycles and unsupported source roles keep their existing diagnostics.

This role requires a direct ordinary lexical path. Composed/union/hierarchy
lexical owners, union products, root-default/count-bearing target roots and
hierarchy/common/inline ownership remain separate. Typed composed-reference
support alone does not authorize arbitrary shape borrowing. Existing object
allOf later overrides and approximation warnings remain; this does not add
exact intersection validation.

Nullable intent follows the nearest original target/chain/member view and
ordinary member intersection. Original own field/default/check metadata,
required/Patch suppression, nominal nested aliases/codecs and recursion retain
their contracts. Original AST nodes remain unchanged. Borrowing contributes
fields through the ordinary shape planner and obeys combined constructor slots.

The shared intersection capture budget remains16,384 work units/8MiB per
document, across ordinary and composed targets. Capture follows original
semantic nodes and named shape-reference edges. Repeated targets reuse capture;
distinct overlapping targets are charged independently, and copied analyzer
contexts share the same budget. Source48, checked16, JVMslots240 and the
existing input/default/value limits remain.239+1 slots is accepted and240+1
is rejected.

`bash scripts/test.sh feature allof-target-intersections` generates fresh
Data/Plain×validation projects, each with nullable/non-null baseline and
combined optimized/locked profiles plus a239+1 constructor. The
[non-null](../tests/fixtures/http/allof-target-intersections.json) and
[nullable](../tests/fixtures/http/nullable-allof-target-intersections.json)
fixtures exercise original nested constructors, recursion, nested DTO/enum
field defaults, four Json settings, required/Patch, HTTP and fragmented SSE
null/data/error/closure/reuse. Go source tests check AST/catalog/Pointer,
actual owner identity, overlapping capture and exact work/byte boundaries;
native tests compare core bytes, readonly/no-op, failure Pointers and old
output preservation. Bounded fuzz varies chains and nullable intent.
Broader graphs and platforms require separate evidence.

**Migration:** formerly rejected eligible nested allOf DTO operands now
generate with existing field/API/wire rules. Existing accepted named/internal
operands, manifest/name-lock formats and optimization contracts remain. General
composed/union/hierarchy lexical ownership stays separate.

Composed/union and named hierarchy-leaf lexical owners use the [composed target owner extension](composed-target-owners.md) and the same final original-owner proof.
