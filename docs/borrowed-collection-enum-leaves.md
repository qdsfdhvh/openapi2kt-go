# Borrowed collections with retained String enum leaves

Finite borrowed internal List and typed Map segments, including explicit component root exports, may refer to existing plain String enum vocabularies through local named/internal references and their accepted aliases. The original retained StringEnum declaration owns its canonical serializer, `entries`, `fromSerialName` and `Unrecognized` APIs. A borrowed container or root alias introduces no vocabulary class or nested classifier. This extends F04/F07/M03/M08; native, numeric, formatted or other nominal source roles remain separate.

Admission is provisional. Output requires one original actual vocabulary at the original lexical catalog, schema node/Pointer and FQName. Missing, same-name replacements, repeated declarations, copied source trees and discarded or ambiguous owners reject. Original vocabulary-array, member and ordered schema-member identities remain; replacing a member with an identical string is not original source identity. Original enum nullable provenance and actual member names/wire values are checked again. Named alias edges retain original node bytes, unique actual ValueAliases and final cached heights. Forward root-container traversal shares the existing catalog DFS for enum aliases, retaining original source work rather than treating a cached terminal as a new owner.

Nullable container and nullable enum item/value intent are independent. Nearest explicit true/false wins on the actual path; false does not reset preceding references or container work. Canonical enum serializers are non-null; reified nullable codecs or the canonical nullable adapter handle null. Known strings decode to canonical entries, future strings retain `Unrecognized(serialName)`, and wrong JSON kinds fail. Collections retain native array/object wire representations. Depth48, checked collection edges16, work16,384, vocabulary240 and JVM slots240 remain fixed; each List/Map field or parameter consumes one slot.

Validation opt-in enforces container counts at DTO, Patch.Value, HTTP pre/postflight and SSE event boundaries. Standalone collection assignment and reified collection serialization do not enforce container constraints; they still call canonical enum serializers. Opt-in [String enum list uniqueness](string-enum-unique.md#referenced-enum-leaves) additionally compares actual serialName payloads through these admitted references, preserving open unknown values. General nominal-item equality and enum membership rejection remain separate. Shared defaults, required nullable inputs and request-only Patch keep their existing contracts. Structured HTTP query projection follows the existing parameter encoder.
